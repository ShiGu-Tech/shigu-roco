> 文档状态：设计 ✅ v0.1 · 代码 ⬜ 已废弃 · 验证 ⬜ · 生产 ⬜

> ⚠️ **已废弃**：本文描述原 Python/FastAPI 常驻引擎（26901）与 Next.js 代理的旧通道。引擎已于 v0.2.0 重写为纯 TS 并入前端同仓（Web Worker + Route Handler），现行架构见《引擎 TS 化-设计-v0.1》。本文保留供追溯。

## 1. 定位与边界

定义 Python 引擎进程与 Next.js 前端之间的**进程形态、HTTP 契约、端口与启动方式**。本文只谈「怎么连」，不谈战斗规则（见模拟器稿）与搜索算法（见 MCTS 稿）。

## 2. 设计原则

1. **引擎常驻**：模拟器与 MCTS 需要毫秒级反复调用；若每次请求都起一个 Python 子进程，解释器与依赖导入开销会吞掉 1.5s 思考预算。故引擎是**常驻 HTTP 服务**。
2. **回环绑定**：引擎只监听 `127.0.0.1`，不对外网暴露，天然满足「离线、无外泄」。
3. **单一入口**：前端只通过 `/api/engine/*` 反代访问引擎，浏览器不直连引擎端口（规避 CORS 与端口暴露）。
4. **契约先行**：请求 / 响应结构用 Pydantic（引擎）与 TypeBox（前端）双侧声明，字段命名统一 `camelCase`，避免两端漂移。
5. **可降级**：引擎不可用时，前端 `/api/engine/*` 返回 502 + 结构化错误，UI 提示「引擎未启动，请运行 scripts/dev.ps1」。

## 3. 进程与端口

| 组件 | 地址 | 启动 |
| --- | --- | --- |
| Python 引擎（FastAPI / uvicorn） | `http://127.0.0.1:26901` | `scripts/engine-dev.ps1` 或 `scripts/dev.ps1` |
| Next.js 前端 | `http://127.0.0.1:26900` | `pnpm -F web dev` |
| 前端代理 | `/api/engine/[...path]` | 转发至 `ROCO_ENGINE_URL` |

环境变量（`.env.local` / 脚本注入）：

| 变量 | 默认 | 用途 |
| --- | --- | --- |
| `ROCO_ENGINE_URL` | `http://127.0.0.1:26901` | 前端代理目标 |
| `ROCO_ENGINE_PORT` | `26901` | 引擎监听端口 |
| `ROCO_WEB_PORT` | `26900` | 前端端口 |
| `ROCO_DATA_DIR` | `<repo>/data` | 引擎数据目录 |

> 端口选 26900/26901 以避开参考项目的 26841（`D:\ShiGuZone\main`）。

## 4. HTTP 契约

统一前缀 `/`（引擎根）。响应统一 JSON；错误统一 `{ "error": string, "detail"?: unknown }`，HTTP 状态码语义化（400 参数、404 未找到、422 校验失败、500 内部）。

### 4.5 `POST /opponent/observe`

回报一局中观察到的对手动作，更新贝叶斯模型（会话内，前端负责持久化到 localStorage 后再回传）。

```json
{ "enemyActiveId": "shuipao", "actionClass": "A" }
```

响应 `{ "ok": true, "posterior": { "A": 0.55, "D": 0.15, "S": 0.30 } }`。

> 设计取舍：对手模型的**持久化放前端**（localStorage）。引擎保持无状态，重启不丢数据由前端把历史计数随 `/recommend` 一起传入。

## 5. BattleState 契约（通道层）

完整字段定义以数据层设计稿为准，此处给出通道视角的骨架：

```ts
type ActionKind = "skill" | "defend" | "switch" | "wish" | "leader";

interface ActiveSpriteState {
  spriteId: string;
  hp: number; maxHp: number;
  energy: number;
  buffs: Record<string, number>;
  debuffs: Record<string, number>;
  marks: { name: string; stack: number }[];
}

interface SideState {
  magic: number;
  active: ActiveSpriteState;
  bench: ActiveSpriteState[];       // 我方可见背包
  seenEnemy?: string[];             // 敌方已登场精灵 id（我方视角）
}

interface BattleState {
  turn: number;
  weather: { id: string; turnsLeft: number } | null;
  player: SideState & { wishChargesLeft: number; wishCooldown: number; leaderUsed: boolean };
  enemy:  SideState & { wishChargesLeft?: number; leaderUsed?: boolean }; // 对手侧为推测/估计
  personality?: Record<string, string>;  // 性格（运行时输入）
  ivs?: Record<string, Record<string, number>>; // 个体值（运行时输入）
}
```

## 6. Next.js 代理实现要点

- 路由：`apps/web/src/app/api/engine/[...path]/route.ts`，`export const runtime = "nodejs"`、`export const dynamic = "force-dynamic"`。
- 行为：把 `request` 的 method、body、query 原样转发到 `${ROCO_ENGINE_URL}/${path.join("/")}`；超时（如 30s）后返回 504。
- 引擎连接失败（ECONNREFUSED）→ 返回 `502 { error: "引擎未启动", hint: "运行 scripts/dev.ps1" }`。
- 不在代理层做任何游戏逻辑或缓存。

## 7. 启动方式

- `scripts/setup.ps1`：创建 `engine/.venv`、`pip install -e engine[dev]`、`pnpm install`。
- `scripts/engine-dev.ps1`：激活 venv，`uvicorn roco_engine.api.app:app --host 127.0.0.1 --port 26901 --reload`。
- `scripts/dev.ps1`：并行拉起引擎与 `pnpm -F web dev`（两个 `Start-Process`，输出各自日志到 `logs/`）。
- 只跑前端：`pnpm dev`（引擎需另行启动，否则 `/recommend` 返回 502）。

## 8. 关键决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 进程形态 | 常驻 HTTP 服务 | 规避 Python 启动开销；支持热重载数据 |
| 通信 | 回环 HTTP JSON | 简单、可调试（curl 可复现）、跨语言 |
| 代理位置 | Next 服务端反代 | 浏览器不直连引擎；统一错误处理 |
| 状态归属 | 引擎无状态；存档在浏览器 | 引擎简单可重启；存档随用户 |
| 字段命名 | 全线 camelCase | 与 TS 前端一致，减少映射代码 |

## 9. 非目标

- 不做鉴权、不做多用户、不做 HTTPS、不做公网部署。
- 不做 WebSocket / 流式：单次推演 1.5s 内返回，一元请求足够（若阶段 5 需要进度条再议）。
- 不做引擎侧持久化数据库。
