## 1. 定位与边界

- **定位**：对战台每一次开战 = 创建一个**观战房间**；房间由主机（对战台标签）写入，生成观战 URL。任意设备打开 URL 可：进行中**实时**跟随（引擎内部流程按发生顺序逐个点亮）；结束后切**回放**（可暂停 / 重播 / 拖动）。
- **解决的痛点**：引擎内部流程目前只能在主机本页（小号图）或事后到 `/engine` 看；无法分屏 / 换设备大屏围观。
- **边界**：
  - **只读观战**：观众不能改局面、不能操作、不能触发结算。
  - **主机唯一写者**：只有对战台标签推快照。
  - 服务端只存**展示层数据**（名号 / 轨迹步 / 已渲染事件 / 终局），**不含引擎可操作状态**，**不跑引擎**。
  - 不改引擎语义、不改 `mechanisms.json`。
- **与非目标区分**：本地存档回放（`/replays`，`replays/storage.ts`）是「自己存、自己放」；本稿是「服务端房间、别人看」，两者不合并。

## 2. 设计原则

1. **只读、单向**：观众永远只读；数据流 主机 → 服务端 → 观众，单向。
2. **服务端轻量、无账号**：房间 id 不可猜（URL 即密钥）；无登录、无权限、无数据库；内存 `Map` 存储。
3. **主机是唯一写者**：`POST` 建房、`PUT` 推全量快照；观众只 `GET` / 订阅。
4. **传输可替换（`RoomTransport`）**：v1 用 SSE；不可用时轮询兜底；将来换 WebSocket / 第三方只换实现。
5. **复用现有 atlas**：观战页复用 `lifecycle-graph`（`full` 布局）+ `flattenFirings`（[引擎全景图] P4 已具备），不重写。
6. **失败降级**：SSE 断开自动重连 / 回退轮询；房间不存在 / 过期给出明确空态。

## 3. 领域模型

```ts
/** 一方的展示信息（大屏标题用）。 */
interface RoomSide {
  label: string;                                   // 阵容名 / "我方" / "敌方"
  sprites: { id: string; name: string; element?: string }[];
}

/** 一次「用户操作 → 引擎响应」的观战条目（每回合一条；强制换人另计）。 */
interface WatchEntry {
  turn: number;
  label: string;                                   // "回合 2" / "我方阵亡换人"
  actions: { side: "player" | "enemy"; label: string }[];
  step: AtlasStep;                                 // 轨迹（复用 atlas/types）
  log: { side: "player" | "enemy" | "system"; text: string }[];  // 已渲染事件文本
}

/** 观战房间（服务端内存；`/api/watch/rooms/[id]` 返回体）。 */
interface WatchRoom {
  id: string;                                      // r-<不可猜 id>
  createdAt: number;
  updatedAt: number;
  status: "live" | "ended";
  seed: number;
  player: RoomSide;
  enemy: RoomSide;
  turn: number;
  terminal: { winner: "player" | "enemy"; reason: string } | null;
  entries: WatchEntry[];                           // 累积（限额 ≤ 120 条）
  dataVersion: string;
  engineVersion: string;
}
```

- `step` 直接用 `modules/atlas/types#AtlasStep`；`flattenFirings(entries.map(e => e.step))` 得回放序列。
- `log` 在主机侧用现有 `modules/board/log.ts#describeEvent` 渲染成文本，**观战页不引引擎**。
- 房间不含 `BattleState`（不可操作）。

## 4. 接口 / 契约（Next Route Handler，`runtime = "nodejs"`）

```text
POST   /api/watch/rooms                 建房（主机）  body: { player, enemy, seed, dataVersion, engineVersion } → { id }
PUT    /api/watch/rooms/[id]            推全量快照（主机）  body: WatchRoom → { ok: true }
GET    /api/watch/rooms/[id]            读取当前快照（首屏 / 轮询兜底） → WatchRoom | 404
GET    /api/watch/rooms/[id]/stream     SSE：连线即推最新快照，此后每次 PUT 广播；15s 心跳
DELETE /api/watch/rooms/[id]            结束并删除（主机，可选）
```

- **存储**：模块级 `Map<string, RoomRecord>`（`RoomRecord = { room: WatchRoom; listeners: Set<() => void> }`），惰性初始化；TTL `12h`、上限 `200` 房，访问时惰性清理最旧。**单进程内存**。
- **SSE**：构造时即带 headers（`text/event-stream` / `no-cache` / `no-transform`），`req.signal` 的 `abort` 里退订 + 清心跳；`enqueue` 用 `TextEncoder`。
- **幂等**：`PUT` 全量覆盖；`updatedAt` 递增用于观众侧判新旧。

## 5. 路由与页面

```text
/watch/[roomId]   观战大屏（新增）
   ├─ 顶：房间 id · 状态徽章（实时 / 已结束）· 双方阵容 · 第 N 回合 · 数据/引擎版本
   ├─ 主：引擎全景图（lifecycle-graph full 布局）按 flattenFirings 顺序逐个点亮
   │      · live：新条目自动续播（有「跟随最新」开关）
   │      · ended：暂停 / 重播 / 进度拖动
   └─ 侧/底：事件记录（按 entry 列出 actions + log 文本）
/（对战台）        建房 + 每回合推快照 + 终局推 ended；顶栏显示「观战链接」+ 复制 / 新窗口打开；移除页内嵌 BoardAtlas 面板
/engine            不变
```

- 观战页取机制列表（图计数）走 `GET /api/engine/workbench/mechanisms`（与 `/engine` 同）。
- 复制链接用 `navigator.clipboard`（失败降级手选文本）。

## 6. 关键决策

1. **SSE 而非 WebSocket**：观战是单向 server→client；Next standalone 支持流式 Route Handler，无需自定义 server。
2. **PUT 全量快照而非增量**：轨迹 / 日志量小（≤120 条），全量实现简单、天然有序、断线重连无补偿。
3. **内存房间，不引数据库**：满足「无账号、无持久库」；重启丢房间可接受。持久回放列为非目标 / 后续。
4. **URL 即密钥**：房 id 随机不可猜；不引鉴权；只读。
5. **只同步展示数据**：房间不含 `BattleState`，避免观众侧可操作 / 泄露信息。
6. **复用 atlas，不碰引擎**：观战播放完全走 `modules/atlas`。
7. **版本**：新功能 **bump minor**（业务 `0.48.0`）；`ENGINE_VERSION` 不动。

## 7. 非目标

- 观众操作 / 远程对战 / 多人同房聊天 / 弹幕。
- 账号、权限、房间管理后台、房间列表。
- 持久化与多实例部署（v1 单进程内存，进程重启丢房间）。
- 观战页做引擎重算或展示可操作状态。
- 引擎语义 / 数据格式改动。
