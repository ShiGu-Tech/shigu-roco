## 1. 一句话

**引擎是通用「状态修改器执行器」；一切具体内容（技能 / 特性 / 印记 / 状态 / 天气）都是数据。** 引擎甚至要能执行「凭空创造」的技能——它不认识任何一条具体数据。

## 2. 三层划分

| 层 | 内容 | 允许知道 | 禁止知道 |
| --- | --- | --- | --- |
| **引擎核心** `modules/engine/**`（除 `catalog/`、测试） | 状态域 + 通用动词 + 触发器 / 条件 / 效果命令 / 动态数值框架 | 抽象的域与操作（印记、状态、buff、能量、天气、冷却、计数…） | 任何具体技能 id / 印记 id / 站点字段 / 某个机制的名字 |
| **数据层** `data/*.json`、`catalog/*`、`server.ts` 装配 | 具体内容：`mechanisms.json`、marks/statuses/weather/skills 定义、`rules` 参数；站点快照 → 归一化 | 站点格式、具体 id、具体数值 | 不写引擎逻辑 |
| **表现层** `modules/board/**`、`components/**` | UI、日志、推荐 | 展示用数据 | 不参与结算 |

## 3. 判据：什么时候才算「新引擎能力」

1. 能用「**触发器 + 条件 + 通用效果**」描述 → **归数据**，改 `mechanisms.json`，引擎版本不动。
2. 只有出现**真正新的动词或数值形态**（无法用现有原语组合）时，才给引擎加**通用**原语，并 bump `ENGINE_VERSION` minor。
3. 新原语必须**与具体内容无关**：命名、参数、语义都不能出现某个技能 / 印记的名字。

**反例（禁止）**：
- 在引擎里 `if (skill.id === "sk-xxx") ...`；
- 在引擎里解析站点字段（如 `<desc_id=1016>`）或图鉴结构；
- 在引擎里硬编码某个印记的引爆 / 某个机制的专属公式；
- 用具体 id 作为原语参数默认值。

**正例**：为「按合计层数做非线性取值」加通用的 `DynamicValue.terms`（多项式）；为「消耗印记并把合计层数交给后续效果」给 `consumeMark` 加 `effectsOnConsume` + `event.consumed`。这两个能力与星陨无关，任何内容都能用。

## 4. 历史特化的处置（本节记录迁移）

| 特化 | 原位置 | 处置 |
| --- | --- | --- |
| 「应对」从站点 `<desc_id=1015/1016/1017>` 标签推导 | 引擎 `simulator/battle.ts` | 推导移到 `catalog/normalize.ts`（数据摄取层）产出通用字段 `skill.reaction`；引擎只读该字段做「reaction × 敌方行动类型」比对 |
| 星陨引爆（`starfall-mark` + `rules.starfall` + N²+24N−24） | 引擎 `simulator/battle.ts#applyStarfall` | 删除；改为 `mechanisms.json` 中两条 `ownerType:"mark"` 机制（用 `onHit` + `consumeMark.effectsOnConsume` + `DynamicValue.terms` + 事件 `element`） |

## 5. 数据摄取层（`catalog/`）职责

`catalog/` 是**唯一**允许接触站点格式的地方：把外部快照规范化成引擎可读的通用字段（`reaction`、`elements`、印记/状态 key、规则参数等）。它属于数据层，不是引擎核心。

## 6. 非目标

- 不在引擎里做技能自然语言解析（仍由 `scripts/derive-effects.mjs` + 人工转写为 `mechanisms.json`）。
- 不引入脚本沙箱 / 表达式引擎：动态取值只支持点路径 + 系数 / 偏移 / 多项式。
- 不追求「引擎预置任何示例内容」。

## 7. 校验

- 评审引擎 PR 时先问：**这条改动是否与具体内容无关？** 否则拒绝，退回数据层。
- `pnpm check` 全绿；新增通用原语需补单测（覆盖通用语义，不用具体技能名）。
