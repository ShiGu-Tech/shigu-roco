# 静态数据与前台计算 · 设计 v0.1

> 文档状态：设计 ✅ v0.1 · 代码 ✅ · 验证 ✅ · 生产 ✅

## 1. 定位与边界

把引擎运行时的**数据来源**与**计算位置**收敛到浏览器：

- **数据**：激活图鉴（精灵 / 技能 / 印记 / 天气 / 属性）+ 引擎参数，导出为一份**精简静态 JSON**，落到 `apps/web/public/data/bundle.json` 并提交入仓，浏览器直接 `fetch`，不再依赖 Node 进程读盘。
- **计算**：物化后的 `recommend`、`simulate/turn`、`simulate/forced-switch`、`simulate/leader`、`catalog` 全部在 **Web Worker** 内执行（不阻塞主线程）；`/api/engine/*` 仅作兜底与图鉴管理（同步 / 注册 / 激活 / reload）。

保留 Next 服务（页面宿主 + 管理接口 + 兜底），不改为纯静态站点。

不在本文范围：MCTS / 模拟器算法本身（见《MCTS决策》《战斗模拟器》）；图鉴同步协议（见《图鉴数据同步》）。

## 2. 设计原则

1. **单一数据来源**：浏览器侧只认静态 `bundle.json`；它由服务端对 `getBundle()` 的结果序列化而来，与 Node 侧完全同构。
2. **精简传输**：`bundlePayload` 剥离只用于追溯的 `sourceData`（原始页面快照），把运行时载荷从 130 MB 级降到 ~1 MB 级；同时补齐 `mechanisms` 字段（此前缺失导致 Worker 内技能无伤害）。
3. **同构复用**：Worker 仍调用与 Node 完全相同的 `api/handlers.ts`，不复制任何逻辑。
4. **可回退**：静态文件缺失或 Worker 不可用时，逐级回退到 `/api/engine/*`。
5. **数据与代码解耦不变**：导出脚本只搬运数据，模拟器 / MCTS 代码零改动。

## 3. 领域模型与数据流

```text
data/*.json（引擎参数）  data/registry/catalogs/<active>/catalog.json（图鉴，含 sourceData）
        └──────────────┬──────────────┘
                       ▼  Node：server.getBundle()  合并参数 + 图鉴 + 技能 dealDamage 机制
             bundlePayload()  剥离 sourceData / 补 mechanisms
                       │
        ┌──────────────┴───────────────┐
        ▼                              ▼
 GET /api/engine/bundle         scripts/export-static-data.mjs
 （Node 兜底 / 管理）              └─► apps/web/public/data/bundle.json（入仓）
                                               │
                                               ▼
                                       Worker init → buildBundle(raw)
                                       recommend / simulate/* / catalog 全在 Worker
```

`bundle.json` 的字段与 `RawDataFiles` 对齐：`sprites/skills/marks/weather/elements/rules/stats/assets/mechanisms/dataVersion`。

## 4. 接口 / 契约

- `bundlePayload(bundle)`（`engine/api/handlers.ts`）
  - 新增 `mechanisms: string[]`（合并后的机制数组）。
  - `sprites/skills/marks/weather` 条目剥离 `sourceData` 后输出。
  - 其余字段不变；`GET /api/engine/bundle` 与静态文件同一形状。
- Worker 初始化（`engine/worker/client.ts`）
  - 优先 `fetch("/data/bundle.json")`；失败回退 `GET /api/engine/bundle`。
- Worker 路由（`engine/worker/engine.worker.ts`）已覆盖 `simulate/forced-switch`、`simulate/leader`、`catalog`。
- 前端客户端（`modules/battle/client.ts`）
  - `recommend` / `simulateTurn` / `forcedSwitch` / `requestLeader` / `getCatalog`：Worker 优先，异常回退 HTTP。
- 导出脚本 `scripts/export-static-data.mjs`
  - `exportStaticBundle(origin)`：`GET {origin}/api/engine/bundle` → 写 `apps/web/public/data/bundle.json`（压缩为单行 JSON）。
  - CLI：`pnpm static:export`；`scripts/sync-roco-world.mjs --register` 注册成功后自动调用。

## 5. 关键决策

- **D1 保留 Next 服务**：管理型操作（同步、注册、激活、reload）必须写文件，天然属于 Node；页面与兜底也由 Next 提供。计算前台化不等于取消服务端。
- **D2 提交 `public/data/bundle.json`**：让仓库自包含、可离线启动；代价是数据更新后需重跑导出（已并入同步脚本与 npm 脚本）。
- **D3 剥离 `sourceData`**：原始页面快照仅用于图鉴追溯，引擎运行时不需要；`catalog()` 的技能来源已有归一化 `skillSources` 字段，不依赖 `sourceData` 回退。
- **D4 `catalog` 也走 Worker**：与引擎共享同一份数据，避免「UI 数据（服务端）与推演数据（静态）」版本漂移。
- **D5 逐级回退**：静态文件 → 服务端 API → 报错提示，保持鲁棒。

## 6. 非目标

- 不做纯静态导出（`output: export`）与离线单文件分发。
- 不在浏览器重做图鉴同步 / 注册（写文件能力仍留在 Node）。
- 不改动 MCTS / 模拟器算法与数据 schema。
