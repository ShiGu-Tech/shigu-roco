## 1. 定位与边界

**一句话**：把工具从「桌面工作台」改造成「手机上的对局助手」——首页是功能列表，第一个功能是 PVP：手机上录入双方阵容（可从共享仓库挑、可拍照、可口述）→ 6v6 对战 → 对局中反推对手养成。

- **本轮范围**：手机端外壳 + 首页功能列表 + PVP 全流程（录入 / 对战 / 反推）+ 精灵仓库（共享 + 手机化）。其余现有页面**隐藏但不删除**（保留直达 URL）。
- **非目标**：不做自动操作游戏、不读内存/抓包、不做账号体系、不做多实例、不做 NN 加速。
- **与现有定位的关系**：仍然「非外挂、人工录入、引擎只做推演」。新增的只有两条输入通道（拍照/口述）与一份共享仓库（服务端）。

### 1.1 红线修订申请（需确认）

`AGENTS.md` 第 7 行现文：「**非外挂**：不读取游戏画面、不读内存、不抓包、不自动操作游戏、不联网（运行时）」。

本轮要引入 **用户主动拍照 / 录音** 与 **服务端 AI 通道**，与「不读取游戏画面、不联网」直接冲突，申请修订为：

> **非外挂**：不读内存、不抓包、不自动操作游戏、不注入游戏进程。**用户主动提交**的截图 / 录音仅用于「名单识别」（把图/话变成精灵名单），**必须经用户逐项确认后才生效**，不解析对局画面、不自动填状态、不自动决策。识别走**自有服务器 + 自有 GPU 服务**（`docs/operations/线上部署与发布-v0.1.md` 的 cspy-site 与 frp 后的 GPU 机），不接游戏、不接第三方识别服务；不调用时全站仍可纯手工使用（降级可用）。

## 2. 设计原则

1. **手机优先（authored mobile-first）**：新页面先写 ≤520px 基线，再用 `min-[520px]:` / `min-[860px]:` 放大（沿用工作区断点，不引 Tailwind 默认 `sm:`/`md:`）。
2. **AI 只做「录入辅助」，不做决策**：识别结果是**候选**，用户确认后才成为阵容；识别失败一律退化为手工录入（不阻断流程）。
3. **服务端持有凭据，浏览器不碰 token**：语音/视觉服务的令牌只在服务器 `.env`，浏览器只调本站 API。
4. **共享仓库是「一份事实」，本地是「工作副本」**：仓库统一在服务端（多人可见），浏览器不复制一份真相；离线/未配置时回退本地（`roco.pets`）。
5. **重计算不占主线程**：反推从主线程搬进 Worker（手机上 5.6 万组合会明显卡顿）。
6. **照抄既有模式，不发明新基础设施**：服务端落盘沿用 `modules/watch/persistence.ts` 的「单文件 + tmp→rename 原子写 + TTL 清理」；Worker 通道沿用现有 RPC 分发。

## 5. 模块划分与接口契约

### 5.1 移动端外壳与功能列表

- 首页 `/` 改为**功能列表**（卡片），数据来自一份声明式清单（新增 `modules/shell/features.ts`）：`{ id, title, desc, href, enabled, icon }`。PVP 为第一项。
- 导航：`app-nav.tsx` 的 `ITEMS` 改为读该清单，只渲染 `enabled` 项；≤520px 只显示当前页标题 + 返回，不再横滚 7 项。
- 隐藏方式：**路由保留、导航不渲染**（`enabled: false`）；不删代码、不加中间件。
- 触控尺寸：新页面按钮/列表项最小 44×44；不沿用 `h-8`/`w-[26px]` 这类桌面尺寸。
- **验收**：320 / 390 / 430 / 768 四档无横向溢出（沿用 `scripts/cdp-smoke.ps1` 的横向溢出断言）。

### 5.2 AI 录入通道（经 tmxk 能力；**roco 只做业务层**）

**通道已定：走 tmxk 能力平台**（能力侧设计见 tmxk-site《视觉与语音能力-v0.1》）。roco **不直连 GPU 服务、不持 GPU 令牌、不感知网段与上游地址**，只在服务端换票调用：

```text
浏览器 ──图/音──> roco 服务端 ──Bearer app 票据──> tmxk.site /api/vision/ocr、/api/voice/transcribe
                     │
                     └ 识别出的文本 ──> §5.2.1 本地名单匹配器 ──> 候选（前端人工确认）
```

| roco 的业务接口 | 入参 | 出参 | 依赖能力 |
| --- | --- | --- | --- |
| `POST /api/ingest/photo` | `{ image: base64(压缩后 jpeg) }` | `{ candidates: [{text, score, matched: {spriteId,name,confidence}[]}] }` | `vision:ocr` |
| `POST /api/ingest/voice` | `multipart: audio(webm/opus)` | `{ transcript, candidates: [...] }` | `voice:transcribe` → §5.2.1 |
| `POST /api/ingest/text` | `{ text }` | 同上（`candidates`） | 无（纯本地匹配器） |

**业务层留在 roco 的三件事**（能力平台不承担）：① **名单匹配器**（§5.2.1）；② **人工确认流**（候选必须经用户确认才成为阵容）；③ **降级**（能力不可用 → 手工录入）。

**接入配置**（服务器 `.env`，不入仓）：`TMXK_SITE_BASE_URL`、`TMXK_APP_KEY`、`TMXK_APP_SECRET`；服务端换票后缓存票据（`expires_in - 30s` 提前刷新）。

**5.2.1 名单匹配器（纯本地，核心）**：把 OCR 文本行 / ASR 文本切成候选片段，对 621 个精灵名做匹配——`精确 → 去空格/别名 → 拼音首字母 → 编辑距离(≤2)`，输出**带置信度**的候选。放在 `modules/ingest/match.ts`（纯函数，可单测）。技能名同理（579 个）。
**5.2.2 LLM 兜底（可选，P2）**：极端口语（「对面带了条冰狗」）才需要语义推断；默认关闭，开启需在服务器 `.env` 配 key（`INGEST_LLM_*`）。**不把 key 放进仓库。**

**降级**：上游不可达 / 未配置 → 返回 `{ degraded: true, reason }`，前端提示「识别服务不可用，请手动录入」，流程不中断。

### 5.3 共享精灵仓库（服务端）

- 存储：`data/library/pets.json`（宿主挂载卷内，随 `data/` 走，重建镜像不丢），单文件信封 `{ $schemaVersion, version, updatedAt, instances: PetInstance[] }`，**原子写**（tmp→rename），带进程内写锁；沿用观战房间的目录解析（`ROCO_DATA_DIR`/`LIBRARY_DATA_DIR`）。
- API：`GET /api/library/pets`（列表）｜`POST`（新增）｜`PUT /api/library/pets/:id`｜`DELETE /api/library/pets/:id`｜`POST /api/library/import`（批量，照 `pets/store.ts:108` 的按 id 去重语义）。
- **写入鉴权**：`LIBRARY_WRITE_TOKEN`（服务器 `.env`，不入仓）；浏览器首次写入时输入一次、存 `localStorage`。读开放。
- 与本地仓库的关系：**共享库为主**，本地 `roco.pets` 保留为「离线/未配置时的私有草稿」；两者在 UI 上分区展示，一键「上传到共享库」。P0 只做共享库。
- `PetInstance` 模型**原样复用**（`pets/instance.ts:18`），不新增字段；解析仍走 `resolveInstance`（换图鉴自动跟随）。

### 5.4 反推先验（仓库 → 收窄搜索空间）

- 先验来源：共享库 + 本地库按 `spriteId` 聚合 → `nature` 直方图、`talent` 直方图（样本 < 3 只时不启用先验，避免过拟合）。
- 接入点（**低风险**，因为底层已预留参数）：调用 `inferOpponent` 时传 `natures`（按先验排序的白名单，默认 top 3）+ 收窄天分档位；`infer.ts:239` 的「均匀加权」改为**先验加权**（概率输出更接近真实分布）。
- 预期：42 性格 × 11³ ≈ 55,900 → 典型 3 性格 × 2 档/维 ≈ 24 组合（**约 2000×**），且命中率提升（对方是"常见配置"的概率本就更高）。
- 迁移：`inferOpponent` 从主线程搬进 Worker（新增 RPC `infer/build`），手机上不卡 UI；先验缺失时退化为现有全枚举行为。

### 5.5 6v6 PVP 手机流程

- 抽常量：`TEAM_SIZE = 6`、`MIN_TEAM_SIZE`（引擎不限制，允许 1–6，UI 默认 6）→ 三处字面量改为读常量。
- 录入三页（§4）；我方支持「从仓库勾选」（默认路径）与「预置阵容」（复用 `roco.lineups`）；对方沿用「真实对战模式」口径（只登记精灵）。
- 对战页手机布局：单列 + 分区折叠（当前场上 / 动作区 / 日志·走势）；沿用现有子组件（`active-board` / `side-panel` / `timeline` / `trend-chart`），只改排布与尺寸；**不重写对战逻辑**。
- 性能降级：手机端 MCTS 默认 `maxIterations` 下调（如 400）并按 `navigator.hardwareConcurrency` 自适应，UI 明示「低精度模式」。

## 6. 关键决策与取舍

| 决策 | 取舍 |
| --- | --- |
| 拍照走 **OCR 文本 → 本地匹配**，不做 621 张图的 `icon-match` | `icon-match` 要求把整个画廊 base64 随请求上传（621 张 ≈ 40MB+/次）且视觉服务是 CPU 版，不现实；OCR 一次只传一张小图，且名字是图鉴里就有的确定性信息。**图标识别留作 P2**（配"先用 OCR 收窄候选、再在小画廊里 icon-match"） |
| 口述走 **`voice:transcribe` 能力 + 本地匹配器**，LLM 兜底默认关 | ASR 输出基本就是精灵名，本地匹配确定性、免费、可单测；语义兜底是长尾需求 |
| 共享库用**文件落盘**而非数据库 | 与项目「无数据库」一致；数据量级（几十~几百只）单文件足够；多实例非目标 |
| 写入用**一次性 token** 而非账号 | 无账号体系是既定红线；token 足够挡住"路人乱改"，代价是换设备要重输 |
| 反推**先收窄再计算**，不改成贝叶斯 | 保持引擎"固定规则"的边界，改动集中在调用侧与 `inferBuild` 的入参 |
| 现有页面**隐藏不删** | 符合"后面有选择性开放"；`enabled` 开关一处控制 |

## 7. 前置依赖与风险

1. **AI 服务的可达性（已由 §7.1 的选定方案消解）**：`shigu-vision`(8100) / `shigu-voice`(18191) 在 tmxk（`192.168.10.95`）上容器 `Up 7 days`、本机 healthz 200（实测 2026-10-16）。但 cspy-site 的 iptables 对 18188/18189/18190 **只放行 `127.0.0.1/32` 与 `172.16.0.0/12`，其余 DROP**；roco 容器在 `192.168.0.0/20`，直连一律超时。**所以 roco 不直连**——全部经 tmxk 能力平台（平台侧容器在 `172.x` 网段内，天然被放行）。
2. **不把 GPU 端口/网段写进 roco**：`172.30.0.1` 不是服务地址，而是 cspy-site 上 `shigu-zone_default` 网络的**网桥网关**（宿主机自身）；18188–18191 是 frps 监听口，经反向隧道到 tmxk 的 `127.0.0.1:{8188,8000,8100,18191}`。这些属**平台侧**事实，roco 的代码、配置、文档都不出现。
3. **凭据不入仓**：roco 侧只需 `TMXK_APP_KEY` / `TMXK_APP_SECRET`（换平台票据）与 `LIBRARY_WRITE_TOKEN`，只写服务器 `/opt/shigu-infra/shigu-roco/.env`；**GPU 服务令牌属平台侧**，roco 不持有。`compose.yaml` 用 `${VAR:-}` 透传，未配置即降级。
4. **隐私**：截图/录音经 roco 服务端转发到 tmxk 能力平台（上游为自有 GPU 机），**平台与 roco 均不落盘**；UI 需明示「识别用，不保存」。
5. **手机性能**：MCTS（默认 1500ms 时间预算）与反推在手机上偏重，需 Worker 化 + 降级档位。
6. **公开站点**：`roco.shigu.zone` 已是公网可访问，共享库一旦开放写入面，等同"任何拿到 token 的人都能改"——若你希望更严，可改为"仅服务器 SSH 内写入 + 前台只读"。
