# 引擎版本与维护 · 设计 v0.1

> 文档状态：设计 ✅ v0.1 · 代码 ✅ · 验证 ✅（health/bundle 暴露 + UI 展示） · 生产 ✅

## 1. 定位与边界

纯 TS 引擎（`apps/web/src/modules/engine/`）作为**独立版本化的子系统**维护：它对外提供「复刻官方回合结算 + MCTS 推演」的能力，**版本号与业务系统（`package.json`）各自独立**，互不牵连。

引擎版本描述的是**能力面**（触发器、条件、效果命令、结算语义、规则通道），**不是数据**。数据（技能 / 印记 / 状态 / 天气 / 特性 / 规则参数 / 图鉴）有各自的版本：图鉴 `registrationId` + `dataVersion`、`data/*.json` 各自的 `version`。

## 2. 版本策略（`apps/web/src/modules/engine/version.ts` 的 `ENGINE_VERSION`）

| 变更 | 版本动作 | 例 |
| --- | --- | --- |
| 新增机制能力：新触发器 / 新效果命令 / 新规则覆盖通道 / 新结算阶段 | **bump minor** | 加 `passive` 触发器 + `setRuleModifier` |
| 修正既有结算语义或能力行为（不新增能力） | **bump patch** | 冷却净 ±N、印记消费口径修正 |
| 接口 / 契约破坏性变更（握手字段、`Action`/`BattleState`/`Bundle` 形状） | **bump major** | 改 `simulate/turn` 请求结构 |
| **新增数据**：技能 / 印记 / 状态 / 天气 / 特性 / 规则参数，或它们的任意组合——只要能用现有触发器 + 条件 + 效果命令表达 | **不动版本** | 新增一个「造成伤害 + 叠印记 + 应对加成」的技能 |

判据一句话：**若能只改 `data/*.json` / 图鉴数据表达，就不动引擎版本；只有需要新能力时才 bump。**

## 2.1 版本历史

- `0.1.0` 基线：触发器 + 条件 + 效果命令 DSL、事务结算、冷却净 ±N、`passive` + `setRuleModifier` 规则覆盖通道。
- `0.2.0` 印记域原语：`setMark` / `scaleMark` / `transferMark` / `transformMark` + `layersFrom` 动态层数。
- `0.3.0` 记忆域：`addCounter` / `setCounter` / `clearCounter`、`lastTurn`（上回合记忆）、`modifySkill`（技能永久修正）、`setHits.hitsFrom`。
- `0.4.0` 强化/状态/能耗/行动域：`clearStat` / `setStatus` / `scaleStatus`、`modifySkillCost`、`forceSwitch` / `escape` / `allowSwitch`；`removeMark` 全部、`applyMark` 叠加。

## 3. 能力面（当前 `0.8.0`）

- 触发器：`battleStart` / `turnStart` / `actionDeclared` / `beforeAction` / `actionResolved` / `beforeDamage` / `afterDamage` / `afterEffect` / `beforeSwitch` / `afterSwitch` / `beforeDeath` / `afterDeath` / `turnEnd` / `battleEnd` / `skillUsed` / `passive` / `onHit` / `statusApplied` / `markApplied` / `weatherChanged` / `skillCooldownReduced`。
- 条件：`allOf` / `anyOf` / `not` + `path/op/value/valueFrom`（对象 / 事件 / 数值 / 状态 / 关系）。
- 效果命令：伤害 / 治疗 / 属性 / 印记 / 状态 / 天气 / 冷却 / 魔力 / 换人锁 / 技能池 / 行动队列 / **规则覆盖（`setRuleModifier`）**。
- 结算：事务应用、`applyStatus`/`applyMark` 级联（深度上限）、冷却净 ±N、伤害修饰通道、规则覆盖通道（`passive` 按需求值）。

## 4. 暴露与消费

- `GET /api/engine/health` → `{ engineVersion, dataVersion, counts, warnings }`。
- `GET /api/engine/bundle`（导出 `public/data/bundle.json`）→ 顶层 `engineVersion` + `dataVersion`。
- 前端 `EngineStatus`：分别显示「引擎 vX · 数据 Y」。

## 5. 非目标

- 本稿**不**把引擎拆成独立 npm workspace 包；仍是 `apps/web/src/modules/engine/` 内的自洽模块（纯逻辑不依赖 `fs` / DOM，Node 侧与 Worker 共用）。若后续需要跨仓复用，再评估抽包（届时 `ENGINE_VERSION` 与能力面清单可直接迁移）。
- 引擎版本**不随业务发布自动变**；业务系统 `package.json` 版本按前端功能独立 bump。
