# 引擎执行图 · 设计 v0.1

> 文档状态：设计稿（待评审）｜创建 2026-10-01
>

## 1. 定位与边界

- **定位**：把引擎做成一台**可视图灵机**——「底层执行了什么」以**逐节点 trace** 完全可见；「执行什么」全部由一份**可编辑、可版本化**的**程序（图）**定义。
- **核心心智**：不再是「引擎层 vs 数据层」，而是 **指令 vs 程序**：
  - **原语节点 = 指令集**（可插拔、代码、自带 schema）：每个节点只干一件事（取值 / 运算 / 比较 / 分支 / 写入 / 触发 / 调度）。
  - **程序 = 你搭的东西**（统一配置）：触发、条件、效果、回合流程、伤害公式、系别克制……**全是这一个图**。
  - **运行时 = 解释器**：走程序，逐步执行并录 trace。
- **边界**：
  - 唯一必须是代码的：**节点类型怎么执行**（指令语义）。除此之外一切可配置。
  - 不提供：数据里的任意脚本 / `eval`（节点执行器是注册的封闭集合）。
  - 不改：外部图鉴同步、DSH / 站点数据、决策层搜索语义（可后续）。

## 2. 设计原则

1. **指令封闭、程序开放**：节点类型是强类型、可插拔的封闭集合；「用哪些、怎么连、什么参数」100% 是程序。
2. **细粒度**：取值 / 运算 / 比较 / 逻辑 / 赋值 / 写入 / 分支都拆成独立节点（图灵机式的可组合性）。
3. **数据流 + 控制流分离**：控制边决定「按什么顺序 / 分支」，数据边把「值」喂给端口。节点从数据边**拉取**输入，执行后**写**状态并产出输出。
4. **纯函数 + 显式副作用**：取值 / 运算 / 比较是纯函数；只有「写入节点」改状态；随机走显式 `rng.*` 节点（可复现）。
5. **无 `eval`**：运算 = 封闭算子节点；不执行任何字符串代码。
6. **一切可观测**：每次执行产出逐节点 trace（输入 / 输出 / 状态增量 / 父触发 / 序号）。
7. **唯一事实源**：程序是唯一事实源；旧文件（mechanisms/pipeline/formula/elements）迁移进程序，**不并行两套**。
8. **可版本化**：程序是一份 JSON，带 `programVersion` / `hash`；回放与试跑都钉版本。
9. **组合优于重复**：提供**子图 / 分组节点**把常用片段封装，避免意大利面。

## 3. 三层（重新定义）

```text
┌───────────────────────────────────────────────────────────────┐
│  程序 Program（统一、可编辑、可版本化）                        │
│  nodes[] + edges[](control/data) + entries[] + resources{}      │
│  —— 机制 / 流程 / 公式 / 系别克制 全在这里                      │
├───────────────────────────────────────────────────────────────┤
│  节点类型注册表 NodeTypeRegistry（可插拔、代码、自带 schema）   │
│  · 事件源  · 流程控制  · 取值  · 运算  · 逻辑/比较  · 写入      │
│  · 查询  · 随机  · 资源  · 子图                                 │
├───────────────────────────────────────────────────────────────┤
│  运行时 Runtime（代码、极简固定）                              │
│  · 调度激活 → 拉取数据边 → 执行节点 → 写状态 → 记 trace        │
└───────────────────────────────────────────────────────────────┘
        ↑ 程序 + 节点库 + 资源 = 可实例化、可 reload、可沙盒
```

## 4. 节点分类与粒度

> 命名 `域.动作`。每类节点声明：输入端口、输出端口、参数 schema、是否纯函数、是否产生副作用、可否异步/延迟。

### 4.1 事件源（触发）`on.*`
`on.battleStart` / `on.turnStart` / `on.actionDeclared` / `on.beforeAction` / `on.beforeDamage` / `on.onHit` / `on.afterDamage` / `on.actionResolved` / `on.beforeSwitch` / `on.onEntry` / `on.afterSwitch` / `on.beforeDeath` / `on.afterDeath` / `on.turnEnd` / `on.skillUsed` / `on.statusApplied` / `on.markApplied` / `on.statusReached` / `on.markReached` / `on.buffGained` / `on.debuffGained` / `on.weatherChanged` / `on.cooldownReduced` / `on.passive`。
- 输出：`event`（事件负载）。

### 4.2 流程控制 `flow.*`
`flow.seq`（顺序） / `flow.branch`（bool 二选一） / `flow.switch`（多分支） / `flow.gate`（oncePerTurn / 每回合一次 / 概率门） / `flow.delay`（延迟到指定 timing，等价 `scheduleEffect`） / `flow.scheduleEntry`（换人登场队列） / `flow.emit`（派发领域事件，触发级联） / `flow.subgraph`（调用子图）。

### 4.3 取值 `read.*`
`read.literal`（常量） / `read.path`（点路径：`self.active.hp` / `target.active.marks.x` / `event.*`） / `read.skill`（技能字段） / `read.sprite`（精灵字段） / `read.slot`（行动技能的技能栏槽位） / `read.neighbor`（相邻技能威力：和 / 差） / `read.count`（按图鉴条件计数） / `read.countKeys`（对象键数） / `read.aggregate`（对数组求和 / 极值） / `read.length`。

### 4.4 运算 `math.*` / 逻辑 `logic.*` / 比较 `cmp.*`
- `math.add/sub/mul/div/floor/ceil/round/min/max/pow/clamp/mod`、`math.expr`（多项表达式，复用 P1 求值器）。
- `logic.and/or/not`。
- `cmp.eq/neq/gt/gte/lt/lte/in/has/contains`。

### 4.5 写入（唯一的副作用节点）`write.*`
即现有 effect 原语逐个成为写入节点：`write.dealDamage` / `write.heal` / `write.modifyStat` / `write.clearStat` / `write.modifyDamage` / `write.setHits` / `write.setDamageReduction` / `write.applyStatus` / `write.setStatus` / `write.scaleStatus` / `write.settleStatus` / `write.removeStatus` / `write.applyMark` / `write.setMark` / `write.scaleMark` / `write.transferMark` / `write.transformMark` / `write.removeMark` / `write.consumeMark` / `write.modifySkillCost` / `write.clearCostMod` / `write.modifyCooldown` / `write.modifyEnergy` / `write.modifyMagic` / `write.modifySwitchLock` / `write.forceSwitch` / `write.escape` / `write.allowSwitch` / `write.rotateLoadout` / `write.learnSkill` / `write.forgetSkill` / `write.replaceSkill` / `write.randomizeSkill` / `write.swapSkillSet` / `write.addCounter` / `write.setCounter` / `write.clearCounter` / `write.modifySkill` / `write.changeWeather` / `write.setPriority` / `write.forceFirst` / `write.insertAction` / `write.cancelAction` / `write.replaceAction` / `write.setRuleModifier` …
- 输入：目标端口 + 各参数端口（值可由上游数据边提供）。

### 4.6 查询 / 随机 / 资源 `query.*` / `rng.*` / `resource.*`
- `query.resolveTarget`（self / opponent / event-sourced）、`query.isDefenseSkill`、`query.markCap`。
- `rng.int` / `rng.chance`（受种子驱动，可复现）。
- `resource.elements`（克制矩阵 / 倍率 / 合并规则）、`resource.rules`、`resource.formula`、`resource.skills`、`resource.sprites`——系别克制与公式因此成为**可编辑的资源节点**（满足「系别克制可改」）。

## 5. 执行模型

- **激活（Activation）**：事件源节点触发时产生一次激活，携带 `event` 负载与 `parentEvent`。
- **控制流**：运行时沿 `control` 边游走（`flow.seq` 按端口顺序，`flow.branch` 依条件选路）。
- **数据流**：节点执行前，对每个数据输入端口**拉取**其上游节点输出（纯节点惰性求值、可缓存）。
- **副作用**：仅 `write.*` 改 `BattleState`；每次写入记状态增量到 trace。
- **级联**：`flow.emit` 派发领域事件（如 `statusApplied` → `statusReached`），运行时把新激活压栈（可设深度上限，现有 `depth < 4`）。
- **确定性**：纯节点 + 种子 `rng.*`；同一程序 + 同一种子 = 同一结果。
- **延迟 / 门**：`flow.delay`、`flow.gate` 由运行时维护待结算队列与每回合计数（等价现有 `pendingEffects` / `onceFired`）。

## 6. 程序文档 schema

```jsonc
{
  "programVersion": "1.0.0",
  "hash": "…",                       // 内容哈希，回放/试跑比对
  "nodes": [
    { "id": "n1", "type": "on.beforeAction", "params": {}, "position": { "x": 0, "y": 0 } },
    { "id": "n2", "type": "read.path", "params": { "path": "self.active.hp" } },
    { "id": "n3", "type": "cmp.lt", "params": {} },
    { "id": "n4", "type": "flow.branch", "params": {} },
    { "id": "n5", "type": "write.dealDamage", "params": { "category": "Physical" } }
  ],
  "edges": [
    { "from": { "node": "n1", "port": "out" }, "to": { "node": "n4", "port": "in" }, "kind": "control" },
    { "from": { "node": "n2", "port": "value" }, "to": { "node": "n3", "port": "a" }, "kind": "data" },
    { "from": { "node": "n3", "port": "value" }, "to": { "node": "n4", "port": "cond" }, "kind": "data" },
    { "from": { "node": "n4", "port": "then" }, "to": { "node": "n5", "port": "in" }, "kind": "control" }
  ],
  "entries": ["n1"],
  "resources": {
    "elements": { "matrix": {}, "values": {}, "combine": {} },
    "rules": { "formula": {}, "combat": {}, "energy": {} }
  }
}
```

- **校验** `validate(program)`：节点类型存在；端口存在且数据类型匹配；无环（控制流）；必填端口已连；`entries` 可达；资源引用有效。
- **子图**：`flow.subgraph` 引用一段可复用子图（参数化），是控制复杂度的主要手段。

## 7. Trace 模型（逐节点）

每次执行产出有序 trace：

```jsonc
{ "seq": 12, "activation": "a3", "parent": "a1", "node": "n5", "type": "write.dealDamage",
  "inputs": { "target": "enemy", "power": 110, "category": "Physical" },
  "outputs": { "event": "damage" },
  "mutations": [ { "path": "enemy.active.hp", "before": 300, "after": 190 } ],
  "durationUs": 42 }
```

- 这正是「看到底层执行了哪些东西」：**哪个节点、什么输入、写出什么、改了哪里的状态**。
- 与 P1 的伤害 `breakdown`、W0 的事件 `trigger` 对齐：trace 是它们的超集。

## 8. 现有资产迁移映射

| 现状 | 迁移为 |
| --- | --- |
| `mechanisms.json`（trigger + when + effects） | 每条形如 `on.X → [条件子图] → [写入节点]`；`when` 编译成 `cmp.*` / `logic.*` 子图 |
| `pipeline`（`step` 阶段顺序） | 控制流子图：`flow.seq` 串起各阶段，阶段处 `flow.emit` / 调用触发源 |
| `rules.formula`（P1 表达式 AST） | `math.expr` 节点（直接复用 `effects/formula.ts` 求值器） |
| `elements`（系别克制） | `resource.elements` 资源节点（可编辑；满足「克制可改」） |
| `rules` / `stats` | `resource.rules` / `resource.stats` |
| `onceFired` / `pendingEffects` | `flow.gate` / `flow.delay` 的运行时状态 |
| 既有 effect 原语 | `write.*` 节点（语义不变，接口变端口） |

- **迁移策略**：先写一个**编译器**把现有 `mechanisms` / `pipeline` / `formula` 编译成程序（自动生成节点/边），作为过渡与回归基准；随后**程序成为唯一事实源**，旧文件退役。

## 9. 关键决策与风险

- **D1 指令 vs 程序**：用 NodeTypeRegistry（代码）+ 一份程序（配置）取代「引擎层 / 数据层」。
- **D2 细粒度 + 子图**：细粒度给最大灵活度，但必须配合**子图/分组**避免意大利面。
- **D3 纯函数优先**：取值/运算/比较纯函数、可缓存；副作用只经 `write.*`。
- **D4 无 `eval`**：运算节点是封闭算子；节点执行器为注册的强类型函数。
- **D5 唯一事实源**：程序为准，旧文件经编译器迁移后退役。
- **D6 可版本化可沙盒**：程序带 `programVersion` / `hash`；运行时从「程序 + 节点库 + 资源」实例化，可 `reload` / 沙盒试跑。
- **风险 R1 性能**：细粒度节点多、逐节点 trace 有开销 → 需要节点级缓存、trace 分级（调试全量 / 生产轻量）。
- **风险 R2 复杂度/校验**：需要端口类型检查、环检测、子图与必填校验，否则易搭出坏程序。
- **风险 R3 迁移量**：现有 mechanisms 数百条要编译成子图，需自动化编译器 + 回归基准。

## 10. 非目标

- 不做数据里的任意脚本 / `eval`。
- 不做图灵完备的通用语言（节点词汇封闭、受控）。
- 不改外部图鉴同步、DSH / 站点数据。
- 不改决策层搜索语义（可用同一程序跑，但本稿不重构 MCTS）。
- 不做多人协作 / 云端程序库。
