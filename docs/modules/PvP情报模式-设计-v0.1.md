# PvP 对战模式（我方已知 / 对方只知精灵）· 设计 v0.1

> 文档状态：设计 ✅ v0.1 · 代码 ✅（模式开关 / 我方资质与技能录入 / 对方只知精灵 / 引擎档案接入）· 验证 🟡（面板公式已对拍；对方未知项的推断待实战回填）· 生产 ✅

## 1. 定位与边界

对战台（`/`）原先只有一种**双透明沙盒**：双方的面板、技能、性格都当已知，MCTS 直接对双方求解，适合「假设双方配置都清楚」的推演。

真实 PvP 不是这样：我方（红队）6 只是自己养的，**资质 / 技能 / 性格都知道**；对方（蓝队）6 只**只知道「带了哪些精灵」**，等级固定 **60**、星级固定 **5★**，**资质（性格 / 天分）/ 技能全部未知**。双方各上场一只，逐回合打。

本稿把 **PvP 模式**做进对战台本身（不另开页面）：

1. **模式开关**：`PvP`（默认）/ `沙盒`。
2. **我方（左）**：每只可录 **等级 / 星级 / 性格 / 六项天分 / 出战 4 招**，并实时预览换算面板。
3. **对方（右）**：每只**只登记精灵**，资质 / 性格 / 技能一律未知。
4. **引擎接入**：我方按录入资质算面板（血量 / 伤害）；对方按**中性 5★·60 级**占位估算。
5. **对局中落实**：对方技能未知 → 技能位为空，用「换」记录它这回合**实际用的技能**并结算。

不在本稿范围：

- 对方技能效果 / 性格的自动推断（先手工落，自动化另稿）。
- 对方**行动概率模型**（已有 `roco.opponentLibrary` / `roco.opponentModel`，后续接）。
- 我方队伍的 localStorage 持久化（当前每次刷新重置为默认阵容）。

## 2. 设计原则

1. **已知才填、未知留空**：对方默认**不带任何资质**（不假设星级、不假设性格、不假设天分），血的教训是曾把野怪默认成有星级。
2. **未知用中性占位、但显式标注**：对方引擎侧按「中性性格 · 5★ · 60 级 · 天分 0」估算，UI 明写「资质未知 · 按中性 5★·60 级估算」。
3. **状态即真相**：面板数值一律由引擎 `computeStats` 换算，前端不另写公式。
4. **复用既有面板**：对局里仍用 `SkillGrid` / `OtherActions` / `FaintPicker`，只按模式**改初始加载与文案**，不造第二套。

## 3. 领域模型

`apps/web/src/modules/board/util.ts`：

```ts
type TalentMap = Partial<Record<StatKey, number>>; // 天分 1~10；缺项 = 未填（按 0）

interface PetSetup {
  level: number;          // 默认 60
  stars: number;          // 0~5，默认 5
  nature: string | null;  // 性格 id；null = 中性
  talent: TalentMap;
  skills: string[];       // 出战 4 招；空 = 用本精灵默认 4 招
}

interface TeamEntry {
  spriteId: string;
  setup?: PetSetup;       // 无 = 未知资质（对方）
  skillsUnknown?: boolean;// true = 技能未知（引擎按默认 4 招估算，界面不展示为已知）
}
```

换算：`profileFromSetup` 把 `PetSetup` 转成引擎 `StatProfile`，**个体值 = 天分 ×(1 + 星级)**，与《数值与伤害模型》口径一致；`buildState(catalog, playerTeam, enemyTeam)` 接收 `(string | TeamEntry)[]`，逐只调 `activeFromSprite(sprite, stats, energy, profile)` 落 `profile`，并给血量/伤害结算用。

## 4. 数据库 / 接口

无新增接口。沿用 `POST /api/engine/simulate/turn` 等；新增的 `profile.stars` 由 `engine/api/handlers.ts` 的 `parseProfile` 一并解析（此前只解析 `level / nature / iv`）。

## 5. 路由与页面

- `/` 对战台：setup 加「模式」开关 + 双列队伍编辑器 → 对局。
- 我方编辑器（`board/pet-setup.tsx` 的 `BuildEditor`）：
  - 精灵下拉；
  - **等级 / 星级**；
  - **性格矩阵**（`NaturePicker`）：6×6 网格，**行 = ↑提升项、列 = ↓下降项**，点格即选、同行同列禁用，另有「中性」按钮；显示已选性格名与 `X↑ Y↓`；
  - **面板雷达图**（`board/stat-radar.tsx`，ECharts radar）：六轴（生命/物攻/魔攻/物防/魔防/速度），实线 = 当前面板、虚线 = 中性基准；
  - **三维及加点**：六行，每行「加点」开关 + 天分数值（1~10）+ 实时面板值；`individual.investCount=3` → 最多开 3 项，超出 `sonner` 提示；
  - **出战技能**：4 槽（本精灵技能 / 全部技能）。
- 对方编辑器：只有精灵下拉 + 「资质 / 性格 / 技能未知」说明。
- **阵容库**（`board/lineup-bar.tsx` + `board/lineups.ts`，localStorage `roco.lineups`）：每侧顶部一条，输入名字「保存阵容」（同名同侧覆盖），下方 chip 一键套用、`×` 行内二次确认删除；我方存的是含资质 / 技能的整队，对方存的是只含精灵的整队。
- 对局中：我方场下多一张「我方面板」雷达卡（由 `active.profile` 实时换算）；对方场上卡副标题写「资质未知 · 按中性 5★·60 级估算」；对方技能位为空，文案提示用「换」记录实际技能。

## 6. 数据

- `data/stats.json` 0.6.0：补齐 `natures` 为 **6 项两两组合 30 条 + 中性**（原仅 9 条），id 形如 `atk_spatk`，中文名仅 8 条按游戏常见口径命名、其余以 `↑X ↓Y` 占位；这样「快速选性格」的任意组合都能在引擎里按 id 命中 `natureMultiplier`。
- `individual.investCount=3` / `maxPerStat=60` 为三维与加点上限的权威来源（前端 `MAX_INVEST=3` / `MAX_TALENT=10`）。

## 7. 关键决策

1. **做进对战台而非独立页**：用户要的是「对战面板」本身的模式，独立 `/scout` 页已删除。
2. **对方引擎侧仍给 4 招**：完全空技能会让引擎无合法动作，故引擎按本精灵默认 4 招估算，仅界面不展示为已知。
3. **对方不假设星级 / 性格 / 天分**：用中性占位，以免把未知当已知。
4. **我方默认 5★·60 级·中性**：我方是自养宠，星级/等级通常明确，先给一个合理默认，用户再改。
5. **性格用矩阵点选而非下拉**：30 条性格在下拉里太长；6×6 矩阵「行 ↑ / 列 ↓」一格即选，且天然排除同行同列。
6. **雷达图叠加中性基准**：单看绝对值没有参照，虚线基准让「性格 + 加点」的收益一眼可见。
