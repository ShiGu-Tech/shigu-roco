# 图鉴数据同步 · 设计 v0.1

> 文档状态：设计 ✅ v0.1 · 代码 ✅ 第一阶段 · 验证 ✅ · 生产 ⬜ 未开始

## 1. 定位与边界

将 [roco.world 中文站](https://roco.world/zh/) 的图鉴数据登记为 shigu-roco 的可版本化动态资源，为对战分析提供完整的精灵形态、技能、学习关系、属性、被动描述和来源信息。

`dist-share` 仅是本轮讨论使用的临时展示包，不是数据源，不进入长期同步协议。

本模块负责：

- 读取外部图鉴快照并验证元数据、数量和引用关系；
- 通过注册接口写入版本化注册包；
- 将外部字段规范化为引擎的图鉴结构（sprites / skills / marks / weather / elements）；
- 保留原始来源、版本哈希和未翻译规则，供后续机制映射和人工校对；
- 原子切换当前激活版本，支持回滚和定时重复同步。

本模块不负责：

- 将中文自然语言被动或技能描述自动推断成可执行机制；
- 覆盖已有的战斗规则、倍率和机制注册；
- 把外部站点作为运行时在线依赖。

## 2. 权威数据源

唯一参考入口：`https://roco.world/zh/`。

后续同步器从中文站的页面、接口或静态资源中读取并生成注册请求。中文名称、中文说明、属性中文名、机制词条和图片 URL 必须保留为注册数据的展示事实源；英文枚举只能作为引擎内部规范化字段。

## 3. 注册模型

```text
CatalogRegistration
├─ registrationId
├─ source = roco-world
├─ catalogVersion
├─ generatedAt
├─ registeredAt
├─ sourceDir / sourceFiles
├─ counts
├─ warnings[]
└─ normalized
   ├─ sprites[]
   ├─ skills[]
   ├─ skillLearners
   ├─ elements
   └─ sourceMeta
```

实体 ID 必须稳定：精灵使用 `sp-{id}-{formId}`，技能使用 `sk-{id}`。同一基础精灵的不同形态不能共享运行时 ID。

## 4. 注册接口

- `POST /api/engine/admin/catalog/register`
  - body：`{ sourceDir?: string, snapshot?: ExternalSnapshot, activate?: boolean }`
  - `sourceDir` 仅用于未来的本地同步适配器，不代表权威来源；适配器必须声明来源为 `https://roco.world/zh/`。
  - `snapshot` 用于后续定时任务或其他同步器直接提交已经读取的 JSON。
  - 同一 `source + catalogVersion` 幂等，返回既有注册记录。
  - 注册成功后写入 `data/registry/catalogs/{registrationId}/`，并在 `active.json` 激活。
- `GET /api/engine/admin/catalog/registry`
  - 返回当前激活版本、历史版本、统计和校验警告。
- `POST /api/engine/admin/catalog/activate`
  - body：`{ registrationId }`，仅切换已注册版本。

## 5. 激活与兼容

系统默认不激活动态实体，启动后 `/health` 的精灵、技能、印记、天气数量为 0。`scripts/dev-with-catalog.ps1` 负责启动服务、等待就绪并调用注册接口；生产环境也应由外部调度器在服务启动后执行同样的注册请求。

注册包作为当前动态目录提供给 catalog 和后续分析；基础战斗规则仍由系统代码和规则配置维护。注册器不自动生成复杂机制，所有不可验证的被动和复杂技能仅保留 `rawText` / `params.note`，不能伪装成已实现规则。

启动脚本只负责启动服务和调用注册接口；后续同步脚本必须以 `https://roco.world/zh/` 为抓取入口，再提交规范化快照。

同步器入口：

```powershell
node scripts/sync-roco-world.mjs
node scripts/sync-roco-world.mjs --register
```

同步器先通过中文站 sitemap 和详情页生成快照，校验精灵属性、种族值、学习关系和技能字段完整后才允许 `--register`；校验失败时只报错，不向系统注册不完整数据。

## 6. 校验规则

- 必须存在全部 8 个输入文件；
- `meta.counts` 与实际数组数量不一致时产生 warning；
- 精灵技能引用必须能在技能表中找到；
- `spirit-skills` 的 key 必须对应精灵的 `id:formId`；
- 技能属性、精灵属性必须能映射到引擎属性 ID；未知属性保留 warning，不丢弃实体；
- 同一规范 ID 不得重复；
- 注册写盘采用临时目录 + rename，避免半成品成为激活版本。
