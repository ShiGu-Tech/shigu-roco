## 1. 定位与边界

**技能能耗不是技能图鉴的固有属性，而是「本场战斗内、挂在某只精灵身上的修正条目集合」**。一次释放可能被多个来源修改：技能自身（天洪）、精灵特性（浸润 / 缩壳 / 冰封）、状态 / 名义 debuff（聒噪、冻结附带）。

引擎职责：提供**声明式的能耗修正模型**与**统一的"有效能耗"读取**，使**执行、我方预览、对手预览、`legalActions` 看到同一份结果**；**具体条目仍由数据（技能 / 特性 / 状态）用触发器 + 条件 + 效果登记**，引擎不认识任何具体 id。

边界：

- 引擎不硬编码「某技能减多少」；数据侧只登记条目参数。
- 「可驱散 / 不可驱散」「隐藏 / 可见」是**条目属性**（按来源与游戏表现），不是引擎对某技能的特判。
- 迸发 / 选择 / 位置改写等子系统不在本稿（见 §8）。

## 2. 设计原则

1. **读时求和，不物化**：能耗由 `基础 + Σ 匹配条目` 现算，避免"驱散后残留""预览与结算两套数"。
2. **所见即所扣**：UI 显示、`legalActions` 筛选、结算扣能量统一走同一个 `effectiveCost`。
3. **来源决定可见性与可驱散性**：名义 debuff（技能造成）可驱散且可见；特性造成的不可驱散；是否隐藏按游戏表现（天洪只看数字）。
4. **次数 / 时效引擎化**：`oncePerTurn`（每回合各 1 次）、`turns`（回合末 −1）、`nextAction`、`aura`（在场光环）由引擎统一维护，不让数据侧绕。
5. **下限 0**：任何情况下有效能耗 `clamp ≥ 0`；扣能 `max(0, ...)`（现有 `battle.ts:406` 语义保留）。
6. **只追加**：在既有 `modifySkillCost` 上扩展字段 + 新增清除原语，不改既有语义。

## 3. 领域模型

### 3.1 存储

`ActiveSprite` 新增：

```ts
costMods?: CostMod[];

interface CostMod {
  key: string;                 // 唯一键；同 key 覆盖/刷新（去重、驱散定位）
  source: "skill" | "trait" | "status";
  sourceId?: string;           // 技能 / 特性 / 状态 id（UI 展示与驱散定位）
  scope: "skill" | "attack" | "defense" | "all";
  skillId?: string;            // scope=skill 时
  elements?: string[];         // 按系筛选（如消波块：地系）
  excludeElements?: string[];  // 反向筛选（如盲从：非幻系）
  delta?: number;              // 加性
  multiply?: number;           // 乘性
  mode?: "add" | "set";        // add（默认）同 key 累积；set 同 key 替换（每回合重算，如天气）
  duration: "permanent" | "turns" | "nextAction" | "aura";
  turnsLeft?: number;          // duration=turns
  oncePerTurn?: boolean;       // 每回合限一次（触发型）
  dispellable: boolean;        // 名义 debuff=true；特性=false
  hidden: boolean;             // 天洪=true（只改数字）；特性/状态=false（可显示）
  usedThisTurn?: boolean;      // oncePerTurn 运行时状态
}
```

> 现有 `skillMods[skillId].cost` 迁移到 `costMods`；`skillMods` 继续承载 `power / hits / priority`。

### 3.2 有效能耗

```
effectiveCost(state, side, skillId):
  base = getSkill(bundle, skillId).cost
  x = base; add = 0
  for m in active.costMods where matches(m, skillId):
      if m.multiply: x *= m.multiply
      add += m.delta ?? 0
  add += skillMods[skillId].cost ?? 0        // 旧数据兼容
  return max(0, floor(x + add))              // 向下取整（省能耗方向）

matches(m, skillId):
  m.scope == "all" ? true
  : m.scope=="skill" ? m.skillId == skillId
  : m.scope=="attack" ? skill.category ∈ {Physical, Magic}
  : m.scope=="defense" ? skill.actionType == "Defense"
  && (elements 命中 / excludeElements 不命中 skill.element)
```

- **元修正**（后置）：`倾轧`（受能耗变化效果翻倍）、`对流`（增减互换）在 `effectiveCost` 里读精灵上的开关（`costModAmplify` / `costModInvert`）。
- `set` 用于"每回合按当前状态重算"的条目（如同 key 的沙暴耗减半），保证同来源只留最新一条。

### 3.3 时效 / 次数

| duration | 生命周期 |
| --- | --- |
| `permanent` | 到本场结束（或数据侧显式清除） |
| `turns` | 登记时写 `turnsLeft`；每回合末 −1，归零移除 |
| `nextAction` | 该侧下一次行动结算后移除 |
| `aura` | 来源精灵在场即生效；离场时移除（如冰封：在场时敌方全技能 +1） |
| `oncePerTurn` | 回合开始重置 `usedThisTurn`；当回合命中一次后置位，不再触发（如深渊蛙「每回合各1次」） |

### 3.4 驱散

- 名义 debuff（`source:"skill"`，如聒噪）`dispellable:true` → 可被 `clearStat`（减益）清除。
- 特性造成（`source:"trait"`，如深渊蛙）`dispellable:false` → 驱散无效。
- 新增 `clearCostMod { target?, source?, dispellableOnly? }`，或扩展 `clearStat` 增加 `domain:"cost"`；默认只清 `dispellable`。

## 6. 路由与页面（UI）

- **技能卡能耗**：显示 `effectiveCost`，修正项以 `能耗 3 → 1` 形式标注来源（hover 列出来源条目）。
- **对手侧**：同样读 `effectiveCost` 显示对手技能能耗（可开关）。
- **特性触发 icon**：精灵头像角标——触发特性（或产生/改变能耗条目）时显示小 icon，hover 展示"触发了什么、修改了哪些游戏状态"（来自事件流的 `sourceId` + 变更明细）。天洪等隐藏条目**不出现 icon，只体现在能耗数字**。

## 7. 关键决策（已定）

1. **声明式 `costMods` 取代物化 `skillMods.cost`**：读时求和，保证驱散 / 时效 / 预览 / 结算一致。
2. **可驱散性由来源决定**：名义 debuff（技能造成）可驱散、特性造成不可；不用特判具体技能。
3. **`oncePerTurn` 引擎化**：不靠数据侧计数器绕（引擎先落一版：回合开始重置、按 `side:机制` 只触发一次）。
4. **取整 `floor`（省能耗方向）**：如 3 能耗地刺开沙暴 `3×0.5=1.5→1`；并 `clamp ≥ 0`。
5. **时效**：`turns` 回合末 −1；`nextAction` 该侧下次行动后移除；`aura` 来源离场（换人 / 阵亡）即回收。
6. **是否本场永久由数据（技能 / 特性）声明**：`duration:"permanent"` 才跨换人保留；其余离场即清。
7. **隐藏与否是条目属性**：天洪 `hidden:true`（只改能耗数字、无 icon）；特性可见。
8. **天洪本回合不享受 −6**：登记在本次行动结算之后，从下次使用起生效。
9. **聒噪换人不保留**（非永久，敌换上即清）。
10. **结算顺序**：`base × Πmultiply + Σdelta`（同 key 的 `mode` 去重在登记期完成），消除数据书写顺序的影响。

## 8. 非目标

- 迸发 / 选择 / 位置改写子系统（`超负荷` / `异类` / `盲拧` 等）另稿。
- `倾轧` / `对流` 的元修正先预留开关，本稿不实现。
- 不改伤害 / 威力通道（本文只涉及能耗）。
