# 数值与伤害模型（洛克王国底层机制）· 设计 v0.1

> 文档状态：设计 ✅ v0.1 · 代码 ✅（星陨 / 特性倍率表除外）· 验证 ✅ · 生产 ✅

## 1. 定位与边界

把《洛克王国世界》的**真实数值换算**与**伤害结算**沉淀为引擎的底层机制，替代此前 `stats.ts` / `damage.ts` 的占位实现（宝可梦式、数值口径不对）。

本稿覆盖：

1. **面板真实数值**：种族资质 / 个体资质 / 性格 / 等级 60 的换算（PVP 口径）。
2. **伤害主公式**：攻防真实数值 + 战时显示威力 + 平衡系数 + 减伤 + 连击。
3. **各项加成倍率**：本系、属性克制（含双系）、强化差值、特性、减伤。
4. **数据契约**：`data/stats.json` / `data/rules.json` 的新结构；属性倍率配置（`values` / `combine`）随图鉴归一化产出（`engine/catalog/normalize.ts`）。

不在本稿范围：

- **星陨**：属印记机制，后续注册到印记效果（`marks` / 机制扩展层）。
- **特性表**（勇敢 / 圣火骑士 / 偏振等 30+ 条）：本稿只留数据驱动的倍率入口，具体表另稿。
- 回合顺序、技能效果 DSL、MCTS（各自模块稿）。

## 2. 设计原则

1. **公式即数据**：所有系数落 `data/*.json`（属性倍率随图鉴归一化），代码只做解释器；实测校准 = 改数据。
2. **PVP 归一**：PVP 视为固定 **60 级 + 5★**，等级折进系数，个体按天分换算；不做真实等级曲线。
3. **可复现**：纯函数、整数舍入规则明确（四舍五入 / 向下取整）。
4. **未确认处显式标注**：双系混合、特性表、强化层存储等标 `【待校准】`，不伪装成确定事实。

## 3. 领域模型

### 3.1 资质（静态）

| 名称 | 来源 | 说明 |
| --- | --- | --- |
| 种族资质（种族值） | 图鉴写死（`catalog.sprites[].race`，现查） | 同种一致，六维 |
| 个体资质（天分） | 运行时 `StatProfile.iv` | 天分 0~10 × 星级系数（5★=×6）→ **IV 0~60**；只能加在 **3 项** |

### 3.2 养成档案（`StatProfile`）

```ts
interface StatProfile {
  level?: number;                 // PVP 固定 60（可省）
  nature?: string | null;         // 性格 id（stats.json.natures）
  iv?: Record<string, number>;    // 个体值：hp/atk/spatk/defense/spdef/speed，各 0~60
}
```

> 旧的「三维（体力/攻击/防御）培养面板 + perPoint」模型**废弃**。

### 3.3 面板真实数值（`stats.ts`）

```text
生命：round( round(种族×1.7 + 个体×0.85 + 70) × 性格 ) + 100
其他：round( round(种族×1.1 + 个体×0.55 + 10) × 性格 ) + 50
```

- `1.1 = 0.01×(60+50)`、`1.7 = 0.02×(60+25)`：**等级 60 已折进系数**。
- `round` = 四舍五入，作用于两次：括号内一次、乘性格后一次；末尾常数在舍入之外。
- 性格只乘括号（种族 + 个体 + 基础），**末尾 +50/+100 不受性格影响**。
- 系数/常数全部来自 `data/stats.json.panels`。

**校验（迪莫 种族 141 / IV 60 / 大胆物攻+20%）：**

```text
round(141×1.1 + 60×0.55 + 10) = round(198.1) = 198
round(198 × 1.2) = 238
238 + 50 = 288   ✓
```

### 3.4 性格（`stats.json.natures`）

- 加成 **×1.2**、削弱 **×0.9**、中性 ×1.0（5★ 口径）。
- 性格改变 → 整体重算（无状态，与升级先后无关）。

> ⚠️ `【待校准】`：图例「迪莫 性格大胆(物攻+20%)」与现有性格表的「大胆=防御+ / 攻击−」冲突，名称→属性映射需按游戏核实。

## 4. 伤害模型

### 4.1 主公式

```text
伤害 = floor( (攻 × 战时显示威力 × 37/41) ÷ 防 ) × 减伤 × 连击

战时显示威力 = 技能威力 × 克制 × 本系 × 攻方特性 × 防方特性 × 强化差值 × 其他
```

- 攻 = 真实物攻 或 魔攻（物理 / 魔法取对应）；防 = 真实物防 / 魔防。
- `37/41 ≈ 0.9024`：平衡系数。
- `floor` 向下取整。

### 4.2 各项倍率

| 项 | 规则 |
| --- | --- |
| 本系 | 技能属性 = 精灵属性 → ×1.25；不一致 → ×1.0 |
| 属性克制 | 双重克制 ×3、单倍克制 ×2、普通 ×1、单倍抵抗 ×0.5、双重抵抗 ×0.25 |
| 强化差值 | `1 + 0.1×攻方层 − 0.1×防方层`（攻+3 ≡ 防−3 ≡ ×1.3） |
| 特性 | 数据驱动倍率表（攻方 / 防方），内置 30+ 条；本稿留入口，默认 1.0 |
| 减伤 | `1 − 减伤%/100`，上限 99% |
| 连击 | 命中段数，默认 1 |

**双系混合规则**（`【待校准】`，与上表一致的最小实现）：

```text
weak  = 防方属性中，本攻击属性为「克制」的个数（0~2）
resist= 防方属性中，本攻击属性为「抵抗」的个数（0~2）
克制项 = weak=0 → 1；weak=1 → 2；weak=2 → 3
抵抗项 = resist=0 → 1；resist=1 → 0.5；resist=2 → 0.25
克制倍率 = 克制项 × 抵抗项
```

> 例：火 vs [草, 水] = 1 弱 1 抗 = `2 × 0.5 = 1.0`，与旧测试一致。

### 4.3 强化差值与 buff 存储

- `buffs[stat]` / `debuffs[stat]` 存**分数**，一层 = 0.1（`+0.3` ≡ +3 层）。
- 强化差值 = `1 + (攻方 buff+debuff) − (防方 buff+debuff)`，攻/防属性取对应物理 / 魔法项。
- 伤害中的攻/防用**纯面板数值**（不含 buff）；buff 只通过强化差值进伤害。
- 速度 / 展示用 `effectiveStat = 面板 × (1 + buff + debuff)`（保留）。

### 4.4 星陨（占位）

```text
星陨威力 N = N² + 24N − 24   （1层=1、5层=121、10层=316）
星陨伤害 = floor( round(攻 × 星陨威力 × 幻系克制 × 特性 × 强化差值 × 37/41) ÷ 防 ) × 减伤
```

> 归入**印记**机制，后续注册到印记效果，不在本稿实现。

## 5. 数据契约

### 5.1 `data/stats.json`

```jsonc
{
  "level": { "default": 60 },
  "panels": {
    "hp":      { "raceFactor": 1.7, "ivFactor": 0.85, "base": 70, "result": 100 },
    "default": { "raceFactor": 1.1, "ivFactor": 0.55, "base": 10, "result": 50 }
  },
  "individual": { "starMultiplier": 6, "maxPerStat": 60, "starMax": 5, "investCount": 3 },
  "natures": [ { "id": "adamant", "up": "atk", "down": "spatk", "upFactor": 1.2, "downFactor": 0.9 } ],
  "trainingProfiles": { "options": [ { "id": "full", "label": "满个体", "prior": 1, "iv": { "hp": 60, "atk": 60, "speed": 60 } } ] }
}
```

### 5.2 `data/rules.json.damageFormula`

```jsonc
{ "kind": "roco_v1", "balance": 0.9024390244, "stab": 1.25 }
```

### 5.3 属性倍率（图鉴归一化产出）

- 不再有 `data/elements.json` 静态文件；由 `engine/catalog/normalize.ts` 在注册图鉴时写入 `bundle.elements`（`elements` 属性表 + `matrix` 克制矩阵 + 下列配置）。
- `values`：`counter=2 / counter3=3 / neutral=1 / resisted=0.5 / resisted4=0.25`。
- `combine`：`{ mode: "count", clampTo: [0.25, 3] }`。

## 6. 接口 / 契约变更

| 位置 | 变更 |
| --- | --- |
| `StatProfile` | `training`（三维）→ `iv`（个体 0~60） |
| `StatsData` | 去 `training`；增 `panels` / `individual`；`trainingProfiles[].training` → `iv` |
| `GET /catalog.stats` | 回传 `panels` / `individual` / `natures` / `trainingProfiles` |
| `computeDamage` | 新公式；`DamageResult` 增 `breakdown`（各倍率） |
| `typeMultiplier` | 改为「克制/抵抗计数」规则 |

## 7. 关键决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 等级 | PVP 归一 60，折进系数 | 与真机 PVP 口径一致 |
| 个体建模 | 天分×星级，IV 0~60，限 3 项 | 来自官方图例 |
| 性格只乘括号 | 末尾常数不乘性格 | 与图例 288 校验一致 |
| 双系 | 计数规则（弱+1 / 抗×0.5） | 与给出的 5 档表一致 |
| 特性 | 只留数据驱动入口 | 30+ 条特性表另稿 |

## 8. 非目标

- 不做真实等级成长曲线（PVP 固定 60）。
- 不实现特性表与星陨（另稿）。
- 不引入暴击 / 命中 / 随机浮动（本项目非外挂、可复现优先）。

## 9. 待校准 / 待确认

1. 性格名称→属性映射（大胆 疑似物攻+20%，与现表冲突）。

3. 特性倍率表数据（30+ 条）。
4. 连击 / 减伤的数据来源（技能 / 印记 / 特性）。
