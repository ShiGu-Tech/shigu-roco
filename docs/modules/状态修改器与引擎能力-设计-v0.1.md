## 1. 定位与边界

**一次释放技能 = 一束「状态修改器」**（可能多个）。引擎的职责不是「认识每个技能」，而是**安全、通用地把修改器作用到状态上**，并能在结算中读「有效状态 / 有效规则」。

- 引擎提供**操作原语**（effect commands）；技能 / 特性 / 印记 / 天气只是「触发器 + 条件 + 原语组合」的**数据**。
- **能只改数据表达的，不动引擎版本**；只有**新增操作原语**（或结算语义变化）才 bump `ENGINE_VERSION`（见《引擎版本与维护》）。
- 引擎不认识游戏策略；不在引擎里写「某个技能怎么处理」。

## 2. 设计原则

1. **域化状态**：把战斗状态切成互不串味的域（生命 / 能量 / 强化 / 状态 / 印记 / 天气 / 冷却 / 魔力 / 离场 / 技能池 / 行动队列 / 规则 / 记忆），每个域暴露一组「增删改查 + 缩放 / 转移」原语。
2. **原语正交**：一个原语只做一件事；复杂效果由多个原语组合。
3. **target 可解析**：`self / actor / target / opponent` 统一由运行时解析（已有）。
4. **动态取值**：需要「按当前状态算值」时（如层数 = 敌方印记层数），原语支持 `valueFrom`（点路径读当前状态），而不是新增专用命令。
5. **上限 / 例外走规则覆盖**：任何「突破上限 / 特例」用 `setRuleModifier`（`passive` 触发器）表达，**不写死在代码**（见 `marks.replaceDifferent`）。
6. **事务化 + 可预览**：每个命令产生事件明细，供 UI 展示与回归。
7. **只追加**：新原语只加到联合类型 + runtime 一个 case，不改既有语义。

## 4. 接口 / 契约（新增效果命令）

```ts
// 印记域
| { type: "setMark";      target?: string; markId: string; layers: number | { valueFrom: string }; scope?: "sprite" | "team" }
| { type: "scaleMark";    target?: string; markId?: string; factor?: number; delta?: number; scope?: "sprite" | "team" } // markId 省略 = 全部印记
| { type: "transferMark"; markId?: string; amount?: number | "all"; from?: "self" | "opponent"; to?: "self" | "opponent" }
| { type: "transformMark";target?: string; toMarkId: string; scope?: "sprite" | "team" }                                  // 合计层数收拢成一种

// 强化域
| { type: "clearStat";    target?: string; stat?: string; layers?: number | "all"; polarity?: "buff" | "debuff" | "all" }

// 记忆 / 计数域
| { type: "addCounter";   target?: string; key: string; delta: number }
| { type: "setCounter";   target?: string; key: string; value: number | { valueFrom: string } }
| { type: "clearCounter"; target?: string; key?: string }

// 能耗域
| { type: "modifySkillCost"; target?: string; skillId?: string; scope?: "skill" | "all" | "attack" | "defense"; delta?: number; multiply?: number }

// 行动域
| { type: "forceSwitch";  target?: string }         // 强制换人（引擎不自动选，前端补 forced-switch）
| { type: "escape";       target?: string }         // 脱离（“自己脱离 / 敌方脱离”）
| { type: "allowSwitch";  target?: string }         // 允许被限制的换人
```

统一约定：
- 数值字段可为 `{ valueFrom: "<context path>" }`，运行时用 `resolveContextPath`（`target.active.marks.starfall-mark` 等）求值。
- `target` 语义沿用现有 `resolveSide`；`transferMark` 的 `from/to` 用 `self/opponent` 相对触发方。
- 所有命令只产出事件，不做隐藏副作用。

## 5. 关键决策

- **为什么用新原语而不是给技能写分支**：原语是小而通用的「操作」，组合爆炸交给数据；引擎版本只在原语集合变化时动。
- **`valueFrom` 而非专用命令**：把「按状态算值」做成通用能力，避免每来一个「层数 = X」就加命令。
- **记忆/计数放精灵与侧两处**：计数天然是「谁身上 / 哪一队」的属性，放 `active.counters` 与 `side.counters`，条件用 `self.counters.<key>` / `self.active.counters.<key>` 读取。
- **`transformMark` / `scaleMark` 的必要性**：「驱散后每层获得增益」「所有印记变星陨」这类要**先合计再写回**，用组合命令会出现中间态，务必原子化。

## 6. 非目标

- 不做「技能自然语言 → 效果」的全自动解析：仍以转写器（`scripts/derive-effects.mjs`）+ 人工校对为主，无法确认的登记 `unsupported`。
- 不引入脚本沙箱 / 表达式引擎；`valueFrom` 只支持点路径。
- 不改现有原语的语义（只追加）。

### 批次 1 目标技能（印记域）

已登记（`mechanisms.json` 0.9.0）：

- `心灵洞悉`（`applyMark` + `layersFrom`：层数 = 敌方印记层数）。
- `二律背反`（应对防御 → `scaleMark factor:2` 翻倍）。
- `拟寄生`（`transferMark` 偷取敌方 1 层）。
- `许愿池`（双方已有印记 `scaleMark delta:1`）。
- 星云旅者「与星星同行」（`transformMark`：敌方所有印记收拢成同层星陨）。

仍待（需要其它批次 / 动态读取器）：

- 掠影 / 翼刃（“偷取”）、扩散侵蚀（按中毒印记层数 ×2 → 需带系数的动态取值）、
  焚毁 / 焚尽（驱散后每层获得物攻+X% → 需「合计层数」动态读取器）。
- `超新星馈赠` 永久 +1（需批次 3 计数域）。

### 批次 3 已登记（记忆域，`mechanisms.json` 0.10.0）

- `奇点`（上回合双方有水系 → `applyMark` +4 层，读 `self/opponent.lastTurn.element`）。
- `掠影`（上回合双方有火系 → `modifyEnergy` 偷取 3 能量）。
- `乘胜追击`（`addCounter` + `setHits.hitsFrom`：连击数 = 永久计数器）。
