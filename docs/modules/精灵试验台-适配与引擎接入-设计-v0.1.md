# 精灵试验台 · 精灵适配与完整引擎接入 · 设计 v0.1

> 文档状态：设计 ✅ v0.1 · 代码 ⬜ · 验证 ⬜ · 生产 ⬜

## 1. 定位与边界

承接《精灵试验台-设计-v0.1》。本稿解决「样板精灵能摆，但**个体差异**摆不进去」：

- 状态分类可视化（属性增益 / 减益、**正面印记 / 负面印记**、状态、天气、计数器）直接显示在精灵下方；
- **正 / 负面印记**的一般规则（多数精灵各最多 1 个）与**逐精灵例外**（如里拉鳐「吟游之弦」：异种印记不替换、同时生效）；
- **特性是否触发**可勾选（如某只火系特性按需点亮）；
- 每条交互即使只有一回合，也用**完整对战引擎**结算（非仅记录）。

边界：仍是离线单机 1v1；不扩到 6v6；不改红线。

## 2. 设计原则

1. **数据驱动适配**：每只精灵 / 每个印记 / 每条特性的「试验台属性」写**数据**（`data/lab-adapters.json`）+ 通用默认；`modules/engine/**` 与试验台代码**不含具体精灵 / 印记内容**（守《引擎边界》红线）。
2. **复用引擎**：交互结算走既有 `Simulator`（`simulate/turn`），不自写规则。
3. **分层**：通用规则（印记一般最多一对、状态按 `maxStack`、天气唯一）为默认；逐精灵 / 逐印记**覆盖**。
4. **未知不当已知**：无适配时用通用默认并标「未适配」，不臆造。

## 3. 领域模型

### 3.1 适配注册（数据）

```ts
interface LabAdapters {
  version: string;
  /** 印记分类与上限：polarity 正 / 负；max 缺省按通用（正 1 / 负 1）。 */
  marks: Record<string, { polarity: "positive" | "negative"; max?: number }>;
  /** 逐精灵覆盖：印记上限放宽（里拉鳐：异种印记并存，不设一对上限）、可勾选特性、说明。 */
  sprites: Record<string, {
    marks?: { maxPositive?: number; maxNegative?: number; allowMultiple?: string[] };
    traits?: string[];          // 可勾选触发的特性（traitKey，如 `trait:sp-xxx-1`）
    notes?: string;
  }>;
  /** 特性触发开关默认值。 */
  traits?: Record<string, { toggle?: boolean; defaultTriggered?: boolean }>;
}
```

- `markId` / `traitKey` 全部来自现查图鉴（唯一来源），不写死中文。
- 通用默认（代码内）：正 / 负印记各最多 1；状态按图鉴 `maxStack`；天气全局唯一。

### 3.2 运行时

- `ActiveSpriteState` 增 `traitTriggers?: Record<string, boolean>`（勾选「本回合是否触发该特性」）。
- 印记校验：增 / 改印记时按 `LabAdapters` 检查上限，超限用 `sonner` 提示（不静默丢）。

## 4. 数据 / 接口

- 新增 `data/lab-adapters.json`（`version` / `updatedAt`），随 `GET /api/engine/lab-adapters` 只读下发；`catalog` 一并带上（省一次请求）。
- **引擎接缝（最小）**：`traitTriggers` 作为状态覆盖进入特性机制派发（新增一个「特性触发覆盖」通道：未勾选的 `trait:` 机制本回合不派发；勾选的强制派发一次）。仅加通道，不写具体机制。
- 无数据库；试验台状态与适配缓存走 `localStorage` / 静态包。

## 5. 路由与页面

- 精灵卡状态区（基础 chip 已在 `lab.tsx`）：细分「属性增益 / 减益 · **正面印记 / 负面印记**（带上限与例外校验）· 状态 · 天气 · 计数器」。
- 精灵卡特性行：可勾选「本回合触发」（`traitTriggers`）。
- 交互卡片：加「**引擎结算预览**」——按当前双方配置 + 该交互双方技能跑一次 `simulate/turn`，列出引擎伤害 / 血量 / 事件，与实测对比（验证实时设置）。

## 6. 关键决策

1. 适配走**数据注册**，引擎与试验台代码不含具体精灵内容。
2. 印记正 / 负面与上限**可配**，逐精灵覆盖（里拉鳐例外）。
3. 交互可用**完整引擎**结算（一回合），与手动登记并存。
4. 缺适配走通用默认并标「未适配」。

## 7. 非目标

- 不一次性适配全部精灵 / 印记（按需逐批登记）。
- 不做多回合 / 6v6 / 联机。
- 不在引擎写具体精灵 / 印记 / 倍率。
