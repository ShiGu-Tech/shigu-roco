# 战斗模拟器（MDP 环境） · 设计 v0.1

> 文档状态：设计 ✅ v0.1 · 代码 ⬜ 未开始 · 验证 ⬜ 未开始 · 生产 ⬜ 未开始

## 1. 定位与边界

模拟器是**固定规则脚本**：给定 `BattleState` 与双方动作，按复刻的官方回合结算逻辑，输出新的 `BattleState` 与事件日志。它是 MCTS 的「环境」（`reset` / `step` / `terminal` / `reward`），也是真机对拍校准的对象。

不负责：搜索策略（MCTS 稿）、UI（辅助台稿）、数据来源（数据层稿）。

## 2. MDP 形式化

| 要素 | 定义 |
| --- | --- |
| 状态 S | `BattleState`：双方魔力、天气、愿力/CD、首领化、双方场上的血量/能量/buff/debuff/印记、我方背包、敌方已见集合 |
| 动作 A(s) | 攻击（选技能）/ 防御 / 状态（选技能）/ 换人（背包每只能上场精灵各一个）/ 愿力魔法 / 首领化 |
| 转移动力学 P | 固定伤害与确定性结算 + 明确的同速随机 / 对手采样。为可复现，随机由 `seed` 注入 |
| 奖励 R | 终局：胜 +1 / 负 −1；非终局 0（可选塑形，见 MCTS 稿估值） |
| 终止 | 我方魔力 = 0（负）/ 敌方魔力 = 0（胜）/ 达到回合上限（推演截断，非真实终局） |

## 3. 设计原则

1. **快照式状态**：`step` 不修改入参，返回全新状态（immutable copy-on-write），便于 MCTS 树节点共存与回溯。
2. **规则可配置**：结算阶段顺序、伤害系数、换人判定依据等来自 `rules.json`，技能 / 特性效果来自 `mechanisms.json`。
3. **阶段化结算**：严格镜像官方四阶段，每个阶段产出事件日志，可逐步对拍。
4. **确定性优先**：同 seed + 同状态 + 同动作 → 同结果；不确定性只在显式随机源处发生。
5. **纯函数核心 + 薄外壳**：`simulate_turn(state, actions, rng, data) -> (state, events)` 为纯函数；I/O 与 API 在外壳。
6. **校准友好**：提供 `/simulate/turn` 与逐阶段日志，便于与真机逐条比对。

## 4. 回合结算顺序

严格按 `rules.turnPhases`（默认）：

```text
① 洛克魔法阶段  magic
   - 双方宣告并使用「愿力魔法」（如有），处理 CD 与次数上限
   - 若为变化技能，按 rules.wish.changeSkillFactor 应用 1.5× 伤害修正

② 换人阶段      switch
   - 处理本回合换人动作
   - 双方同时换人：按「旧场上精灵速度」决定先后（rules.switchOrderBasis=oldActive）
   - 换入触发 onSwitchIn；换出触发 onSwitchOut / 下场清除类印记

③ 精灵技能阶段  skill
   - 先手 / 后手值、速度和同速规则进入行动队列；应对成功可抢占先手
   - 依次执行技能：机制触发 → 固定伤害 / 效果 → 后续机制事件
   - 「应对状态 / 应对防御」在对方已宣告且匹配时触发（conditional.when.action）

④ 结算阶段      settle
   - 伤害落账、印记逐条按 trigger 结算
   - buff/debuff 计时与过期
   - 判定阵亡 → 扣魔力 → 强制换人（若场上空）
   - 检查终止条件
```

> 顺序存疑点（如「印记在阶段③即时结算还是阶段④统一结算」「天气每回合在哪个钩子扣回合」）在实现时以配置钩子表达，标注 `【待校准】`。

## 5. 伤害计算

> ⚠️ v0.2 起伤害公式已按官方口径重写，权威定义见《数值与伤害模型-设计-v0.1》§4。现行形态：

```
伤害      = floor( (A × 战时显示威力 × 37/41) ÷ D ) × 减伤 × 连击
战时威力  = 技能威力 × 克制 × 本系(1.25) × 攻方特性 × 防方特性 × 强化差值 × 其他
强化差值  = 1 + 0.1×攻方层 − 0.1×防方层
克制      = 双系按「克制/抵抗计数」：weak=0/1/2→×1/×2/×3；resist=0/1/2→×1/×0.5/×0.25

A/D 取值：
 - 物攻技能：A = 攻方面板真实 atk，D = 守方面板真实 def（不含 buff，buff 走强化差值）
 - 魔攻技能：A = 攻方 spatk，D = 守方 spdef
 - 状态/防御技能：power=0 → 不进入伤害结算
```

- 公式集中在 `rules.damageFormula`（`balance` = 37/41、`stab` = 1.25）。
- 性格、个体值在 `ActiveSprite.profile`（`StatProfile`）运行时提供，经 `stats.ts` 换算进 A/D/hp；换算数据在 `data/stats.json`（已落地，60 级 PVP 口径）。
- 特性倍率表、连击 / 减伤来源、星陨（印记）仍 `【待校准】` / 待补。

## 6. 印记结算

- 印记定义在图鉴 `marks` 与 `mechanisms.json`，载体分 `sprite`（挂在精灵）与 `field`（场地）。
- 结算流程：遍历双方及场地的印记 → 按 `trigger` 匹配当前时机 → 执行 `ops` → 更新层数。
- 叠加：`stack = min(stack + delta, maxStack)`；`clearOnSwitch` 决定换人是否清空（我 / 敌各自处理）。
- 引爆：`detonate.when` 成立时执行 `detonate.ops`（通常清空层数并造成一次性伤害）。
- `target` 语义：`self` = 印记携带者，`enemy` = 其对手，`field` = 场地。

示例（灼烧，占位公式）：`damage = stack * ratio`，`target = 携带者`，`trigger = turnEnd`。

> 各印记真实公式、上限、清除与引爆条件均 `【待校准】`，按数据层 §5.3 格式填写。

## 7. buff / debuff 与状态异常

- buff/debuff 以 `(stat, mode, value, duration)` 表达；`duration` 为剩余回合，回合末在 `settle` 递减，归零移除。
- `mode`：`flat`（固定值）、`percent`（百分比）、`stage`（段数，需换算表）。
- 状态异常（冻结 / 睡眠 / 混乱 …）用 `status` op 施加，命中 / 行动限制规则随状态类型配置；v0.1 实现冻结（禁行动）与睡眠（回合数），其余扩展。
- 叠加与覆盖规则（同名取强 / 刷新回合 / 独立叠加）在 `rules` 或印记/状态定义中声明，默认「同名刷新取较强」。

## 8. 动作细则

### 8.1 换人
- 换人动作先于技能（阶段②）。
- 双方同时换人：**旧场上精灵速度**决定出手顺序；换人本身不消耗技能先后制。
- 换入立即触发 `onSwitchIn` 印记/特性；换出触发 `onSwitchOut` 与下场清除。
- 换人占用本回合行动（不能再出技能）。

### 8.2 愿力魔法
- 每方最多 `rules.wish.maxUses` 次（默认 2），存在 CD（默认 1 回合）。
- 若用于变化技能，附带 `changeSkillFactor`（默认 1.5×）伤害修正。
- 在阶段①宣告与结算。

### 8.3 首领化
- 全局仅一次（`rules.leader.once`），且仅当 `sprite.leaderAllowed`。
- 生效后套用种族提升（提升幅度 `【待校准】`，放 `rules.leader.raceBoost`）。
- 属动作之一，占本回合行动。

### 8.4 防御
- 防御动作为 `actionType=防御` 概念动作（可对应具体防御技能）。
- 减伤 / 免伤倍率 `【待校准】`，进 `rules`。

## 9. 阵亡与终止

- 精灵 HP ≤ 0 → 阵亡，`side.magic -= rules.magic.perFaint`（默认 1）。
- 场上精灵阵亡且背包非空 → 强制换人（阶段④末尾）；背包空且魔力 > 0 也判负。
- 终止：`player.magic == 0` → 我方负；`enemy.magic == 0` → 我方胜。
- 回合上限（如 100）到达 → 判平/按剩余魔力与血量裁决（`rules` 配置，推演中一般提前截断）。

## 10. 接口

```python
@dataclass(frozen=True)
class BattleState: ...

@dataclass(frozen=True)
class Action:
    kind: Literal["skill","defend","switch","wish","leader"]
    skill_id: str | None = None
    bench_id: str | None = None

class Simulator:
    def __init__(self, data: DataBundle): ...
    def legal_actions(self, state: BattleState, side: Side) -> list[Action]: ...
    def step(self, state, player_action, enemy_action, rng) -> StepResult: ...
    def terminal(self, state) -> Terminal | None: ...
    def observe_hidden(self, state, enemy_action) -> BattleState:  # POMDP 揭示
        ...
```

`StepResult = { state, events: list[Event], phase_logs }`。

## 11. POMDP 隐藏信息处理

不可观测项（敌方未登场精灵、敌方剩余能量 / 背包、对手动作）在模拟中按分布采样：

- 敌方动作：由贝叶斯对手模型给出 A/D/S 分布，采样具体动作（见 MCTS 稿）。
- 敌方未登场精灵 / 能量：用「已见集合 + 先验」构造一个**信念状态（belief state）**的采样；采样逻辑独立成 `opponent/belief.py`，可替换。
- UI 明确标注哪些是「已知」、哪些是「推测」。

## 12. 性能

- 纯 TypeScript，同构运行于 Next.js Route Handler 与 Web Worker；热点（伤害 / 印记遍历）保持小对象与就地计算。
- 状态为不可变但采用**浅结构复用**（未变动侧共享对象），降低拷贝成本。
- 可选：阶段 5 用 numpy 或 C 加速；MVP 先保证 1.5s 内千次模拟可用。
- 提供 `benchmarks/` 微基准，跟踪每次 `step` 耗时。

## 13. 验证与真机对拍

- `pytest`：伤害公式（含克制、STAB、暴击、随机区间边界）、印记叠加与结算顺序、换人速度判定、愿力次数/CD、阵亡扣魔力与终止。
- **真机对拍流程**：游戏内构造已知状态 → 记录两侧动作与结果数值 → 用 `/simulate/turn` 复算 → 比对日志 → 校准 `data/rules.json` / 图鉴 `marks` 参数 → 固化回归用例。
- 每个校准后的用例进 `tests/regression/`，防止回退。

## 14. 非目标

- 不追求覆盖全部精灵与技能（按数据增量）。
- 不做真机自动化验证（人工对拍）。
- 不做网络对战 / 联机同步。
