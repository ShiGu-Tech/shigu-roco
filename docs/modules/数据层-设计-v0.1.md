# 数据层 · 设计 v0.1

> 规则执行说明已由《战斗机制扩展层-设计-v0.1》接管。本文中的 `ops` / `markAdd` 等字段描述属于旧版数据迁移记录；当前仓库以 `data/mechanisms.json` 的触发器、条件和效果命令为唯一执行来源，技能 / 印记 / 天气 JSON 不再由旧 `ops` 解释器直接执行。

## 1. 定位与边界

数据层是「改数据不改代码」硬约束的落点：把精灵、技能、印记、天气、属性克制表达为**现查图鉴**（`data/registry/catalogs/`），全局规则 / 养成 / 资产 / 机制表达为 `data/*.json` 参数，由引擎在启动时装配为只读 `DataBundle`。本文记录图鉴归一化前的静态 schema、把自然语言技能效果数据化的**效果 DSL**、校验与维护流程。

不在本文范围：爬虫与文本解析实现（阶段 5）、模拟器如何消费这些数据（见模拟器稿）。

## 2. 设计原则

1. **一切可变数值进 JSON**：种族值、威力、能耗、倍率、上限、系数，代码中不出现魔法数字（除算法常量如 UCB 的 π）。
2. **效果数据化**：技能 / 印记 / 天气的特殊逻辑不写成 `if 技能名 == "引燃"`，而是一组可被解释器执行的 **op**（操作）与 **when**（触发条件）。
3. **未知即告警不崩溃**：加载到引擎不认识的 op / when，记录 warning 并在 `/health` 暴露，模拟时安全跳过，保证「先加数据、后升级代码」。
4. **双系独立结算，规则可配**：属性倍率按「克制 / 抵抗计数」，倍率值（`values`）与封顶（`combine`）随图鉴归一化产出。
5. **人类可校对**：每个实体保留 `rawText`（Wiki 原文片段）与 `source`（来源 URL），方便人工复核与纠错。
6. **MVP 精简**：每份文件带 `"$schemaVersion": "0.1"`；只 `additionalProperties: false` 于核心结构，效果 op 用「基类 + 判别字段」放宽扩展。

## 3. 文件清单与依赖关系

```text
data/
├─ registry/catalogs/   激活图鉴：sprites / skills / marks / weather / elements（现查注册）
├─ rules.json           全局规则参数（魔力、愿力、首领化、结算阶段顺序、伤害系数）
├─ stats.json           养成资质（面板系数、性格表、个体档位先验）
├─ assets.json          静态资源映射（图标等）
└─ mechanisms.json      机制注册（触发器、条件、效果命令）
```

引用完整性：`sprites.skillList` → `skills.id`；`skills.markAdd[].name` → `marks.id`；`skills.specialRules / ops` 中的 mark/weather 引用同理。加载期做一次全量引用校验。

## 4. 效果 DSL

### 4.1 设计动机

Wiki 输出是中文自然语言（如 `引燃 火 状态 敌方获得10层灼烧。能耗2`）。为兼顾「覆盖足够多的机制」与「可维护」，定义一个小而稳的 DSL：**效果 = op 列表；每个 op 有一个 `kind`；条件效果用 `when` 包裹**。

### 4.2 op 词表（v0.1）

| kind | 语义 | 关键字段 |
| --- | --- | --- |
| `stat_mod` | 属性增减 | `target`(self/enemy)、`stat`(atk/def/spatk/spdef/speed)、`mode`(flat/percent/stage)、`value`、`duration`(回合或 null) |
| `damage` | 造成伤害 | `target`、`basis`(power/stack/maxHp/currentHp/flat)、`ratio`、`element?`、`ignoreDef?` |
| `heal` | 回复 | `target`、`basis`(maxHp/currentHp/flat)、`ratio` |
| `add_mark` | 叠加印记 | `target`、`mark`、`stack` |
| `remove_mark` | 移除印记 | `target`、`mark`、`stack`(all/number) |
| `mark_delta` | 印记层数增减 | `target`、`mark`、`delta` |
| `energy` | 能量增减 | `target`、`delta` |
| `magic` | 魔力增减 | `target`、`delta` |
| `status` | 施加异常状态 | `target`、`status`(frozen/sleep/confuse/…)、`turns`、`chance?` |
| `weather` | 改变天气 | `weather`、`turns` |
| `priority` | 先制等级 | `value`（迅捷等） |
| `multi_hit` | 连击 | `times` 或 `timesPerStack` |
| `charge` | 蓄力 | `turns`、`releaseOp` |
| `force_switch` | 强制换人 | `target`、`benchIndex?` |
| `wish_boost` | 愿力魔法增益 | `factor`（对变化技能 1.5×） |
| `heal_from_damage` | 吸血 | `ratio` |
| `conditional` | 条件分支 | `when`、`then`(ops) |

> 覆盖需求文档点名的机制：应对状态 / 应对防御（`conditional` + `when.action`）、蓄力（`charge`）、吸血（`heal_from_damage`）、连击（`multi_hit`）、迅捷（`priority`）、传动（`conditional` + 印记/换人条件）、永久威力变化（`stat_mod` 作用于 `power` 或用 `mark_delta` 建模）。**v0.1 模拟器先实现子集**，其余记录 warning。

### 4.3 when 谓词（v0.1）

| tag | 语义 |
| --- | --- |
| `action` | 对方本回合使用的动作大类：`攻击` / `防御` / `状态`（用于「应对状态」「应对防御」） |
| `firstStrike` | 本回合是否先出手 |
| `hpBelow` | 自身/对方血量比例低于 `ratio` |
| `hasMark` | 目标身上有某印记且层数 ≥ `stack` |
| `element` | 对方系别包含 `value` |
| `weather` | 当前天气为 `value` |
| `stage` | 己方/对方阶位满足比较 |
| `chance` | 概率触发（`probability`） |
| `all` / `any` / `not` | 组合谓词 |

### 4.4 示例：`引燃`

Wiki 原文：`引燃 火 状态 敌方获得10层灼烧。能耗2`

```json
{
  "id": "yinran",
  "skillName": "引燃",
  "element": "火",
  "category": "状态",
  "actionType": "状态",
  "power": 0,
  "cost": 2,
  "hitRate": 100,
  "priority": 0,
  "markAdd": [{ "target": "enemy", "mark": "burn", "stack": 10 }],
  "ops": [
    { "kind": "add_mark", "target": "enemy", "mark": "burn", "stack": 10 }
  ],
  "buffSelf": {},
  "debuffEnemy": {},
  "specialRules": [],
  "rawText": "引燃 火 状态 敌方获得10层灼烧。能耗2",
  "source": "https://.../焰火"
}
```

> `markAdd / buffSelf / debuffEnemy / specialRules` 是需求文档要求的**可读快照字段**；`ops` 是**执行事实源**。阶段 1 二者并存，加载期校验一致性（快照能由 ops 推导），后续可只留 ops + 由脚本生成快照。

## 5. 六份文件 schema

### 5.1 `sprites.json`

```json
{
  "$schemaVersion": "0.1",
  "version": "0.1.0",
  "updatedAt": "2026-09-27",
  "sprites": [
    {
      "no": 6,
      "id": "yanhuo",
      "name": "焰火",
      "stage": 1,
      "elements": ["火"],
      "race": { "hp": 0, "atk": 0, "def": 0, "spatk": 0, "spdef": 0, "speed": 0 },
      "trait": { "name": "", "desc": "", "params": {} },
      "skillList": ["yinran"],
      "leaderAllowed": true,
      "rawText": "",
      "source": ""
    }
  ]
}
```

- `stage`：阶位（1/2/3，或对应进化解锁阶段）。
- `elements`：数组，长度 1 或 2。
- `leaderAllowed`：部分精灵不可首领化（需求 §2.2）。
- **基础资质（race）入库；养成（性格 / 个体值）不入库**，由运行时 `StatProfile` 携带，换算见《数值与伤害模型-设计-v0.1》与 `stats.json`。

### 5.2 `skills.json`

```json
{
  "$schemaVersion": "0.1",
  "version": "0.1.0",
  "updatedAt": "2026-09-27",
  "skills": [
    {
      "id": "yinran",
      "skillName": "引燃",
      "element": "火",
      "category": "状态",
      "actionType": "状态",
      "power": 0,
      "cost": 2,
      "hitRate": 100,
      "priority": 0,
      "markAdd": [],
      "buffSelf": {},
      "debuffEnemy": {},
      "specialRules": [],
      "ops": [],
      "rawText": "",
      "source": ""
    }
  ]
}
```

- `category` ∈ {物攻, 魔攻, 状态, 防御}；`actionType` ∈ {攻击, 防御, 状态}。
- `cost` 为「能耗」；`hitRate` 默认 100。

### 5.3 `marks.json`

```json
{
  "$schemaVersion": "0.1",
  "version": "0.1.0",
  "marks": [
    {
      "id": "burn",
      "name": "灼烧",
      "maxStack": 10,
      "carrier": "sprite",
      "trigger": "turnEnd",
      "ops": [
        { "kind": "damage", "target": "self", "basis": "stack", "ratio": 3, "element": "火" }
      ],
      "clearOnSwitch": false,
      "detonate": null,
      "params": {},
      "rawText": "",
      "source": ""
    }
  ]
}
```

- `carrier` ∈ {sprite（挂在精灵身上）, field（场地）}。
- `trigger` ∈ {turnStart, turnEnd, onHit, onSwitchIn, onSwitchOut, onDamageTaken, onDeath, manual}。
- `defaultStack` 在 `params` 中（初始层数）。
- `detonate`：`{ when: <when>, ops: [ops] }`，用于「引爆」逻辑。
- `ops` 中的 `target: "self"` 指**印记携带者**；`"enemy"` 指其对手；`"field"` 指场地。

> 具体每一种印记（灼烧 / 星陨 / 冻结 / 萌化 …）的叠加上限、结算公式、是否下场清除，均按本文格式调研填写；不确定处标 `【待校准】` 于 `params.note`。

### 5.4 `weather.json`

```json
{
  "$schemaVersion": "0.1",
  "version": "0.1.0",
  "weather": [
    {
      "id": "sunny",
      "name": "烈日",
      "damageMod": { "火": 1.5, "水": 0.5 },
      "defaultTurns": 5,
      "ops": [],
      "rawText": "",
      "source": ""
    }
  ]
}
```

- `damageMod`：按技能系别的伤害乘区。
- `ops`：进入 / 每回合的附加效果（用 DSL）。

### 5.5 `elements.json`

```json
{
  "$schemaVersion": "0.1",
  "version": "0.1.0",
  "elements": ["火", "水", "草", "电", "冰", "地面", "飞行", "..."],
  "matrix": {
    "火": { "草": 2.0, "冰": 2.0, "水": 0.5, "火": 0.5, "地面": 2.0 }
  },
  "combine": {
    "mode": "multiply",
    "clampTo": [0.25, 4.0],
    "overrides": [
      { "attack": "火", "defend": ["草", "水"], "value": 3.0 }
    ],
    "note": "【待校准】双系 ×3 / ×0.25 的叠加规则需游戏实测确认"
  }
}
```

- `matrix[攻击系][防御系]`：未列出的对默认 1.0。
- `combine`：双系合并策略。`multiply` 表示逐系相乘；`overrides` 用于 Wiki 明确写死的组合倍率（如 ×3 / ×0.25）；`clampTo` 封顶。

### 5.6 `rules.json`

```json
{
  "$schemaVersion": "0.1",
  "version": "0.1.0",
  "magic": { "initialPerSide": 3, "perFaint": 1 },
  "wish": { "maxUses": 2, "cooldown": 1, "changeSkillFactor": 1.5 },
  "leader": { "once": true, "raceBoost": { "note": "首领化种族提升幅度【待校准】" } },
  "turnPhases": ["magic", "switch", "skill", "settle"],
  "switchOrderBasis": "oldActive",
  "damageFormula": {
    "kind": "roco_v1",
    "balance": 0.9024390244,
    "stab": 1.25,
    "note": "伤害 = floor((攻 × 战时威力 × 37/41) ÷ 防) × 减伤 × 连击；形态见《数值与伤害模型-设计-v0.1》"
  },
  "combat": { "stageStep": 0.1, "damageReductionCap": 99 },
  "notes": []
}
```

- `turnPhases`：结算阶段顺序（需求 §2.2：魔法 → 换人 → 技能 → 结算），若实测不同只改数组。
- `switchOrderBasis: "oldActive"`：双方同时换人按**旧场上精灵速度**出手（需求 §2.2）。
- `damageFormula` / `combat`：所有系数集中于此，校准 = 改数值；权威定义见《数值与伤害模型-设计-v0.1》。

## 6. 加载与校验流程

```text
启动
 └─ server.getBundle() :
    1. data-node 读引擎参数 JSON（rules 必需；stats / assets / mechanisms 可选）
    2. 读激活图鉴（registry/catalogs/index.json.activeRegistrationId → catalog.json）
    3. 缺激活图鉴 → 直接报错（无静态兜底）
    4. 归一化期已完成引用完整性（skillList / mark / weather）与未知项告警
    5. 产物：只读 DataBundle + warnings + counts
 └─ /health 暴露 dataVersion / counts / warnings
```

- **热重载**：`POST /admin/reload`（仅回环可用）或开发期 `--reload` 重启进程；MCTS 每次推演使用当前 DataBundle 快照，保证一局内配置稳定。
- **性能**：数据量小（数十精灵 / 数百技能），全量预编译为内存对象，运行时不读盘。

## 7. 版本化与维护流程

1. **数据版本**：资源用图鉴 `catalogVersion`，参数用各文件 `version` / `updatedAt`；`dataVersion` 由 `/health` 暴露。
2. **官方更新流程**：
   `roco.world/zh/ → scripts/sync-roco-world.mjs --register（同步并注册，注册即激活）→ 引擎 reload → /api/engine/health 确认 counts/warnings`。
   模拟器与 MCTS 代码**不改**。
3. **schema 演进**：`$schemaVersion` 递增；引擎同时支持相邻版本或提供迁移脚本（阶段 5 视需要）。
4. **回归**：`__tests__/catalog.test.ts` 校验归一化；图鉴变更后经 `/api/engine/health` 确认 counts / warnings。

## 8. 数据采集（已确认来源）

- **来源**：`https://roco.world`（英文，Vite SPA）。每页内嵌 `<script id="roco-bootstrap" type="application/json">`：
  - `catalog.types`：18 属性 + 完整克制矩阵（`effect` ∈ {counter=1, neutral=0, resisted=-1}）→ `elements.json`。
  - `page.data`：`stats`（种族值）、`unit_types`（系别）、`passive_skills`（特性）、`skills`（技能：`energy_cost`/`damage`/`skill_category`/`battle_type_id`/`description`）→ `sprites.json` / `skills.json`。
- **实现（原）**：`engine/roco_engine/ingest/fetch_roco_world.py`，串行限速（默认 0.6s），原始 JSON 存 `engine/ingest/raw/`。⚠️ 该 Python 采集器已随引擎 TS 化下线删除；当前数据人工维护，如需重采集可后续以 TS 重建。
- **技能效果**：由描述启发式解析为 `ops`（应对状态 / 增益 / 印记 / 天气 / 先制 / 连击 / 吸血 / 蓄力），保留 `rawText` 供人工校对；未覆盖的机制留待阶段 5。
- **命名**：源为英文，`name` 存英文；`nameZh` 预留中文字段。
- **礼貌抓取**：限速 + 固定 UA，离线存档，避免重复请求。

## 9. 关键决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 效果表达 | 自定义 op/when DSL | 比硬编码灵活，比通用脚本语言可校验、可静态分析 |
| DSL 与快照并存 | ops 为执行源 + 可读快照字段 | 兼顾可读与可执行，便于人工校对 |
| 属性倍率 | 矩阵 + combine 覆盖 | 吸收 Wiki 明确的 ×3 / ×0.25 特例 |
| 伤害系数 | 全进 `rules.json` | 校准即改配置 |
| 未知项处理 | 告警降级 | 支持「数据先行、代码后补」 |

## 10. 非目标

- 不做运行时远程拉取数据（离线约束）。
- 不做图形化数据编辑器（手工改 JSON + 校验脚本即可；UI 数据浏览为阶段 5 可选）。
- 不追求一步到位覆盖全部印记 / 技能；按 MVP 增量扩充。
