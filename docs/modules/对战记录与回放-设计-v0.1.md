## 1. 定位与边界

对战台（`/`）目前只活在当前标签页里：刷新即失、无法回看。本稿新增 **对战记录与回放**：把一局对战（逐回合的局面快照 + 事件日志 + 胜率走势）**保存在浏览器本地**，并在新的顶级导航页「对战记录」（`/replays`）里**离线回放**。

核心诉求（用户原话）：**回放要基于「当时的记录」，不是最新的技能数据——防止引擎 / 数据升级后把老对局放错。**

边界：

- 只做「记录 → 保存 → 回放」，**不重演**（回放不重新跑引擎、不查最新 catalog）。
- 不改引擎结算；不改对战台现有对战流程（只新增「保存」入口）。
- 数据存 `localStorage`，不上传、不联网（遵守「运行时离线」红线）。
- 不负责分享 / 跨设备同步（见 §8 非目标）。

## 2. 设计原则

- **自包含回放**：一条记录的渲染只依赖记录自身携带的数据（快照 catalog + frames），与当前线上 catalog / 引擎版本无关。
- **存事实，不存推导**：保存的是「当时页面真实显示的 `BattleState` / `BattleEvent` / `TrendPoint`」，不是「动作序列 + 种子」这种需要重算的间接表示。
- **不重演**：回放是**回放录像**，不是**复算对局**。没有 `simulateTurn` 调用，没有随机数，没有版本漂移。
- **按数据版本归档快照**：同一份 catalog 被多局共用，两层存储去重，避免每条记录都塞一份完整图鉴。
- **客户端本地、可失败可降级**：`localStorage` 有配额，写入失败要给出可读提示，不静默丢数据。

## 3. 领域模型

```ts
/** 一帧 = 回合开始前（第 0 帧）或某次结算之后（后续帧）的局面。与对战台 Frame 同构。 */
interface ReplayFrame {
  turn: number;
  state: BattleState;        // 引擎完整状态快照
  log: BattleEvent[];        // 产生该帧的事件（第 0 帧为空）
  history: TrendPoint[];     // 到该帧为止的胜率走势
  terminal: Terminal | null; // 已结束帧携带终局
  label: string;             // 时间线文案（回合 N / 结束 / 阵容阵亡换人 / 首领化）
}

/** 一局记录。 */
interface Replay {
  id: string;             // crypto.randomUUID()
  name: string;           // 用户命名，默认「我方 vs 敌方 · YYYY-MM-DD HH:mm」
  createdAt: number;
  catalogKey: string;     // → ReplayCatalog.key，指向当时的数据快照
  seed: number;           // = state.seed，仅展示用
  playerLabel: string;    // 阵容摘要（精灵名，逗号分隔）
  enemyLabel: string;
  winner: "player" | "enemy" | null;
  reason: string;         // 终局原因
  turns: number;          // 总回合数
  frames: ReplayFrame[];
}

/** 按数据版本归档的 catalog 快照。渲染回放所需的全部图鉴信息。 */
interface ReplayCatalog {
  key: string;            // `${dataVersion}@${dataUpdatedAt}`
  dataVersion: string;
  dataUpdatedAt: string;
  catalog: Catalog;       // 完整 Catalog（sprites / allSkills / statuses / marks / weather / elements / rules / stats）
}
```

存储键（沿用 `modules/battle/storage.ts` 的 `roco.*` 前缀）：

- `roco.replays`：`Replay[]`（最近在前，限额见 §5）。
- `roco.replayCatalogs`：`Record<key, ReplayCatalog>`（按需归档，配额紧张时可回收未被引用的版本）。

## 4. 保存流程（写）

在对战台顶栏新增「保存记录」按钮（`board.tsx` 顶部操作区）：

1. 点击弹出命名对话框（shadcn `Dialog` + `DialogForm`，遵守 UI 约定）。
2. 写入前先从当前 `catalog` 归档一份 `ReplayCatalog`（key 已存在则复用，不重复写）。
3. 把现有 `frames`（含 `state` / `log` / `history` / `terminal` / `label`）序列化为 `Replay.frames`。
4. `unshift` 进 `roco.replays`，超限额从尾部淘汰；`localStorage.setItem` 若抛 `QuotaExceededError`，用 `sonner` 报错并保留旧数据。
5. 成功 `toast.success`，按钮可跳转「对战记录」页。

> 只允许在 `phase === "battle"` 且已有至少一帧时保存；对局结束后同样可保存（终局帧已带 `terminal`）。

## 5. 存储与配额

- **两层去重**：catalog 快照按 `key` 归档一次，多条记录共享；不同数据版本各留一份。
- **限额**：记录最多 `50` 条；单局帧数最多 `200`（超出只保留前 200 帧并标记「早于 N 回合的记录未保存」）。写入前预估体积，超 `localStorage` 配额则提示用户删除旧记录。
- **水合一致**：列表 / 详情一律在 `useEffect` 内读取 `localStorage`，`useState` 初值不读浏览器 API（遵守工作区水合红线）。
- **回收**：删除记录后，若某 `catalogKey` 不再被任何记录引用，一并从 `roco.replayCatalogs` 删除。

## 6. 回放流程（读）

路由与页面：

- 新增顶级导航项 **「对战记录」→ `/replays`**（`components/app-nav.tsx`），与「对战台 / 精灵仓库 / 基础数据 / 复盘」并列。
- `/replays`：
  - **列表态**：卡片列出 `name / createdAt / 双方阵容 / 回合数 / 胜负`，支持重命名、删除（行内二次确认或 `AlertDialog`，禁用原生弹窗）。
  - **回放态**：点开某条记录进入回放。

回放器（新模块 `modules/replays/`，尽量复用对战台组件）：

- 数据源 = `record.frames` + `replayCatalogs[record.catalogKey].catalog`；**绝不调用** `getCatalog()` / Worker / `/api/engine/*`。
- 局面渲染复用 `ActiveBoard`（传入快照 catalog 构造的 `Catalog` 与当前帧 `state`，交互全部 `disabled`）。
- 事件日志复用 `board/log.ts#describeEvent`（传入快照 catalog，名称 / 图标都来自当时数据）。
- 时间线复用 `board/timeline.tsx`；走势复用 `board/trend-chart.tsx`（喂当前帧前的 `history`）。
- 播放控制：`⏮ 上一帧 / ▶ 播放 / ⏸ 暂停 / ⏭ 下一帧 / 速度（0.5×/1×/2×）`；播放用 `setInterval` 逐帧推进 `cursor`，到末帧自停。

响应式：列表卡片与回放面板按 `min-[520px]:` / `min-[860px]:` 三档适配，窄屏纵向堆叠、按钮不溢出。

## 7. 关键决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 持久化位置 | `localStorage` | 离线优先、零后端、与现有 `roco.saves` 一致；用户已确认 |
| 回放表示 | 完整快照 + 事件日志 | 用户明确要求「基于当时记录、防止放错」；不重演即可根除版本漂移 |
| catalog 处理 | 按 `dataVersion` 归档完整 `Catalog` 并去重 | 渲染回放需要 sprites / allSkills / statuses / marks / stats，截取子集易漏字段；整份归档最稳，去重控体积 |
| 是否重演 | 否 | 重演依赖 seed + 动作 + 引擎版本三者对齐，任一升级即放错；录像式回放天然免疫 |
| Tab 位置 | 新增顶级「对战记录」 | 用户已确认；与现有信息架构并列，不挤占「复盘」的手动录入职责 |

## 8. 非目标

- 不做服务端存储、登录态、分享链接、跨设备同步。
- 不做「导出 / 导入录像文件」（可作后续增量，格式预留 `JSON.stringify(Replay + ReplayCatalog)`）。
- 不做对局中自动录制（本稿只提供手动「保存记录」）。
- 不把记录用于 MCTS 训练 / 对手库统计。
