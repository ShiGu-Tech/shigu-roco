# 对局辅助台（Web UI） · 设计 v0.1

> 文档状态：设计 ✅ v0.1 · 代码 ✅ · 验证 ✅ · 生产 ✅（详见 §12 实施状态；后演进为《对战台-设计-v0.2》的实时对局形态）

## 1. 定位与边界

需求文档建议 Streamlit；本项目按用户决定与技术栈对齐，改用 **Next.js 16 + React 19 + Tailwind v4 + shadcn/ui** 实现对局辅助台。职责：**人工录入对局状态 → 触发推演 → 展示结果 → 存档复盘**。

不负责：任何战斗规则 / 概率计算（全在引擎）。

## 2. 页面与路由

| 路由 | 页面 | 阶段 |
| --- | --- | --- |
| `/` | 对局辅助台（主页）：输入面板 + 推演 + 结果面板 + 存档 | MVP |
| `/data` | 数据浏览器：只读查看精灵 / 技能 / 印记 / 天气 / 属性表 | 阶段 5 可选 |

`apps/web/src/app/layout.tsx`：`lang="zh-CN"`，挂载 shadcn `Toaster`。

## 3. 页面结构（`/`）

三段式布局（响应式：`min-[520px]:` / `min-[860px]:`）：

```text

│ 顶栏：数据版本(dataVersion) · 引擎状态灯 · 存档 / 读档 / 重置 │

│ 输入面板（左 / 上）        │ 结果面板（右 / 下）             │
```

## 4. 输入面板规格

- **全局**：双方魔力（数值步进）、天气（下拉，来自 `/catalog`，可设剩余回合）、愿力剩余次数 / CD、首领化是否已用。
- **场上精灵卡片**（我方 / 敌方各一）：
  - 精灵选择（`search-select`，按编号 / 名称 / 系别搜索，数据来自 `/catalog`）。
  - 当前 / 最大血量（自动按种族值 + 运行时参数初算，可手改）、能量。
  - buff / debuff（键值对，`tag-input` 风格）、印记（名称 + 层数，下拉 + 数值）。
- **我方背包**：可增删的精灵卡片列表（简化：精灵 + 血量 + 能量）。
- **敌方已见**：多选精灵集合（POMDP 已知部分）。
- **运行时参数（可选折叠）**：性格、个体值；不填用默认。
- **推演档位**：快速 300ms / 标准 1.5s / 深入 3s；显示将实际发送的 `options`。
- **推演按钮**：调用 `/api/engine/recommend`；进行中禁用并显示 loading。

> 所有下拉 / 印记 / 天气 / 属性数据均来自 `GET /catalog`，前端不硬编码游戏数据。

## 5. 结果面板规格

- **推荐动作榜**：每项展示动作标签、胜率（进度条 + 百分比）、相对最优的差值、访问次数；点击展开「推荐理由」与「若对手如此应对」的简要说明。
- **对手动作概率**：ECharts 柱状 / 饼图展示 `opponent` 分布（A/D/S）；标注来源（先验 / 历史样本数）。
- **推演元信息**：迭代次数、耗时、搜索回合、剪枝动作数、对手建模模式、seed；提供「复现」按钮（用同 seed 再算一次）。
- **置信提示**：当迭代次数过低或数据缺失（未录入精灵）时显示警告条。

## 6. 存档 / 复盘

- 存档 = 完整输入（`BattleState` + options + 对手计数）；存 `localStorage`，键 `roco.saves`。
- 功能：保存当前、另存为、读取、删除、导出 / 导入 JSON 文件。
- 复盘：读档后可直接重推；可选记录每次推演的 `actions` 结果快照（只读历史）。
- 对手模型持久化：`localStorage` 键 `roco.opponentModel`，随请求传入并在响应后更新。
- 前端状态管理：MVP 用 React `useState` + 自定义 hook（`useBattleState` / `useRecommend`）；不引入 Redux。

## 8. 组件与交互约定（对齐参考项目）

- 弹窗统一使用 `DialogBody` / `DialogForm`，禁止原生 `alert` / `confirm` / `prompt`。
- 交互元素优先 `components/ui/*`：`button` / `input` / `select` / `search-select` / `tag-input` / `card` / `tabs` / `progress` / `switch` / `badge`。
- 图表用 ECharts 6，按需注册封装在 `components/charts/echart.tsx`，配色在 `lib/chart-theme.ts`。
- 错误提示用 `sonner` toast。
- 响应式断点 `min-[520px]:` / `min-[860px]:`，手机 / 平板自验。

## 9. 引擎交互与降级

- 所有请求经 `lib/engine-client.ts` → `/api/engine/*`。
- 引擎不可用（502）：页面顶部红条「引擎未启动，请运行 `scripts/dev.ps1`」，推演按钮禁用，其余输入与存档仍可用。
- `/catalog` 失败：下拉为空并提示，不允许提交推演。
- 超时（>30s）：toast 报错，建议降低档位。

## 10. 可用性细节

- 输入校验：血量 ≤ 最大血量、能量非负、印记层数 ≤ 上限（上限来自 catalog）；非法值即时红框。
- 血量最大值的初算：由种族值 + 运行时参数（性格 / 个体）估算，允许手改覆盖（对局中经常需要）。
- 「我的操作」提示：推演只给建议，最终由用户手动在游戏中执行（工具不操作游戏）。
- 空态：未录入任何精灵时展示引导文案。

## 11. 非目标

- 不做对局录像 / 截图识别（需求明确非目标）。
- 不做多用户 / 账号 / 云同步。
- 不做移动端原生 App（Web 响应式即可）。
