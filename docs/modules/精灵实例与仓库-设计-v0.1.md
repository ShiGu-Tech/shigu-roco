# 精灵实例与仓库 · 设计 v0.1

> 文档状态：设计 ✅ v0.1（已确认） · 代码 ✅ · 验证 ✅（`pnpm check` 6 文件 47 项） · 生产 ✅（本机 `/warehouse`）

## 1. 定位与边界

**问题**：图鉴（`data/registry/catalogs/`）里的精灵是**模板（species）**——只有种族值、属性、特性、技能池，是只读的、随版本同步的资源。真实 PvP 打的是**实例**：同一只模板 + 各自的养成（等级 / 星级 / 性格 / 天分 / 出战 4 招）。当前这些信息是 UI 层临时拼出来的（`battle/pet.ts` 的 `PetSetup` 塞进 `ActiveSprite.profile`），不是一等领域概念：仓库、阵容库、对手库各自存碎片，引擎不认识「天分 / 技能选择」，无法复用、无法校验、无法对外暴露。

**本稿定义**：

1. **`PetInstance` 一等领域对象**：一只精灵的个性化副本，只存「选择 + 养成」，不存任何可由模板派生的数值。
2. **外键绑定模板**：实例通过 `spriteId` 引用图鉴模板；面板、技能文本、特性、属性、图片全部**运行时现查**，模板改了（种族值 / 技能 / 名称）实例自动跟着变。
3. **精灵仓库**：一个页面（`/pets`），手动新增 / 编辑 / 删除实例，搜索筛选，供对战台选人。

**边界 / 非目标**见 §9。

## 2. 设计原则

1. **实例存「输入」，不存「结果」**：实例只落 `spriteId / level / stars / nature / talent / skills`。面板、个体值、技能威力等全部由引擎现算（`engine/stats.ts` `computeStats`）——**禁止把面板数值写进实例**，否则模板调整失效。
2. **模板单向依赖**：实例 → 模板是外键引用，模板不知道实例存在。图鉴换版（同步 / 注册）不动实例文件。
3. **改数据不改代码**：面板 / 技能口径仍走 `data/stats.json` + 图鉴；本模块不新增游戏数值。
4. **未知留空、显式标注**：沿用 PvP 情报模式口径——对方实例可只登记 `spriteId`（资质未知，中性 5★·60 占位）。
5. **可校验、可迁移**：实例引用失效（精灵 / 技能被模板移除）时不崩，标记 `issue` 并由 UI 提示重挂。

## 3. 领域模型

新增 `apps/web/src/modules/pets/instance.ts`（前端 + 引擎同构可用的纯类型 / 纯函数）：

```ts
/** 精灵实例：图鉴模板的个性化副本。只存选择与养成，派生值一律现算。 */
export interface PetInstance {
  id: string;              // 实例稳定 id（crypto.randomUUID），跨模板版本不变
  spriteId: string;        // 外键 → 模板（Catalog.sprites[].id / DataBundle.sprites[spriteId]）
  level: number;           // 等级（默认 stats.json.level.default = 60）
  stars: number;           // 星级 0~5
  nature: string | null;   // 性格 id（↔ StatsData.natures[].id）；null = 中性
  talent: TalentMap;       // 天分 1~10，按属性键；≤ individual.investCount 项
  skills: string[];        // 出战 4 招，外键 → 模板技能池 skills[].id
  note?: string;           // 备注（自由文本，不参与结算）
  createdAt: number;
  updatedAt: number;
}
```

> `TalentMap` = `Partial<Record<StatKey, number>>`，沿用 `battle/pet.ts` 定义。

**派生值（不落盘，每次现算）**：

| 派生量 | 来源 | 现算入口 |
| --- | --- | --- |
| 个体值 `iv` | 天分 × (1 + 星级) | `profileFromSetup` 同口径（`battle/pet.ts:45`） |
| 面板 6 项 | 模板 `race` + `profile` | `engine/stats.ts` `computeStats` |
| 技能威力 / 能耗 / 说明 | 模板技能池 | `catalog.allSkills` / `sprite.skills` |
| 特性 / 属性 / 图片 | 模板 | `CatalogSprite` |

**模板绑定（外键）**：

```text
PetInstance.spriteId  ──外键──▶  CatalogSprite（race / trait / elements / skills / image）
PetInstance.skills[]  ──外键──▶  CatalogSkill（power / cost / description / element）
PetInstance.nature    ──外键──▶  StatsData.natures[]
```

**解析函数**（纯函数，前端与引擎共用）：

```ts
export interface ResolvedInstance {
  profile: StatProfile;          // level / stars / nature / iv（喂给引擎）
  loadout: string[];             // 已过滤出合法技能的出战列表（≤4）
  sprite: CatalogSprite | null;  // 模板（缺失 = orphan）
  issues: InstanceIssue[];       // 失效引用 / 超限提示
}
export type InstanceIssue =
  | { kind: "orphan-sprite"; spriteId: string }              // 模板已不存在
  | { kind: "unknown-skill"; skillId: string }               // 技能全库不存在
  | { kind: "skill-not-learnable"; skillId: string }         // 技能不在该模板技能池
  | { kind: "too-many-talents"; count: number }              // 加点项 > investCount
  | { kind: "too-many-skills"; count: number };              // 出战 > 4

export function resolveInstance(catalog: Catalog, instance: PetInstance): ResolvedInstance;
```

`resolveInstance` 是唯一入口：对战台 / 仓库预览 / MCTS 都从这里取 `profile + loadout`，保证「同源」。

## 4. 数据与持久化

- **无数据库**（沿用 AGENTS）：仓库存浏览器 `localStorage`，key `roco.pets`。
- 结构：`{ version: 1, instances: PetInstance[], updatedAt: number }`。
- 读写模块 `apps/web/src/modules/pets/store.ts`：`listPets / getPet / upsertPet / deletePet / importPets / exportPets`。
- **水合一致**：`useState` 初始值不读 `localStorage`，在 effect 内恢复（避免 SSR 不一致）。
- **容量**：一条实例 < 1 KB，数百条无压力；导入导出走 JSON 文本，便于备份 / 迁移。
- **迁移**：现有阵容库 `roco.lineups`（`board/lineups.ts`）里的 `TeamEntry.setup` 在首次进仓库时**导入为实例**（去重按 `spriteId + setup` 指纹）——可选、幂等、不删原数据。

## 5. 接口 / 契约

- **不新增服务端 API**：图鉴经 `GET /api/engine/catalog`（前端已有）就够了；实例是纯本地数据。
- `board/util.ts` 的 `sideFromTeam` / `buildState` 改为：队伍条目从 `TeamEntry` 换为 `{ instanceId: string } | PetInstance`，物化时调 `resolveInstance` 得到 `profile + loadout`，再 `activeFromSprite`。
- 向后兼容：保留接受旧 `TeamEntry.setup` 的路径一段，内部转成临时实例。
- 引擎侧 `StatProfile` / `ActiveSprite` **不改结构**（本模块只改「谁产生 profile」）。

## 7. 模板变更传播（外键语义）

| 模板变更 | 实例表现 | 机制 |
| --- | --- | --- |
| 种族值调整 | 面板 / 血量自动变 | 实例不存面板，`computeStats` 现算 |
| 技能威力 / 能耗 / 说明调整 | 对局数值与文案自动变 | 技能外键现查 `CatalogSkill` |
| 名称 / 图片 / 特性调整 | 自动变 | 模板现查 |
| 技能被移出该精灵技能池 | `issue: skill-not-learnable`，UI 标红；结算按合法子集 | `resolveInstance` 过滤 |
| 技能全库删除 | `issue: unknown-skill` | 同上 |
| 模板（形态）被删除 | `issue: orphan-sprite`，实例保留但不可出战，提示重挂 | `resolveInstance` 返回 `sprite: null` |

关键：**传播是「现查」而非「同步」**——实例文件永远不需要因图鉴换版而重写，只有失效引用需要用户处理。

## 8. 关键决策

1. **实例改成一等对象、仓库独立成页**：对阵 / 存档 / 对手库统一引用 `PetInstance.id`，不再各自存 `PetSetup` 碎片。
2. **持久化用 localStorage**：与「无数据库 / 不联网」定位一致；仓库导出 JSON 作为备份通道。
3. **面板绝不入实例**：从结构上杜绝「写死」，模板调整天然生效（用户明确要求）。
4. **`resolveInstance` 单一物化入口**：前端预览、引擎结算、MCTS 共用，避免两套口径。
5. **失效引用不删实例、只标记**：图鉴换版是常态，静默删数据不可接受。

## 9. 非目标

- 不做服务端账号 / 云同步（无数据库）。
- 不做图片识别 / 自动录入。
- 不做精灵实例之间的「体质 / 亲密度 / 努力值」等洛可不存在的维度。
- 不改 `StatProfile` / `ActiveSprite` / 引擎结算结构（本稿只解决「实例的来源与绑定」）。
- 不自动推断对方实例的真实资质（沿用对手库后验，另稿）。

## 12. 加点自动推荐（机械 v1）

新增实例 / 配置时提供「一键推荐」：由机械规则给出「加哪 3 项 + 天分数值」。规则**先用参数固定**，接口保持 `recommendTalent(catalog, instance)`，**后续由 AI 结合该精灵技能池替换打分来源**（调用点不变）。

**入口**：`apps/web/src/modules/pets/recommend.ts` `recommendTalent(catalog, { spriteId, stars, nature })` → `{ talent, order, scores }`；配置弹窗（`components/pet-config-dialog.tsx`）「三维及加点」标题右侧「一键推荐」按钮调用它。

**阈值参数**（`data/stats.json.talentRecommend`，缺省用代码内置默认）：

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `speedThreshold` | 115 | 速度种族 ≥ 此值 → 加速度项 |
| `hpThreshold` | 100 | 生命种族 ≥ 此值 → 加生命项 |
| `attackThreshold` | 105 | 物攻/魔攻较高者 ≥ 此值 → 加该攻击项 |

**策略（记分 / 模板）**：

1. **性格削弱项一律排除**（`down` 项记 -1000，不入选）。
2. **性格正向（`up`）走角色模板**（取序，排除 `down`，去重，掐前 `individual.investCount` 项）：
   - `speed` → 速度 · 较高攻击 · 生命 ·（物防 / 魔防）
   - `hp` → 生命 · 物防 · 魔防 ·（较高攻击）
   - `atk` / `spatk` → 该攻击 · 速度 · 生命
   - `defense` / `spdef` → 该防 · 生命 · 另一防
   - 「较高攻击」= 物攻/魔攻种族较高者；若其恰为 `down` 则改用另一攻击项。
3. **中性性格走记分**：`速度`/`生命` 命中阈值 +60、较高攻击命中 +50、各项再加 `种族值/10`；按分降序、同分按「生命→速度→物攻→魔攻→物防→魔防」。
4. 选中项天分**拉满**（`RECOMMEND_TALENT_MAX = 10`，与滑条上限一致）。

**性格推荐**（`recommendNature` / `recommendBuild`）：

- 按种族判定角色：`速度 ≥speedThreshold 且 较高攻击 ≥attackThreshold` → **+速度**（速攻）；否则 `较高攻击 ≥attackThreshold` → **+较高攻击**；否则 `生命 ≥hpThreshold` → **+生命**（耐久）；都不满足 → +种族最高项。
- **下降项取「没用的较弱攻击」**（物攻/魔攻中较低者）；若与提升项冲突则退 `spdef`。
- **`recommendBuild` 一键同时给性格 + 加点**：已有明确性格（有 `up`）则**沿用不覆盖**，仅中性 / 未选时按种族自动选（`natureAuto` 标记）。UI「一键推荐」按钮调用它。

**为什么这样**：洛可加点无共享预算、每项独立上限，越高越好，故「选对 3 项 + 拉满」即最优；机械 v1 只解决「选哪 3 项」。占位自述：`data/stats.json.talentRecommend.note`。

**后续（AI 版）**：读该精灵 4 招（物理/魔法比例、速度需求、控制/耐久向）与对局信息，输出同一 `TalentMap`；`recommendTalent` 调用点与 UI 不变，仅替换实现（可加 `recommendTalentAsync` 或策略注入）。
