# MCTS 决策模块 · 设计 v0.1

> 文档状态：设计 ✅ v0.1 · 代码 ✅ · 验证 ✅ · 生产 ✅（详见 §11 实施状态）

## 1. 定位与边界

基于模拟器（MDP 环境），用**蒙特卡洛树搜索**从当前状态向前推演，输出我方每个合法动作的预估获胜概率并排序推荐。**只有我方做搜索**；对手侧用贝叶斯模型采样动作，不展开对手搜索（避免双人博弈搜索过慢）。

不负责：战斗规则（模拟器稿）、输入输出通道（通道稿）、UI 呈现（辅助台稿）。

## 2. 设计原则

1. **搜索模型而非规则脚本**：不硬编码「火系打草系好」之类策略，一切由向前模拟的经验胜率涌现。
2. **无训练、可热换数据**：纯在线搜索，版本更新直接读新 JSON，无需重训。
3. **时间可控**：双停止条件（固定模拟次数 / 最大思考时间），默认 1.5s、最多 1000 次。
4. **可复现**：固定 `seed`；同状态同配置结果一致。
5. **单侧搜索 + 对手建模板**：对手动作按概率采样并在树内以期望回传，不建对手树。
6. **渐进增强**：MVP 用随机 + 启发式估值；神经网络估值列为阶段 5 可选，不阻塞。

## 3. 算法

标准 MCTS 四步，每次迭代：

```text
1. Selection   从根沿 UCB1 选子节点到叶
2. Expansion   叶非终局则扩展一个未试动作
3. Simulation  从新节点向前 rollout 至截断或终局，得回报
4. Backprop    回报沿路径回传，更新 visits / value
```

### 3.1 UCB1

```
UCB = Q/N + C * sqrt( ln(parent.N) / N )
```

- `C`（`rules`/options 中的 `explorationC`，默认 √2 ≈ 1.414），可调。
- `Q` 为节点累计回报（我方视角胜 = 1 / 负 = 0）。
- 未访问节点优先（`N=0 → +∞`）。

### 3.2 对手动作建模

- 攻击阶段：在「我方已选动作」前提下，从对手动作分布 `P_opp(A/D/S)`（贝叶斯模型）采样对手动作。
- **期望回传替代纯随机**：对对手动作用其在分布下的加权期望回报回传（对 3 类动作遍历加权），降低方差。可选纯采样模式以提速，二者由 `options.opponentMode` 控制。
- 对手优势动作排序（速度 / 先制）交给模拟器规则，MCTS 不重复判断。

### 3.3 叶子估值（截断）

rollout 达 `rolloutMaxTurns`（默认 12）仍未终局时，用**启发式估值**返回 [0,1]：

```
value = sigmoid(
    w_magic * (myMagic - enemyMagic)
  + w_hp    * (myHpRatio - enemyHpRatio)
  + w_bench * (myBenchPower - enemyBenchPower)
  + w_marks * (myMarkAdvantage)
)
```

权重在 `data/rules.json` 的 `mctsEval` 段，可校准；默认值给经验初值。

## 4. 动作空间与剪枝

### 4.1 动作派生（我方）

`合法动作 = 模拟器 legal_actions(state, player)`：

- 技能动作：场上精灵可用技能（受能量约束）中各一个，`category/actionType` 区分攻击/防御/状态。
- 换人动作：我方背包每只可上场精灵各一个。
- 愿力魔法 / 首领化：条件满足时各一个。

### 4.2 剪枝（`prune`）

剔除明显劣势动作，减少分支：

1. 能量不足的技能直接不合法（模拟器负责）。
2. 重复效果：同一 (actionType, 目标) 且威力显著更低者，若被严格支配则剪除（保守，仅明显情形）。
3. 换人到「已被对方克制且我方无收益」的精灵：可选剪枝（默认关闭，避免误剪）。
4. 剪枝数与理由在响应 `meta.prunedActions` 与 `reasons` 中透出，保证可解释。

> 原则：剪枝宁可保守；被剪动作若用户手动指定，应能单独 `/simulate/turn` 复算验证。

## 5. 停止条件与预算

| 条件 | 默认 | 说明 |
| --- | --- | --- |
| 最大迭代次数 | 1000 | `options.maxIterations` |
| 最大思考时间 | 1500 ms | `options.timeLimitMs`（普通笔记本档位） |

两者取先到。UI 提供档位（快速 300ms / 标准 1.5s / 深入 3s），并显示实际迭代数与耗时。

## 6. 贝叶斯对手模型

### 6.1 模型

对每个可观测的「对手场上精灵（或对手标识）」，维护对手三类动作 `{A 攻击, D 防御, S 状态}` 的计数，用 Dirichlet–Multinomial 共轭：

```
先验 Dirichlet(αA, αD, αS)，默认 α = (1,1,1)（或按精灵特性给偏置先验）
后验期望 P(A|data) = (αA + nA) / (Σα + n)
```

- 每次观察到对手动作（含对手换人可并入分类或单列 `W`）→ `n` 加一。
- 观察来源：用户在对局中输入、或历史复盘导入；持久化在**前端 localStorage**，随请求传入。
- 引擎保持无状态：`options.opponentModel` 传入计数，响应回传后验。

### 6.2 冷启动

无历史时用先验：`(1,1,1)` 或按敌方精灵样本偏置（如高攻精灵偏 A）。先验表放 `data/rules.json` `opponentPrior`，可扩展。

## 7. 输出契约

```json
{
  "actions": [
    { "action": { "kind": "skill", "skillId": "yinran" }, "label": "引燃",
      "winRate": 0.63, "visits": 412, "score": 0.63,
      "reasons": ["推演中灼烧持续压制", "能耗可承受", "对手防御倾向低"] }
  ],
  "opponent": { "A": 0.5, "D": 0.17, "S": 0.33 },
  "meta": { "iterations": 1000, "elapsedMs": 1420, "searchedTurns": 12,
            "prunedActions": 1, "opponentMode": "expectimax", "seed": 42 }
}
```

- 排序：按 `winRate` 降序；并列按 `visits` 降序。
- `reasons` 为**模板化解释**（非 LLM）：由贡献最大的一条 rollout 路径特征生成（如「命中后印记层数压制」「规避被克制」），保证离线与可复现。

## 8. 性能优化路线

1. 动作剪枝（§4.2）。
2. 路径截断 + 启发式估值（§3.3）。
3. 状态浅拷贝复用（模拟器稿 §12）。
4. 对手动作期望加权替代多重采样（§3.2）。
5. 并行：MVP 单线程；阶段 5 可多进程并行 rollout（注意随机种子独立性）。
6. 阶段 5 可选：NN 估值替代 rollout（需训练，列为非核心）。

## 9. 参数与调优

- UCB 的 `C`：负载 / 对局阶段敏感，暴露为档位（默认 1.414）。
- `rolloutMaxTurns`：越大越准越慢；默认 12。
- 对手先验 α：影响冷启动偏向。
- 估值权重 `w_*`：影响截断回报。
- 调优方法：构造少量「人工已知应推荐某动作」的局面，做参数回归（`tests/mcts_cases.py`）。

## 10. 非目标

- 不训练神经网络（阶段 5 可选）。
- 不做双人博弈 MCTS / CFR。
- 不保证全局最优，只保证「在当前模拟器与数据下的近似最优」。
