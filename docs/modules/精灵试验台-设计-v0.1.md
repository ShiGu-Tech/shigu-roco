# 精灵试验台（PVP 1v1 实时设置 · 资质反推）· 设计 v0.1

> 文档状态：设计 ✅ v0.1 · 代码 ✅ · 验证 ✅（纯函数回归 2 项 + 本地 26900 宽 / 窄屏冒烟）· 生产 🟡（随下次构建发布）

## 1. 定位与边界

一个专用的 **1v1 实验 / 验证页**（`/lab`），用于「**手动摆状态 → 引擎实时给伤害 / 血量 → 从观测反推资质**」的闭环：

- 双方各先选 **1 只**精灵上场，可**随时「加精灵」**（不设上限）；中途**换精灵**只改试验台局面，不占回合。
- 你**实时设置**双方的当前局面：出战技能、增益 / 减益（buff / debuff）、印记、状态、计数器、天气、能耗修正、冷却、血量、能量。
- 引擎**即时**反馈：面板数值（引擎现算）、伤害、剩余血量、能量、逐条结算日志。
- 支持**逐回合结算**（双方各选一个动作跑一次真实结算），也可**随时直接改任意字段**再看结果。
- 你每记录一次观测（造成伤害 / 血条剩余% / 先后手），试验台**持续反推**对方精灵的**性格 + 天分**，收敛为候选 + 置信，可人工确认。
- 目标：把「**反推资质**」练成能力，为后续 **6v6** 情报模式打地基。

**红线不变**（见根 `AGENTS.md`）：非外挂、离线、人工录入；不读画面 / 内存 / 抓包 / 自动操作。本稿是**站内前台 + 引擎现算**，不新增任何外部数据源。

**边界**：

- 不是对战台的替代：对战台是「明牌沙盒 + MCTS 推演」，试验台是「自由摆状态 + 观测反推」。
- 不是《真实对战模式》的替代：那稿把情报层做进对战台；本稿把它独立成可反复试的实验页。
- **不改引擎**：全部复用 `Simulator` / `legalActions` / `engine/calc.ts` 的反解原语，不新增游戏机制。

## 2. 设计原则

1. **状态即真相**：所有面板一律由引擎 `computeStats` 现算，前端不另写公式（同 PvP 情报模式）。
2. **自由摆 + 回合跑双轨**：既能直接改任意字段立即看数，也能按标准回合双方出招结算；两条路共用同一份引擎状态。
3. **观测只来自可观测事实**：反推只吃「伤害 / 血条% / 先后手」这类你在对局里看到的事实，不靠猜、不读画面。
4. **未知不当已知**：对方资质默认 `unknown`，引擎侧按中性 **5★ · 60 级 · 天分 0** 占位，UI 明标「未知 / 推测 / 已确认」三级。
5. **手标优先**：人工确认的字段覆盖自动推断，并在卡片标注来源（推测 / 手标）。
6. **复用优先**：不造第二套面板 / 状态编辑器；沿用 `board/util`、`board/log`、`battle/client`、现有 UI 组件与既有推断函数。

## 3. 领域模型

试验台 = ①**花名册**（配置层，双方各一组，可增删换）+ ②**局面**（引擎 `BattleState`，真值）+ ③**情报档案**（对方每只的未知 / 推测 / 已确认）。

### 3.1 花名册（配置层）

```ts
type BenchRole = "self" | "opp";

interface BenchPet {
  /** 本局稳定实例 id：情报 / 观测绑在它上面，换下再上场仍记住，同队同种不串。 */
  instanceId: string;
  spriteId: string;
  /** 我方（self）直接编辑；对方（opp）可由未知 / 推测 / 已确认回填。 */
  setup: PetSetup;
}

interface BenchSide {
  pets: BenchPet[];      // 起始 1 只，可「加精灵」，无上限
  activeIndex: number;   // 当前上场
}
```

- 换算沿用 `battle/pet.ts#profileFromSetup`（个体值 = 天分 ×（1 + 星级））；**星级 / 等级固定 5★ / 60**（本稿约束，不做推断）。
- 局面由花名册构建：`buildState(catalog, self.pets, opp.pets)`；换人 / 加精灵只重建 active + bench，尽量保留已录 HP / 能量（按 `instanceId` 对齐）。

### 3.2 局面（引擎真值 `BattleState`）

直接沿用 `apps/web/src/modules/battle/types.ts` 的 `BattleState` / `SideState` / `ActiveSpriteState`，试验台在其上加「**可编辑投影**」：

| 可编辑字段 | 位置 | 用途 |
| --- | --- | --- |
| `hp` / `maxHp` / `energy` | active | 血量、能量直接设 |
| `loadout` | active | 出战 4 招（技能） |
| `buffs` / `debuffs` | active | 增益 / 减益层数（当前回合 buff） |
| `marks` | active | 印记层数 |
| `statuses` | active | 状态层数 |
| `cooldowns` | active | 冷却 |
| `skillMods` / `costMods` | active | 技能 / 能耗修正 |
| `profile` | active | 性格 + 个体值（面板现算来源） |
| `weather` | state | 天气 + 剩余回合 |
| `bench` / `active` | side | 上场精灵与场下 |

> 这里的「特性」按你的澄清 = **当前回合的 buff / 印记 / 状态等局面修正**；精灵**物种特性**由图鉴 `sprite.trait` + `mechanisms.json` 自动参与，试验台只读展示（见 §8 非目标）。

### 3.3 情报档案（对方每只）

复用 `board/intel.ts` 的三级结构，扩展为带**反推候选**：

```ts
type IntelLevel = "unknown" | "inferred" | "known";

interface BenchIntel {
  instanceId: string;
  spriteId: string;
  skills: { id: string; turn: number }[];         // 已见技能（按首次使用顺序）
  nature:  { level: IntelLevel; value: string | null; candidates?: { id: string; p: number }[] };
  talent:  { level: IntelLevel; value: TalentMap;      candidates?: { talent: TalentMap; p: number }[] };
  bloodline: { level: IntelLevel; value: string | null };   // 手动标识为主
  observations: Observation[];
}

interface Observation {
  turn: number;
  kind: "damage" | "hp" | "speed";
  attackerSkillId?: string;   // 我方用于攻击的技能（伤害观测）
  damage?: number;            // 实测伤害（单段）
  remainPct?: number;         // 目标血条剩余 %
  speedFirst?: "self" | "opp"; // 先手归属（速度观测）
}
```

- 观测能力直接调用既有原语：`engine/calc.ts#inferDefense`（伤害→守方防御区间）、`inferMaxHpRange`（伤害 + 血条%→最大 HP 区间）、`inferBuild`（种族 + 目标面板区间 → 枚举「性格 × 天分」组合）。
- **反推收敛策略**（同《真实对战模式》§4.2）：先按「**推荐加点**」（3 项各满 +10，`stats.json.talentRecommend`）在「选哪 3 项 × 性格」里搜；未命中再放宽到「任意 ≤3 项、0~10」兜底，标「非典型加点」。固定 `stars:[5]`、`level:60`。
- 多次观测取交集并按似然打分排序，概率过阈值或人工点「确认」→ `known`。

## 4. 数据 / 接口

- **无新增服务端接口、无数据库**：沿用 `POST /api/engine/simulate/turn`（或 Worker `simulate/turn`）、`/simulate/legal`、`/simulate/forced-switch`；反推为纯函数（`engine/calc.ts`），在浏览器现算。
- 持久化：`localStorage`（实验存档 + 对方情报），沿用 `battle/storage.ts` 风格；键形如 `roco.lab` / `roco.labIntel`。
- 无外部数据源；资源与机制仍来自现查图鉴 + `data/*.json`。

## 5. 路由与页面

- 路由：`apps/web/src/app/lab/page.tsx` → `<PetLab />`（新模块 `apps/web/src/modules/lab/`）。
- 导航：`app-nav.tsx` 增一项「**试验台**」（`/lab`），排在「对战台」之后。
- 页面布局（PC 三列，窄屏折单列，断点 `min-[520px]:` / `min-[860px]:`）：

```text
┌ 顶部：花名册（双方各一组，加精灵 / 上场 / 删除；每只可展开设性格+天分+技能） ┐
├ 左：我方场面卡          ├ 中：结算 + 走势 + 日志      ├ 右：对方场面卡 + 情报卡 ┤
│  面板雷达 / 六项现算      │  双方选动作 → 结算          │  面板现算（未知标注）     │
│  HP / 能量 / buff / 印记  │  伤害 / 血量反馈           │  已见技能 / 三级情报      │
│  状态 / 天气 / 冷却      │  帧时间线（可回退）         │  「录观测 → 反推资质」入口 │
└──────────────────────────┴────────────────────────────┴────────────────────────┘
```

- 关键交互：
  - **加精灵**：选精灵 → 追加到该侧花名册；**上场**：点场下头像即切（保留 HP）；**删除**：行内二次确认。
  - **实时改字段**：左右场面卡上的 buff / 印记 / 状态 / 天气 / 冷却 / 技能修正等直接编辑，改完立即用引擎现算面板与预览。
  - **结算一回合**：双方各选动作（`legalActions` 驱动，含技能 / 换人 / 聚能 / 愿力 / 魔法）→ `simulate/turn` → 事件行按 `board/log.ts` 三列（分类 · 来源 · 结果）展示伤害 / 血量 / 状态变化；生成帧，可回退到某回合前。
  - **录观测 → 反推**：在伤害 / 血量事件行上「一键纠错」（改实测伤害或血条%）或情报卡手动录；引擎即刻更新对方 `nature` / `talent` 候选与置信。
  - **手标**：情报卡逐项标记（性格矩阵 / 天分 ≤3 项 / 血脉 / 已见技能）→ 置 `known` 并即时反映到结算。

- 复用组件：`Panel` / `PageHeader` / `components/ui/*`（`DialogBody` / `DialogForm` / `HoverCard` / `sonner`）、`board/pet-setup.tsx` 的编辑器、`board/stat-radar.tsx`、`board/log.ts`、`board/intel-mark-dialog.tsx`（改造接入 `instanceId`）、`board/timeline.tsx`。

## 6. 关键决策

1. **独立页 `/lab`**：不复用对战台、不改《真实对战模式》的既成范围；试验台是「可反复试、以反推为目的」的实验场。
2. **引擎不新增游戏机制**：`Simulator` + `calc.ts` 反解原语已足够；仅在 catalog 只读响应补属性克制矩阵（§9），不在引擎写具体内容（守红线）。
3. **固定 5★ · 60 级**：本稿按你的口径固定，只反推**性格 + 天分**；**血脉手动标识**；星级 / 等级暂不做推断（6v6 若有需要另开）。
4. **花名册无上限 + `instanceId` 稳定**：换人 / 加精灵不丢观测；同队同种不串——直接为 6v6 的「实例级情报」铺路。
5. **自由摆状态优先**：不同于对战台「仅靠回合动作推进」，试验台允许直接改任意局面字段（这正是「验证实时设置功能」的核心价值）。
6. **三级情报 + 手标优先**：与《真实对战模式》口径一致，避免把猜测当事实。
7. **全部本地**：localStorage 持久化，符合「离线、单人、无数据库」定位。
8. **未知占位 5★·60·天分 0**：只为让引擎能结算，UI 明标未知；一旦有观测 / 手标即回填。

## 7. 非目标

- 不读游戏画面 / 内存 / 抓包 / 自动操作；不做图片识别或自动录入（红线）。
- 不接神经网络估值；反推用封闭区间枚举 + 对数似然，不追唯一解。
- 不做物种特**性**的手动覆盖 / 强制激活（物种特性仍由图鉴自动参与）；「特性」在本稿特指局面 buff / 印记 / 状态。
- 不做联机 / 观战房间（那是 `/watch` 与《引擎观战》）。
- 不在引擎写入任何具体精灵 / 技能 / 机制名或站点字段。
- 暂不做星级 / 等级的反推（固定值）。

- ✅ 设计 v0.1（本稿）。
- ✅ **L0 路由与花名册**：`/lab`（`app/lab/page.tsx`）+ 导航「试验台」；双方各起始 1 只，「加精灵 / 上场 / 删除」，`id` 稳定（`modules/lab/lab.tsx`）。
- ✅ **L1 实时状态编辑**：**HP 按百分比**（滑条 + 数值，自动换算绝对值）/ 最大 HP / 能量 / **属性增益·减益**（选「属性 + 升/降 + %」加入 chip，增益存正、减益存负）/ 印记 / 状态 / 计数器（`modules/lab/state-editor.tsx`）；**出战技能卡内直接选择**（4 槽 → `SkillSelector`，直接改 `loadout`）；性格 / 天分 / 血脉走 `PetConfigDialog`；天气在中栏统一切换；面板（六项 + 雷达）由引擎 `computeStats` 现算。
- ✅ **L2 回合结算**：双方「选动作」弹窗（默认列出 `deriveActions` 结果，另可**从全部技能选**——含防御 / 应对 / 任意技能）→ `simulate/turn` → 事件按 `board/log.ts` 三列渲染。**回合以「动作对」记录**（我方 X ⚔ 对方 Y，含应对标记），日志分「回合动作 + 事件明细」两段；**应对由引擎按双方动作类型自动判定**（`actionDeclared` + `reacted`），无需单独录入。帧时间线可回退；`Ctrl / Cmd + Enter` 结算快捷键。
- ✅ **L3 交互记录与资质反推（双方对称）**（`modules/lab/types.ts` 的 `Interaction` + `infer.{ts}` + `intel-panel.tsx`）：**我方 / 对方资质均默认未知**。事实统一记成**交互记录** `Interaction`（**我方技能 ⚔ 对方技能 + 可选结果**），不再挂到单只身上。来源两条：① 结算自动记一条（双方动作）；② 手动「新增交互」选双方技能 → **登记结果**（受击方 + 实测伤害 + 掉血% / 剩余%）。反推时按「受击方」从交互记录取观测（进攻方技能 = 对侧技能、受击方技能 = 本侧技能）。伤害 / **本次掉血%**（非剩余%，与历史无关）/ 先后手 → `inferDefense` / `inferMaxHpRange` / `inferBuild`（固定 **5★ · 60**，先「推荐加点 3 项满」再放宽）→ 性格 / 天分候选 + 概率 + 防御 / 最大 HP 区间；血脉手标；三级 + 手标优先，手标同时回填该侧 setup 生效。**鲁棒性**：伤害 / 血量区间带容差（吸收 floor 与未计入的天气 / 特性 / 减伤 / 连击倍率），受击方防御 / 应对时标近似，无解时逐步放宽区间拟合，只有区间倒挂才报「矛盾」。**引擎校正（关键）**：每条交互登记后**自动**按双方技能跑引擎（含受击方减伤 / 特性，如冰墙 `sk-7090210` 承伤 −80%），用「伤害 ∝ 1/防御」校正目标防御（目标防御 = 当前防御 × 引擎伤害 / 实测伤害），再枚举「性格 × 天分」并按与实测伤害吻合度排序，情报卡给出「**最吻合组合**（性格 · 天分 → 预测伤害）」——**避免把减伤误算成虚高防御**；未跑引擎时才退回闭式（会标近似）。
- ✅ **UI（按「设置状态 → 结算 → 反推并记录」三步流重排）**：
  - **① 状态**：左右两列精灵卡（头像 + HP 条 / 数值 + 六项面板 + **物种特性**（名称 + 说明）+ 场下头像一键换人 + 加精灵 / 配置资质 / 删除上场），卡片头挂「选动作」；卡上「设置状态 / 技能」开全局弹窗，「**情报 / 观测**」开该只的情报弹窗。技能选择统一走**可搜索**的 `SkillSelector`（交互表单的双方技能、动作选择、出战技能均复用）。
