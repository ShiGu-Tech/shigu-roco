# 真实对战模式（未知情报 · 逐步揭露）· 设计 v0.1

> 文档状态：设计 ✅ v0.1 · 代码 ⬜ · 验证 ⬜ · 生产 ⬜

## 1. 定位与边界

对战台现在本质是**明牌沙盒**：双方配置都当已知。已经有的《PvP情报模式》退了一步——对方只登记精灵，技能未知、资质按中性占位，对局中用「换」手记对方招式。

本稿再进一步，做**真实对战模式**：

- 开局**只选对方的 6 只精灵**；对方的 **技能 / 性格 / 天分 / 血脉 / 魔法** 一律**未知**。
- 这些未知项在对局中**逐步揭露**，沉淀成每只对手的**情报档案**，跨局累积（对手库）。
- 仍是**离线人工录入**：所有「观测」来自你从游戏画面看到的事实（对方用了什么招、打出多少血、血条剩多少），工具不读画面、不自动操作（红线不变）。

与现有 PvP 模式的区别：现有版把对方技能记为「已用」，但**不沉淀、不推断、不区分等级**；本稿把「经验」做成结构化的「未知 / 推测 / 已确认」三级情报。

## 2. 设计原则

1. **未知不被当成已知**：未观测到的字段一律 `unknown`，引擎侧仍用中性 5★·60 级占位但 UI 明写「未知」。
2. **揭露只来自可观测事实**：对方实际使用的技能、造成的伤害 / 血量、其能力的触发——不读画面、不靠猜。
3. **三级情报**：`unknown`（未知）/ `inferred`（有候选 + 概率）/ `known`（高置信或用户手动确认）。
4. **工具只记录与推断，不改变事实**：推断永远标「推测」，人工确认可覆盖为 `known`。
5. **复用对战台**：不新开页面；沿用 `SkillGrid` / 对手库 / 引擎后验，只加情报层与露馅日志。

## 3. 领域模型

每只对手精灵一条**情报档案**（`OpponentIntel`）：

```ts
type IntelLevel = "unknown" | "inferred" | "known";
type StatKey = "hp" | "atk" | "spatk" | "defense" | "spdef" | "speed";

interface Observation {
  turn: number;
  kind: "skill" | "damage" | "hp" | "speed" | "entry" | "magic";
  /** 攻击方技能（伤害观测用）。 */
  skillId?: string;
  damage?: number;
  /** 目标血条剩余百分比（0~100，伤害观测用）。 */
  remainPct?: number;
  sourceSpriteId?: string; // 观测者（我方精灵）
}

interface OpponentIntel {
  /** 本局「临时精灵」实例 id（开局给对手 6 只各分配，稳定不随换人变）。 */
  instanceId: string;
  spriteId: string;
  level: number;            // 固定 60
  stars: number;            // 固定 5
  skills: { id: string; usedAtTurn: number }[];          // 已见技能（按使用顺序）
  nature: { value: string | null; level: IntelLevel; candidates?: { id: string; p: number }[] };
  talent: { value: Partial<Record<StatKey, number>>; level: IntelLevel };
  bloodline: { value: string | null; level: IntelLevel };
  magic: { wish: boolean; leader: boolean; element?: string };   // 愿力冲击 / 首领化 / 系魔法
  /** 随机技能 / 巧变 / 随机习得的**实际结果**（你在游戏里看到的，二次选择后记下）。 */
  randomResults: { turn: number; sourceSkillId: string; becameSkillId: string }[];
  observations: Observation[];
}
```

- **绑定「本局临时精灵」而非物种**：开局给对手 6 只各分配一个 `instanceId`，情报挂在实例上——**它换下再上场（切人）仍记住**；同队两只同种精灵也互不串。
- **两级档案**：① 本局实例档案（`instanceId`，随对局快照存/回放）；② 跨局物种档案（按 `spriteId` 汇总进 `roco.opponentLibrary`，本局结束后合并）。
- 未知项在引擎侧仍是「中性 5★·60·天分 0」占位；`inferred`／`known` 时用其值接面板。

## 4. 逐步揭露规则

| 维度 | 初始 | 揭露方式 | 触发源 |
| --- | --- | --- | --- |
| 精灵 | 已知（你选） | — | — |
| 出战技能 | unknown | 对方**实际使用**某技能 → 加入「已见」 | 对局里录入的对方动作 |
| 性格 / 天分 | unknown | 由**伤害 / 血量**观测反推（区间 + 贝叶斯） | `inferDefense` / `inferMaxHpRange` / `inferBuild`（5★ · L60 · ≤3 项天分） |
| 血脉 | unknown | 其**能力触发**（入场 / 增伤 / 受击等）→ 推断 | 引擎机制事件 + 人工确认 |
| 魔法 | unknown | 对方使用**愿力冲击 / 首领化 / 系魔法** → 置位 | 对局里录入的对方动作 |
| 随机技能 / 巧变 / 随机习得 | unknown | 技能触发后**二次选择它实际变成了什么** → 记入 `randomResults` | 引擎随机结果 + 你在画面的观测 |
| 能量 / 魔力 / 血条 / 状态 / 印记 / 天气 | 可见 | 人工录入 | 画面 |

- **技能**：对方从「全技能列表」里选它实际放的招 → 记入 `skills` 且当回合照常结算；已是「已见」的技能优先展示（不再每次翻全集）。
- **资质**：录一次「我方技能 + 造成伤害 + 剩余血量%」→ `inferDefense`+`inferMaxHpRange`→`inferBuild` 出候选性格 / 天分；多次观测取交集 / 贝叶斯后验，概率 > 阈值或人工点「确认」→ `known`。
- **血脉 / 魔法**：由观测到的事实置位，UI 从「未知」变「已见」。

### 4.1 实时标记（人工，对局进行中）

对局中你边看边给对手**打标**，是这套情报的主要来源，两条路径：

1. **动作即标记（自动）**：每回合选对方动作时，你从技能表里选它**实际放的招** → 引擎结算的同时，该技能自动进「已见技能」；再次遇到同一技能时优先出现在候选里（不必翻全集）。
2. **情报卡上的标记按钮（手动）**：在敌方情报卡上直接打标，变化即时反映到对局面板与引擎：
   - **技能**：多选 / 追加它已用过的招；
   - **性格 / 天分**：从性格矩阵点选、给天分项打勾与数值（1~10，≤3 项）→ 置 `known`；
   - **血脉**：选/确认（若画面可辨）；
   - **魔法**：勾「愿力冲击 / 首领化 / 系魔法」是否已见；
   - **观测**（伤害 / 血量）：录数值 → 走推断置 `inferred`。

约束：

- 标记只改变**情报档案**，不改变对局状态本身（血量 / 能量等仍靠正常录入）。
- 推断项与人工项冲突时**人工优先**（`known` 覆盖 `inferred`），并在情报卡上标注来源（推测 / 手标）。
- 标记随对局快照存 / 回放；跨局按 `spriteId` 汇总进对手库。

### 4.2 资质反推策略：先「推荐加点」

对手大概率是**推荐加点**（`modules/pets/recommend.ts` / `stats.json.talentRecommend`）：**3 项天分各 +10、其余 0**。所以反推**不暴力枚举全部组合**：

1. 先在「**选哪 3 项 × 性格**」里搜（3 项固定满 +10）——候选空间从「全枚举」缩到很小的规模；
2. 用观测（物防/魔防区间、HP 区间）对这些候选打分排序，给概率；
3. 若**没有**「3 项满」候选落在区间内（对手没满练 / 非典型），再**放宽**到「任意 ≤3 项、0~10」全枚举兜底，标「非典型加点」。

既快又准，贴合真实对手。

### 4.3 魔法（草魔法等）

「魔法」是双方战前各带的一种，对方未知；对局中它释放/触发即揭露。已确认的一个：

- **草魔法**：释放后**每回合回 15% 生命、持续 3 回合**；**不绑定精灵**（按方），中途换人则**给当前的精灵回血**；**优先级最高——回合开始先回血，再结算行动**。
- 已知另两种是 `愿力冲击`（wish）与 `首领化`（leader），引擎已有；其余系魔法待补。

实现要点：按**方**挂一个 3 回合的回复状态（`turnsLeft`），`turnStart` 结算时对当前 `active` 回 `0.15 × maxHp`，早于任何行动；换人不影响剩余回合、不加也不减。

## 6. 路由与页面

- `/` 对战台：对手开局**只选 6 只精灵**（现状已如此）。
- 敌方面板改「**情报卡**」：每只显示
  - 已见技能（按使用顺序，未知标灰）；
  - 性格 / 天分：`未知` / `推测 ↑X↓Y · 天分 {…}（置信 62%）` / `已确认`；
  - 血脉 / 魔法：`未知` / `已见`；
  - 一行「反推资质」入口（录伤害 / 血量观测）。
- 「**露馅日志**」：本局按回合记「第 N 回合：蓝方 · 鳗尾兽 使用了『泥浆』（已记入情报）」「你方 X 技能对其造成 115 → 反推物防 [a,b]」。
- 对手库页：按精灵汇总已见技能 / 资质后验，可手动确认。

## 7. 关键决策

1. **做进对战台**，不新开页面（沿用现有 PvP 模式开关）。
2. **揭露 = 记录 + 推断**，来源限「可观测事实」；不做画面识别。
3. **资质用「区间 + 候选概率」**，不追唯一解；人工确认优先。
4. **未知不假设**：对手默认中性 5★·60·天分 0，仅用于让引擎能结算，UI 明标未知。
5. **档案跨局累积**（对手库），本局状态随对局快照存 / 回放。

## 8. 非目标

- 不读游戏画面 / 内存 / 抓包 / 自动操作（红线）。
- 不做神经网络估值；推断用封闭区间枚举 + 贝叶斯。
- 不保证唯一推断出性格 / 天分（单次观测常多解）。

## 10. 交互设计：怎么「问」才不烦人

核心原则：**默认零输入也能玩；引擎先给猜测，你只纠正差异；任何一步可跳过、可后补、可撤销。**

### 11.1 三层交互（从轻到重，按需）

1. **动作即录入（必做，但本来就要点）**：每回合选对方实际放的招。这不是额外负担——你本来就要告诉他这回合对方出什么。让「选招」顺带把该技能记入「已见」。可选择「跳过 / 用推测」，引擎继续。

2. **结算后一键纠错（默认，可忽略）**：结算后引擎把**它算出来的**摆在事件行上，只在你发现不符时才动：
   - `敌方受到 115 伤害` → 与实际不符？点数字改成实测值（或改「血条剩 %」）。
   - `先手：红方` → 实际蓝方先手？点一下切换（用于反推速度）。
   - `敌方技能：泥浆` → 实际别的？点选换成实际技能（自动进已见）。
   - `巧变 / 随机习得 触发了` → 弹「**变成了什么？**」的二次选择（你游戏里看到的结果），可跳过（跳过就用引擎的随机结果）。
   - 一律有个极小、不挡路的「纠正」入口；不点就按引擎的走。

3. **情报侧栏随手标（随时可开）**：敌方情报卡常驻，逐项显示 `未知 / 推测 / 已确认`；想标哪项点哪项（技能多选、性格矩阵、天分勾项、血脉、魔法），不标不影响任何流程。

### 11.2 「丰富度」档位（避免一直被打断）

- **静默**：只记录与自动推断，从不主动问。
- **轻（默认）**：仅在「结算结果可能不符」时给一个可忽略的小提示（伤害 / 先手 / 敌方技能）。
- **向导**：想精算的玩家，每回合系统化地走一遍（技能 → 伤害/血量 → 先手）。

### 11.3 该问什么、不该问什么

- **问**（引擎无法自动知道、且高收益）：对方实际用的招（尤其新招）、准确的伤害值或血条%、先手是否异常。
- **不问**（能从别的推 / 能自动算）：
  - 先手 → 默认按面板速度算，异常才纠；
  - 伤害与血条% → 二者**取一即可**，工具自动互换（有我方攻方面板 + 技能即可从伤害反推防御，从血条%反推 maxHp）；
  - 性格 / 天分 → **不要直接问**，让工具从观测反推给候选，最多让你点「确认」。

### 11.4 空值语义与可逆性

- **不填 = 保持当前推测**（`inferred` 或中性占位），事件行标「推测」，对局照常继续。
- 任何标记可**撤销**；补填后**立即重算**当前推荐与后续（无需重开）。
- 推断项与手标项冲突时**手标优先**，并标注来源「手标 / 推测」，避免把猜测当事实。

### 11.5 一句话

把「工具问你」变成「**工具先猜、你纠正**」：先手、伤害、技能它都给默认答案，你只花点击纠正错的；不纠正就继续。想认真时切「向导」，不想管时切「静默」。
