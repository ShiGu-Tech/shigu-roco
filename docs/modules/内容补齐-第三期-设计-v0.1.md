## 1. 定位与边界

- **目标**：注册图鉴中的全部技能、特性、印记、状态都登记为可执行机制；新招 / 新特性 / 新印记可照相同模式继续追加。
- **不在本稿**：伤害主公式、面板换算、MCTS、前端展示、图鉴数据采集。
- **与第二期的关系**：第二期负责「需要一层新通用能力」的条目（已落 B1–B5）；本稿负责**剩余全量**，并明确其中哪些仍需新原语、哪些纯数据。

## 6. 关键决策

1. **数据驱动不猜**：一切以 glossary / 图鉴说明为准；无实测口径登记 `unsupported` + `【待校准】`（沿用第一期原则）。
2. **能力优先**：B 类条目先补「通用原语 / 查询面」，不为单个技能打补丁；新原语 bump `ENGINE_VERSION` minor。
3. **印记 = 独立修饰层**：印记数值效果（威力 / 能耗 / 速度 / 加成）走「读印记算有效值」的通用查询面，不复用 buff 的层数语义。
4. **特性最后做**：213 条语义最杂、复用最低，放在 C4 并先抽样归类。
5. **每批可回归**：新 effect / 触发器走独立单测；改 `mechanisms.json` 后 `pnpm check` + `pnpm build`，并 `pnpm static:export` 重导 `bundle.json`。

## 7. 非目标

- 不做暴击 / 命中随机（项目口径：必中、无暴击）。
- 不为单个技能造专属命令。
- 不在本稿做 MCTS 策略。
