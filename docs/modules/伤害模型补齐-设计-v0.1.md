# 伤害模型补齐 · 设计 v0.1

> 文档状态：设计 ✅ v0.1（已确认） · 代码 🟡（通道 + 效果类型已落地） · 验证 ✅（通道单测） · 生产 🟡
>
> 基础模型见《数值与伤害模型-设计-v0.1》（主公式已封版）。本稿只补「其余倍率与特殊伤害」，不改主公式与面板。

## 1. 定位与边界

**现状**：主公式 `floor(攻 × 战时威力 × 37/41 ÷ 防) × 减伤 × 连击` 已实现（`engine/effects/damage.ts`），但结算时**只传了天气**（`mechanisms/runtime.ts:233`）：

```ts
const result = computeDamage(bundle, attackerDef, targetDef, attacker, target, skill, { weatherId: state.weather?.id ?? null });
```

`computeDamage` 已预留 `attackerTraitMult / defenderTraitMult / damageReduction / hits / extraMult`，但**没人算、没人传**；星陨、特性倍率表、连击、减伤来源、威力变化档位均未落地。本稿补齐这些，使伤害与真实对局一致（能算准的算准，算不了的显式标 `【待校准】`）。

**不在本稿**：面板换算（已封版）、回合顺序、MCTS、技能效果 DSL（见《战斗机制扩展层》）。

## 2. 设计原则

1. **不写死**：特性 / 印记倍率一律数据驱动（`data/mechanisms.json`），代码只做解释器；无法确认的登记为 `unsupported` 并保留原文。
2. **单一收集器**：一次 `dealDamage` 前，向攻/防双方按触发器收集「伤害修饰」，汇总成 `computeDamage` 的 `options`——避免把特性逻辑散进结算函数。
3. **待校准显式**：特性表、连击来源、星陨口径等未实测项在 `params.note` 标 `【待校准】`，不伪装确定。
4. **可回归**：每个修饰走独立单测（同输入可复现），并保留一处「无修饰 = 主公式」的基准测试。

## 4. 领域模型 / 数据契约

### 4.1 伤害修饰走机制扩展层（新增 effect 类型）

在 `data/mechanisms.json` 里，特性 / 印记 / 技能用**既有触发器 DSL** 声明伤害修饰，新增 effect 类型：

```ts
| { type: "modifyDamage"; target?: string; mode: "multiply" | "add"; value: number; scope?: "outgoing" | "incoming" }
| { type: "setHits"; target?: string; hits: number }
| { type: "setDamageReduction"; target?: string; percent: number }
```

- `scope: "outgoing"`（攻方输出倍率）→ `attackerTraitMult`；`"incoming"`（防方承伤倍率）→ `defenderTraitMult`。
- 触发点新增 `beforeDamage`：在 `applyDamageCommands` 结算每次 `dealDamage` 前派发，收集攻/防双方命令，汇总后传给 `computeDamage`。
- 复用既有条件（`when`）与状态/印记上下文，特性「勇气 ×1.4」「圣火骑士 ×2.0」「偏振 ×0.6」等即一组 `modifyDamage`。

### 4.2 `computeDamage` 不变，收集器负责组装 options

```ts
// mechanisms/runtime.ts
private collectDamageModifiers(state, bundle, attackerSide, targetSide, command):
  { attackerTraitMult, defenderTraitMult, extraMult, damageReduction, hits }
```

汇总规则：多个 `multiply` 相乘、`add` 相加；`setHits` 取最后生效值；`setDamageReduction` 累加并受 `rules.combat.damageReductionCap` 限制。

### 4.3 活跃 / 星陨（已实现）

- 星陨威力 `N² + 24N − 24`（`数值与伤害模型` §4.4），N 取「星陨印记」层数。
- 非幻系攻击技命中带印记目标时**引爆**（消耗全部层数），追加幻系伤害 = `floor(round(攻 × 星陨威力 × 幻系克制 × 特性 × 强化差值 × 37/41) ÷ 防)`。
- 实现：`mechanisms.json` 的 `mark:starfall-mark:*` 机制（`onHit` + `consumeMark` + `DynamicValue.terms`）；幻系技能自身不触发。特性倍率暂按 1 `【待校准】`。引擎不含特化（见《引擎边界》）。

### 4.4 威力变化

- 技能 `power_is_variable=true` 时，按机制/层数从 `damage[]` 档位取值（如 砂糖弹球 `[0,20,…,120,0]`）。
- 档位含义 `【待校准】`（层数 / 使用次数 / 回合），先在 `mechanisms.json` 声明 `powerTier` 效果，未确认的用固定首档并标 `unsupported`。

### 4.5 数据

- `data/mechanisms.json`：补 trait / mark 的 `modifyDamage` 等条目（当前 40 trait / 6 mark）。
- `data/rules.json`：`combat.damageReductionCap`（已有）、新增 `stage.cap`（强化层上限）`【待校准】`。
- 技能补充字段（连击 / 多段）：由 `scripts/sync-roco-world.mjs` 采集；无则标 `【待校准】`。

## 5. 关键决策

1. **用机制扩展层承载伤害修饰**（而非另起 `traits.json` 表）：与「技能 / 印记 / 特性统一注册」一致，条件/触发器可复用，避免第二套解释器。
2. **`computeDamage` 只做公式**：所有倍率由收集器组装成 options，保持引擎内核纯净、可单测。
3. **算不准不猜**：无实测口径的（连击来源、档位含义、部分特性）标 `【待校准】`，宁缺勿假。

## 6. 非目标

- 不改主公式系数（`37/41`）与面板换算。
- 不做暴击 / 命中 / 随机浮动（本项目口径：必中、无暴击）。
- 不追求一次补全 30+ 特性：先打通通道 + 覆盖可确认项，其余按 `unsupported` 占位。
