## 1. 定位与边界

补上模拟器当前最大的保真度缺口：**精灵属性不止种族值，还有养成资质**。原数据层写「性格 / 个体值不入库、属运行时输入」，但运行时从未携带，导致模拟器把双方都当作零培养在打。本模块定义：

1. **养成资质的领域模型与换算**（性格 + 三维：体力 / 攻击 / 防御 三个培养面板）。
2. **对手养成是隐藏信息**，用贝叶斯后验从可观测事实推断。
3. **对手库**：持久化「某对手 → 出招分布 + 养成后验」，供下一次对局先验使用。

不在本文范围：搜索算法（MCTS 稿）、结算顺序（模拟器稿）、UI 交互。

## 2. 设计原则

1. **数据驱动**：性格表、三维面板系数、等级换算全部落 `data/stats.json`，标 `【待校准】`，代码实现解释器。
2. **基础 vs 培养分离**：`race`（基础资质，静态、固定）随图鉴（`catalog.sprites[].race`）提供；养成（性格 / 三维 / 等级）是运行时档案。
3. **我方确定、对手概率**：我方养成由用户录入（确定值）；对手养成是隐变量，按后验分布积分 / 采样。
4. **可校准优先**：幅度未知处标 `【待校准】`，实测校准 = 改 JSON。

## 3. 领域模型

### 3.1 养成档案（`StatProfile`）

```ts
interface StatProfile {
  level?: number;                            // 等级（默认 stats.json.level.default）
  nature?: string | null;                    // 性格 id（对应 stats.json.natures）
  training?: Partial<Record<"hp" | "atk" | "defense", number>>; // 三维面板点数
}
```

挂在 `ActiveSprite.profile` 上，随状态快照 / 存档 / 请求一起走。

### 3.2 换算（`stats.ts`）

```text
natureMult(stat) = upFactor if 性格.up == stat
                 = downFactor if 性格.down == stat
                 = 1
trainingBonus(stat) = Σ 面板(panel→stat) : perPoint * points
finalStat(stat) = base.race[stat] * natureMult(stat) + trainingBonus(stat)
maxHp           = finalStat("hp")
```

- 三维面板默认映射：`体力→hp`、`攻击→atk`、`防御→defense`（`stats.json.training.panels`）。
- spatk / spdef / speed 目前不受三维影响，可被性格修正；如实测不同，只改 `stats.json`。
- 等级：`finalStat` 的等级缩放留 `rules.damageFormula.level` 现有口径；如需并入属性表再扩展。

> 幅度与映射均 `【待校准】`：`stats.json` 的 `perPoint`、`upFactor` / `downFactor` 先给占位值。

### 3.3 性格

- 性格 = `{ id, name, up, down, upFactor, downFactor }`；默认 `upFactor=1.1 / downFactor=0.9`（宝可梦式），可 `up=null` 表示中性性格。
- 不支持的性格 / 未知 id → 视为中性并记 warning（不崩）。

## 4. 对手养成：贝叶斯后验

### 4.1 隐变量与先验

对手养成档位离散化为 `stats.json.trainingProfiles.options`（如 未培养 / 半培养 / 满培养），每个档位是一组三维点数（+ 可选性格）。先验由 `prior` 给出（冷启动均匀）。

### 4.2 观测与似然

从对局可观测事实反推：

| 观测 | 似然（示意，`【待校准】`） |
| --- | --- |
| 对手场上次精灵的**最大生命**（血条比例 + 已知种族值） | 各档位算出的 `maxHp` 与观测的接近程度（高斯似然） |
| **速度先手**关系（谁先出手） | 各档位 `speed` 相对我方是否解释该顺序 |
| 一次**伤害数值**（我方已知攻击 → 对方掉血） | 各档位 `defense` / `spdef` 下预测伤害与观测的接近程度 |

MVP 先实现「最大生命」与「伤害」两类似然，速度留接口。

### 4.3 后验更新

离散 Dirichlet–Multinomial：`counts[profile] += 1`（观测硬计数）或按似然加权 `counts[profile] += w * likelihood`。后验期望 `P(profile) = (α + n) / (Σα + n)`，与 A/D/S 对手模型同构。

### 4.4 在 MCTS 中的使用

推演时对手养成不确定 → 在 rollout / expansion 处按后验**采样一个档位**，套用到敌方场上精灵的属性（`maxHp`、`defense`、`speed` 等）再 `step`。这样胜率是对养成不确定性的期望，而非假设某个确定值。

## 5. 对手库（`opponent/library.ts`）

持久化在浏览器 `localStorage`，随请求传入引擎（引擎仍无状态）。

```jsonc
{
  "version": 1,
  "opponents": {
    "sp-20": {
      "seen": 12,
      "actions": { "A": 7, "D": 2, "S": 3 },   // 出招大类计数
      "training": { "untrained": 1, "half": 3, "full": 8 }, // 养成档位计数
      "observations": [ /* 可选：原始观测，供复算 */ ]
    }
  }
}
```

- 键 = 对手精灵 id（后续可扩展为「对手玩家标识 + 精灵 id」）。
- 写入时机：用户录入「对手上一回合动作」（A/D/S）、录入对局事实（最大生命 / 伤害）。
- 读入时机：`/recommend` 请求的 `options.opponentLibrary`。

## 7. 关键决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 养成放哪 | 运行时 `StatProfile`，基础值随图鉴 `race` | 基础资质固定、养成每局不同 |
| 对手养成 | 离散档位后验（非连续拟合） | 与贝叶斯 A/D/S 同构，可解释、易校准 |
| 采样 vs 期望 | rollout 内采样档位 | 保留不确定性方差，实现简单 |
| 幅度 | 全进 `stats.json` 并标 `【待校准】` | 实测校准只改 JSON |

## 8. 非目标

- 不引入连续优化 / 梯度拟合养成参数。
- 不做自动识别对手养成（仍需人工观测反馈）。
- spatk / spdef / speed 的三维培养（若实测存在）留待扩展。
