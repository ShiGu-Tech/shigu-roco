## 1. 定位与边界

- **目标**：把剩余 `unsupported` 条目按依赖的**引擎能力**分组成批，每批加面后把对应条目从占位提升为真实效果；最终 `unsupported` 归零（或仅剩"数据缺失 / 待校准"）。
- **不在本稿**：伤害主公式、面板换算、图鉴同步机制本身；纯数据转写（走第三期批次脚本）。
- **原则**：引擎仍只认**通用行为**（触发器 / 条件 / 动态取值 / 效果原语 / 规则键 / 行动契约），具体技能与参数全在 `data/mechanisms.json`。**算不准不猜**：不确定口径写 `【待校准】`。
- **两类改动**：
  1. **增量加面**（不动行动 / 领域模型，直接扩触发器 / 效果 / 规则键 / 计数）——可连续做、风险低。
  2. **结构性改造**（改 `Action` 契约、加领域对象、需图鉴补数据）——按 AGENTS「新领域模型先出稿」，本稿给出设计，实施另开批次并回填。

## 3. 设计原则

1. **面 vs 内容分离**：新能力进引擎（`ENGINE_VERSION` bump），条目进 `mechanisms.json`（业务版本 bump）。
2. **能直出就直出**：优先用现有触发器 / 效果组合；确无原语才加效果，确无事件才加触发器。
3. **近似要标注**：无法精确表达时在机制 `note` 写「近似为…」，并进 §9 待校准。
4. **结构性改动单独立稿**：涉及 `Action` 契约、进化链、复活 / 变身、血脉数据的，另开设计稿，不塞进数据脚本。
5. **可回放**：新增事件 / 行动字段必须进事件日志，回放 / 观战零特殊处理。

## 4. 领域模型

### 4.1 触发器扩展（`engine/mechanisms/types.ts` + `vocabulary.ts`）

```ts
type TriggerName +=
  | "beforeHeal"      // 治疗结算前（可取消 / 改道）
  | "heal"            // 治疗结算后（等量反应）
  | "statusDamage"    // 状态 DoT 造成伤害时
  | "hpLost"          // 生命下降后（按段计）
  | "revive"          // 复活时
  | "transformed";    // 变身完成
```

- `beforeHeal` / `heal`：在 `runtime.ts` 的 `heal` 分支前后派发（级联，幂等守卫防环）。
- `statusDamage`：在状态 DoT 的 `dealDamage` 处派发（与 `onHit` 并列，带 `statusId` / `value`）。
- `hpLost`：在伤害落地处派发（带 `lost` / `ratio`），供 `hpLostQuarters` 计数。

### 4.2 派生计数（`simulator/battle.ts`，自动维护于 `SideState.counters`）

| key | 触发点 | 服务条目 |
| --- | --- | --- |
| `hpLostQuarters` | `hpLost` 累计 `floor(lost/maxHp*4)` 差分 | 嫁祸（每失去 25% 生命连击 +2） |
| `teamMoe` | `statusApplied`/换人时重算队伍 `moe` 合计 | 守护者（己方每层萌化 → 全技能能耗 −1） |
| `fieldMarkKinds` | `markApplied` 时重算双方场上印记种类 | 和弦共振（每 1 种印记魔攻 +50%） |
| `fieldBuffKinds` | `buffGained` 时重算双方场上增益种类 | 守护之心（每 1 种增益物防 +20%） |
| `incomingLethal` | `turnStart` 估算对手最高威力 vs 自身 HP | 预警 / 先知 / 哨兵 |
| `usedElementKinds` | 已做 | 旧玩具 |

### 4.3 规则键（`setRuleModifier` 通道，`ruleModifiers` 读取）

| key | 语义 | 服务条目 |
| --- | --- | --- |
| `status.dotExtraTick` | 回合末状态伤害额外触发 N 次 | 复方汤剂 |
| `status.burnGrow` | 灼烧衰减改为增长 | 煤渣草 |
| `status.burnToPoison` | 灼烧衰减转为等量中毒 | 焰色反应 |
| `turnEnd.skip` | 本侧回合末效果不触发 | 陨落 |
| `turnEnd.extra` | 本侧回合末效果额外触发 1 次 | 双向光速 |
| `status.moeNoCap` | 萌化层数不限 | 无忧无虑 |
| `cost.payWithHp` | 能量不足时以生命代 1 点能耗 | 盛宴 / 石头大餐 |
| `heal.redirectToDamage` | 回血改为对敌方等量扣血 | 戏耍 |
| `energy.noCap` | 已做 | 多人宿舍 |

### 4.4 效果原语新增（`engine/mechanisms/types.ts` + `runtime.ts` + `graph/effect-nodes.ts`）

```ts
| { type: "redirectHeal"; target?; to?: "opponent" }         // 回血 → 对敌扣血
| { type: "spreadHeal"; target?; basis?; amount; amountFrom? } // 治疗平分到场下
| { type: "spreadEnergy"; target?; delta }                    // 能量平分到场下
| { type: "copyStat"; target?; from?: "opponent"; polarity?: "buff" } // 复制增益
| { type: "grantTag"; target?; tag: string; selector?: {...} } // 给携带技能打 tag
| { type: "flipCostSign"; target? }                           // 能耗增减反转
| { type: "swapHpWithBench"; target?; benchId?: string }      // 与场下/换入交换血量比例
| { type: "tagSkill"; ... }                                    // 技能级附加（重金属粉尘）
```

- 全部走 `WRITE_NODES` 注册 + `EFFECT_VOCABULARY` 登记，程序源（编译）与 DSL 参考同步，`program-collect.test` 守等价。
- `inheritStat` 扩 `event.from`：`afterSwitch` 时可取"刚离场精灵"的强化，服务洁癖 / 孤傲。

### 4.5 动态取值扩展

- `dealDamage.powerFrom` 支持**哨兵取数**：`{ path, sentinel?: "energy" | "freeze" | "moe" }`（消耗能量 / 冻结层 / 萌化层越高威力越高）——魔能爆 / 极寒领域 / 拆礼物。
- `DynamicValue` 增 `rateOf`（`hp/maxHp` 等比）——嫁祸类阈值。

### 4.6 行动契约（结构性，单独立稿）

> 用户确认（2026-10-04）：**迅捷**＝通过主动换人入场时**该次入场即出手**（本次技能照常进入行动队列**正常拼速/优先级**，并非"拼不过就不出手"、也非无条件先手）；**萌化**＝把精灵替换为**低阶**精灵且**资质随之下调**（退化模型确认）；**血脉**作为**培养资质**的一部分输入（可在工具中替换为其他系别 / 首领）；**复生 / 特性继承**确认存在（例：击败方获得被击败方特性，如银月狼王击败骨龙）→ 对应《铭记于月亮》。

- **迅捷换入即用**（换人 + 当场释放一个带「迅捷」tag 的技能；该技能**照常按速度/优先级参与本回合排序**，只因换人本身不再独占行动，故等于"入场即出手"）：

  ```ts
  type Action = { kind: "switch"; benchId?: string; followUp?: { skillId: string; choice?: 0|1 } } | ...
  ```

  换人阶段 `doSwitch` 后，若换入精灵携带带「迅捷」tag 的技能，允许同回合追加一次技能（入 `ActionQueue`，优先级按技能 priority）。`legalActions` 对「携带迅捷技能且本回合可换」列出 `switch + followUp` 组合；MCTS 落子扩展；对战台换人按钮弹可迅捷技能选择。
- 数据侧：`grantTag`（快锤：能耗<3 的技能获迅捷；暴食：龙系技能获迅捷；翼轴：1 号位获迅捷+传动）。

- **选择 / 蓄力深度**：
  - `skillUsed` 事件补 `choice`（已可加）；每技能维护"明 / 暗是否各用过"位（`ActiveSprite.counters["choiceDone:<skillId>"]` 位掩码）——猫精灵的礼物 / 有求必应 / 一意孤行。
  - 蓄力可选：`ruleModifier "charge.manual"`（嫉妒 / 游弋：蓄力中仍可使用任一携带技能）。

### 4.7 进化链 / 伪装 / 复活 / 变身（结构性，需图鉴数据）

- **进化链**：图鉴精灵补 `evolution: { from?: spriteId; to?: spriteId[] }` + 前阶面板；`moe` 退化 = 回到前阶 + 资质重算 + 下场不消失 → 服务 萌化 / 示弱 / 赤子之心 / 反弹 / 拆礼物 / 化茧（已部分）。
- **伪装**：`ActiveSprite.disguise?: { spriteId; revealed?: boolean }` + `revealDisguise` / `applyDisguise` 效果——博物。
- **复活**：`ActiveSprite.reviveAt?: number`（力竭但待复活，`hp<=0` 且 `reviveAt` 存在时不判负）；`afterDeath` 调度 `revive`——不朽 / 正模标本。
- **变身**：`transform` 效果（换 `spriteId` + 面板 + 清空状态）——腾挪 / 保卫 / 好象坏象 / 铭记于月亮（继承被击败者特性）。

### 4.8 血脉（图鉴数据缺失）

- 图鉴精灵补 `bloodlineOptions`（来自 `sourceData.bloodline_options`：含各**系别血脉**与**首领血脉**；当前图鉴缺「污染血脉」）。
- 工具新增 `PetInstance.bloodline` 输入（**可替换为其他系别**），`ActiveSprite.bloodline` 注入 + 条件 `self.active.bloodline` / `target.active.bloodline`——绒粉星光 / 月光审判 / 稀兽花宝 / 契约的形状 / “国王”的威严（天通地明「污染」待数据）。

## 7. 关键决策

1. **先增量后结构**：D1–D5 不碰 `Action` 与领域对象，可连续交付；D6–D9 各自立稿。
2. **规则键统一走 `setRuleModifier` / `ruleModifiers`**：全局修饰不硬编码到引擎逻辑，保持"内容在数据"。
3. **新效果必须同时进 `WRITE_NODES` 与 `EFFECT_VOCABULARY`**，否则程序源与 DSL 参考漂移（`program-collect.test` 会挂）。
4. **派生计数一律引擎维护**（不靠机制自增）：保证无特性在场时也一致，且数值可回放。
5. **`incomingLethal` 用对手招牌技能估上限**（非全枚举），标注 `【待校准】`；宁可保守不漏判。

## 8. 非目标

- 不引入暴击 / 命中随机（命中仍按 100% / 图鉴 `hitRate`）。
- 不重写伤害主公式；哨兵变量威力只走 `powerFrom` 通道。
- 不改观战 / 回放记录格式（新事件向后兼容）。
- 不追求未公开口径的 100% 还原：拿不准写 `【待校准】`。
- 不在本稿做 D6–D9 的具体编码（另开稿 + 批次）。

## 9. 待校准

1. 「敌方技能足够击败自己」的判定口径（是否计入克制 / 连击 / 随机）。
