# 引擎工作台 · 设计 v0.1

> 文档状态：设计 ✅ v0.1（已确认，2026-10-03 分期调整见 §8） · 代码 🟡（W0 / P1 / G0 / G1 已落；G3a 实施中） · 验证 ✅（graph 单测） · 生产 🟡｜创建 2026-10-01

## 1. 定位与边界

- **定位**：把引擎的**统一程序**（执行图：机制 / 回合流程 / 伤害公式 / 系别克制，见《引擎执行图-设计-v0.1》）从「脚本手写」升级为**可视化编辑 + 版本化 + 沙盒试跑**；并提供可操控的**状态调试模式**（手动设 HP / 能量 / 印记 / 状态 / 技能栏，单步结算，看**逐节点 trace**）。
- **核心澄清（指令 vs 程序）**：
  - **程序 = 配置**（统一执行图，JSON、可版本化、可视化编辑）：触发 / 条件 / 效果 / 流程 / 公式 / 系别克制**全在一份程序**里。工作台编辑的就是它。
  - **原语节点 = 代码**：每种**节点类型怎么执行**（如 `write.dealDamage` 的算式、`write.rotateLoadout` 的轮转）是注册在 `NodeTypeRegistry` 的强类型执行器；工作台**不改其语义**，只从节点面板里取用。新增节点类型 = 新增引擎能力 = bump `ENGINE_VERSION`。
- **边界**：不替代图鉴同步；不做原语语义的自定义 DSL；不改 DSH / 站点数据。
- **相关文档**：《引擎执行图-设计-v0.1》《引擎边界》《引擎版本与维护》《引擎能力总览》《对战记录与回放》。

## 2. 设计原则

- **节点封闭、程序开放**：节点类型是注册的强类型执行器；工作台在其上做可视化连线与配置，绝不生成「引擎不认识的语义」。
- **单一事实源**：程序（执行图）是唯一事实源，读写同一 schema，不另造格式。
- **可校验 / 可试跑 / 可 diff / 可回滚**：任何编辑先校验，再在隔离实例里试跑，确认后才入仓。
- **引擎零特化**：工作台不向引擎注入任何具体技能 / 精灵 id / 站点字段。

## 3. 领域模型

围绕**统一执行图（程序）**展开：

- **NodeCatalog（节点库）**
  - `Vocabulary`：从 `NodeTypeRegistry` 导出的节点类型清单（类型名 + 输入/输出端口 + 参数 schema + 是否纯函数 / 副作用），是编辑器的唯一边界。
- **ProgramAuthoring（程序编辑）**
  - `ProgramDraft`：`nodes[] + edges[](control/data) + entries[] + resources{}` + 校验元数据。
  - `ValidationResult`：`{ errors: Issue[]; warnings: Issue[] }`（未知节点类型、端口缺失 / 类型不符、控制流成环、entries 不可达、资源引用无效）。
- **DebugSession（状态调试）**
  - `DebugState`：可手改的 `BattleState` 子集（HP / 能量 / 魔力 / 技能栏 / 印记 / 状态 / buff / debuff / 计数器）+ 天气 + 双方在场。
  - `ActionCursor`：待结算的双方行动（由 `legalActions` 提供选项）。
  - `Trace`：**逐节点** trace（`node / type / inputs / outputs / mutations / parent`）。
- **ProgramVersion（版本管理）**
  - `VersionEntry = { id, label, createdAt, baseVersion, program, note }`。
  - `Diff`：按节点 / 边 / 资源的增 / 删 / 改生成结构化 diff。

## 4. 数据库 / 接口

### 4.1 引擎侧内省补强（前置，属于引擎能力）

1. **事件保留 `trigger`**：`asBattleEvent` 现丢弃 `trigger`，补回，供「本回合在哪些生命周期阶段触发了什么」。
2. **伤害暴露 `breakdown`**：`computeDamage` 已算 `breakdown`（威力 / 属性 / STAB / 克制 / 天气 / 增减伤 / 连击），`applyDamageCommands` 现丢弃，改为挂到 `damage` 事件 `data.breakdown`。
3. **`legalActions` 可调用**：`Simulator.legalActions` 已存在但仅内部用；经 Worker / REST 暴露，供调试台用引擎真值选择行动（替代前端 `board/util.ts` 的重实现）。
4. **（可选）阶段级 trace**：把一回合按 `turnStart / actionDeclared / beforeAction / beforeDamage / onHit / afterDamage / actionResolved / turnEnd` 分段返回，供生命周期流程图逐段高亮。首版可用事件自带 `trigger` 在客户端分组，不改执行器。

### 4.2 工作台接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/engine/workbench/schema` | 返回 `Vocabulary`（节点类型 + 端口 + 参数 schema），由 `NodeTypeRegistry` 导出，UI 不硬编码 |
| POST | `/api/engine/workbench/validate` | 校验 `ProgramDraft`，返回 `ValidationResult` |
| POST | `/api/engine/workbench/preview` | 用 draft 程序构建**隔离实例**（注入编辑后的程序）试跑，返回逐节点 `Trace` |
| GET | `/api/engine/workbench/versions` | 列出版本库（repo 内已发布 + 浏览器 localStorage 草稿） |
| POST | `/api/engine/workbench/versions` | 保存版本条目（草稿） |
| POST | `/api/engine/workbench/apply` | 把某版本写回 `data/program.json`（本地开发写操作，需显式确认） |
| POST | `/api/engine/debug/step` | 用给定 `DebugState` + 双方行动，真实结算一回合，返回逐节点 `Trace` |
| POST | `/api/engine/debug/legal` | 返回某 `DebugState` 下引擎的合法行动 |

- **存储**：现行事实源 = 仓库**程序文件**（`data/program.json`，语义版本；由旧 `mechanisms` / `pipeline` / `formula` / `elements` 编译而来）；草稿 / 版本库首版存浏览器 localStorage（`roco.engineWorkbench`），`apply` 才入仓。不入库的调试状态仅会话内。

## 5. 路由与页面

- **`/engine`（引擎工作台）**：三栏
  - 左：程序 / 子图列表（按事件源 / 关键字筛选，显示校验状态与关联条目）。
  - 中：**执行图编辑器**——节点面板（取值 / 运算 / 比较 / 逻辑 / 分支 / 写入 / 事件源，字段随节点 schema 动态渲染）+ 画布连线（控制边 / 数据边）+ 子图；即《引擎执行图》的统一程序。
  - 右：校验结果 + 试跑轨迹（复用生命周期 / 伤害链面板）。
- **`/engine/debug`（调试沙盒）**：左侧可编辑状态面板；中上「双方行动」（引擎 `legalActions`）；中下轨迹与伤害分解；下「单步 / 回退 / 重置 / 自动播放」。
- 导航（`components/app-nav.tsx`）新增「引擎」入口。
- 复用现有可视化组件：事件渲染参考 `board/log.ts`、费用来源参考 `side-panel.tsx` / `active-board.tsx`。

## 6. 关键决策

- **D1 词汇表来自代码、以 schema 端点暴露**：避免 UI 与引擎漂移；新增原语只改引擎并自动出现在编辑器。
- **D2 版本以 JSON 文件 + 语义版本；草稿另存**：`data/program.json`（执行图）是事实源，工作台草稿在 localStorage，`apply` 才入仓。
- **D3 试跑隔离**：Worker 已支持 `init(raw)`，预览用编辑后的 raw 构建临时 bundle，不污染线上 `bundle.json`。
- **D4 调试 ≠ 回放**：回放只播已存快照、绝不重演；调试沙盒是**真实引擎重算**，可改状态。
- **D5 编辑粒度**：编辑**统一程序**的节点 / 边 / 资源（含 `resource.elements` 系别克制、`resource.rules` 公式）；具体技能 / 精灵仍来自图鉴，不在此编辑。
- **D6 权限**：定位为本地开发 / 自用工具；`apply` 仅本地，线上只读。
- **D7 版本化管理回答**：整份**程序（执行图）**是 JSON、可版本管理（`programVersion` + `hash`），工作台把它产品化；**原语节点**（节点类型的执行语义）是代码，只走 `NodeTypeRegistry` 插拔，不随 JSON 变。

## 7. 非目标

- 不做自定义 DSL / 脚本执行（不在数据里写代码）。
- 不做原语语义的可配置化（那是引擎本体）。
- 不做多人协作 / 云端版本库 / 权限体系。
- 不做图鉴同步与外部数据抓取。
- 不在本稿引入新的模拟语义（仅暴露既有内部信息）。
