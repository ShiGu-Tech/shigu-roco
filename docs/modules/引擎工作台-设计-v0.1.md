# 引擎工作台 · 设计 v0.1

> 文档状态：设计稿（待评审）｜创建 2026-10-01

## 1. 定位与边界

- **定位**：把引擎的**定义层**（`mechanisms.json` 规则 + `pipeline.json` 回合流程 + `formula.json` 伤害公式，见《引擎可改性-设计-v0.1》）从「脚本手写」升级为**可视化编辑 + 版本化 + 沙盒试跑**；并提供可操控的**状态调试模式**（手动设 HP / 能量 / 印记 / 状态 / 技能栏，单步结算，看内部轨迹）。
- **核心澄清（规则层 vs 执行器层）**：
  - **规则层 = 数据**（已经是 JSON，可版本化）：编辑的是「用哪些原语、什么条件、什么参数」的**组合**。工作台只编排组合。
  - **执行器 / 原语层 = 代码**：`TriggerName` 的种类、`Condition` 的算子、`EffectSpec` 每种效果的**语义**（如 `dealDamage` 公式、`rotateLoadout` 轮转）写死在 `engine/**`，工作台**不可改**；新增原语 = 新增引擎能力 = 照旧 bump `ENGINE_VERSION`。
- **边界**：不替代图鉴同步；不做原语语义的自定义 DSL；不改 DSH / 站点数据。
- **相关文档**：《引擎边界》《状态修改器与引擎能力》《数据层》《引擎版本与维护》《引擎能力总览》《对战记录与回放》。

## 2. 设计原则

- **词汇表固定、组合可编辑**：原语是代码里封闭的枚举；工作台在其上做可视化组合，绝不生成「引擎不认识的语义」。
- **单一事实源**：工作台读写与 `data/*.json` 同一 schema，不另造格式。
- **可校验 / 可试跑 / 可 diff / 可回滚**：任何编辑先校验，再在隔离 bundle 里试跑，确认后才入仓。
- **引擎零特化**：工作台不向引擎注入任何具体技能 / 精灵 id / 站点字段。

## 3. 领域模型

三个子域，共享同一 `MechanismDefinition` schema：

- **MechanismAuthoring（机制编辑）**
  - `Vocabulary`：从引擎代码导出的词汇表（触发器名、条件算子、效果类型及其字段），是编辑器的唯一边界。
  - `MechanismDraft`：`MechanismDefinition` + 校验元数据（`dirty` / `origin`）。
  - `ValidationResult`：`{ errors: Issue[]; warnings: Issue[] }`（未知 trigger / 效果类型、缺必填字段、条件路径不可达、引用了词表外的 id 等）。
- **DebugSession（状态调试）**
  - `DebugState`：可手改的 `BattleState` 子集（HP / 能量 / 魔力 / 技能栏 / 印记 / 状态 / buff / debuff / 计数器）+ 天气 + 双方在场。
  - `ActionCursor`：待结算的双方行动（由 `legalActions` 提供选项）。
  - `Trace`：一次结算的完整事件流（含 `trigger` / `mechanismId` / `effectType` / 状态前后值 / 伤害 `breakdown`）。
- **RegistryVersion（版本管理）**
  - `VersionEntry = { id, label, createdAt, baseVersion, files: { path, content }, note }`。
  - `Diff`：按 `mechanisms.json` 条目的增 / 删 / 改生成结构化 diff。

## 4. 数据库 / 接口

### 4.1 引擎侧内省补强（前置，属于引擎能力）

1. **事件保留 `trigger`**：`asBattleEvent` 现丢弃 `trigger`，补回，供「本回合在哪些生命周期阶段触发了什么」。
2. **伤害暴露 `breakdown`**：`computeDamage` 已算 `breakdown`（威力 / 属性 / STAB / 克制 / 天气 / 增减伤 / 连击），`applyDamageCommands` 现丢弃，改为挂到 `damage` 事件 `data.breakdown`。
3. **`legalActions` 可调用**：`Simulator.legalActions` 已存在但仅内部用；经 Worker / REST 暴露，供调试台用引擎真值选择行动（替代前端 `board/util.ts` 的重实现）。
4. **（可选）阶段级 trace**：把一回合按 `turnStart / actionDeclared / beforeAction / beforeDamage / onHit / afterDamage / actionResolved / turnEnd` 分段返回，供生命周期流程图逐段高亮。首版可用事件自带 `trigger` 在客户端分组，不改执行器。

### 4.2 工作台接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/engine/workbench/schema` | 返回 `Vocabulary`（可用 trigger / 条件算子 / 效果类型与字段），由引擎源码导出，UI 不硬编码 |
| POST | `/api/engine/workbench/validate` | 校验 `MechanismDraft[]`，返回 `ValidationResult` |
| POST | `/api/engine/workbench/preview` | 用 draft 机制构建**隔离 bundle**（在 Worker init 时注入编辑后的 `mechanisms.json`），试跑并返回 `Trace` |
| GET | `/api/engine/workbench/versions` | 列出版本库（repo 内已发布 + 浏览器 localStorage 草稿） |
| POST | `/api/engine/workbench/versions` | 保存版本条目（草稿） |
| POST | `/api/engine/workbench/apply` | 把某版本写回 `data/mechanisms.json`（本地开发写操作，需显式确认） |
| POST | `/api/engine/debug/step` | 用给定 `DebugState` + 双方行动，真实结算一回合，返回 `Trace` |
| POST | `/api/engine/debug/legal` | 返回某 `DebugState` 下引擎的合法行动 |

- **存储**：现行事实源 = 仓库 `data/mechanisms.json`（语义版本）；草稿 / 版本库首版存浏览器 localStorage（`roco.engineWorkbench`），`apply` 才入仓。不入库的调试状态仅会话内。

## 5. 路由与页面

- **`/engine`（引擎工作台）**：三栏
  - 左：机制列表（按 `ownerType` / `trigger` / 关键字筛选，显示校验状态与命中技能数）。
  - 中：**定义编辑器**——机制（`trigger` 下拉、条件构建器 `when`、效果构建器 `effects`）、回合流程（`pipeline` 阶段表）、伤害公式（`formula` 表达式 AST），字段随 `Vocabulary` 动态渲染（定义层结构见《引擎可改性-设计-v0.1》）。
  - 右：校验结果 + 试跑轨迹（复用生命周期 / 伤害链面板）。
- **`/engine/debug`（调试沙盒）**：左侧可编辑状态面板；中上「双方行动」（引擎 `legalActions`）；中下轨迹与伤害分解；下「单步 / 回退 / 重置 / 自动播放」。
- 导航（`components/app-nav.tsx`）新增「引擎」入口。
- 复用现有可视化组件：事件渲染参考 `board/log.ts`、费用来源参考 `side-panel.tsx` / `active-board.tsx`。

## 6. 关键决策

- **D1 词汇表来自代码、以 schema 端点暴露**：避免 UI 与引擎漂移；新增原语只改引擎并自动出现在编辑器。
- **D2 版本以 JSON 文件 + 语义版本；草稿另存**：`data/mechanisms.json` 是事实源，工作台草稿在 localStorage，`apply` 才入仓并触发 `export-static-data`。
- **D3 试跑隔离**：Worker 已支持 `init(raw)`，预览用编辑后的 raw 构建临时 bundle，不污染线上 `bundle.json`。
- **D4 调试 ≠ 回放**：回放只播已存快照、绝不重演；调试沙盒是**真实引擎重算**，可改状态。
- **D5 编辑粒度**：编辑 `mechanisms` / `pipeline` / `formula`（定义层，见《引擎可改性》）；`rules.json` / `stats.json` 先只读展示，后续再开。
- **D6 权限**：定位为本地开发 / 自用工具；`apply` 仅本地，线上只读。
- **D7 版本化管理回答**：**策略/规则层**（`mechanisms` / `pipeline` / `formula`）可通过 JSON 版本管理，工作台把它产品化，版本号即 `EngineBundle.specVersion`、比对用 `bundleHash`；**执行器/指令集层**（效果语义等）是代码，只走 `EngineExtension` 插拔，不随 JSON 变。

## 7. 非目标

- 不做自定义 DSL / 脚本执行（不在数据里写代码）。
- 不做原语语义的可配置化（那是引擎本体）。
- 不做多人协作 / 云端版本库 / 权限体系。
- 不做图鉴同步与外部数据抓取。
- 不在本稿引入新的模拟语义（仅暴露既有内部信息）。
