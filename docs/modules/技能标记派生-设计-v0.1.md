# 技能标记派生 · 设计 v0.1

> 文档状态：设计 v0.1 · 代码 ✅ · 验证 ✅ · 生产 🟡

## 1. 定位与边界

把技能的**结构化标记**（`charge` / `quick` / `simple` / `choice`）从「引擎核心用中文正则现算」重构为「**数据事实 + 单一摄取适配层**」，并删除无消费方的死标记。纯结构重构，**不改变任何结算语义**。

## 2. 背景与问题

现状 `engine/data.ts#deriveSkillTags` 由图鉴描述派生 8 个 tag：

| 旧 tag | 消费方 | 结论 |
| --- | --- | --- |
| `charge` | `simulator/battle.ts` 行动 | 保留 |
| `quick` | `simulator/battle.ts` 迅捷 / 换入 | 保留 |
| `simple` | `mechanisms/runtime.ts` 不移 | 保留 |
| `choice` | 无（引擎另用 `/选择/` 正则判定） | 收敛为结构化布尔 |
| `improvise` | 无 | 删除 |
| `burst` | 仅测试 | 删除标记 |
| `shift` | 无 | 删除 |
| `dedicationTarget` | 无 | 删除 |

问题：

1. **死标记**：一半 tag 无任何消费方，纯查询面噪声。
2. **文案耦合**：中文关键词散落在引擎核心（`data.ts` / `simulator/battle.ts` / `server.ts`），站点改字即静默失效；违背《引擎边界-设计》「引擎不得含站点格式」。
3. **声明与实现脱节**：`rules.json.turnPhases` 全仓零引用，阶段顺序实际写死在 `battle.ts#step`（本次一并删除，见 §9）。

## 3. 设计原则

- **引擎运行时只读结构化字段**，不出现任何中文关键词。
- **站点文案解析集中在摄取适配层**（`engine/catalog/**`）。
- **只保留被消费的标记**，无消费方一律删除（不保留兼容层、不留 `tags` 数组）。
- **标记现算、不落盘**：注册图鉴只存原文描述，标记在装配期重建。

## 4. 领域模型（标记）

| 标记 | 语义 | 来源 | 消费方 |
| --- | --- | --- | --- |
| `charge` | 蓄力技（下回合自动释放） | **机制事实** `beginCharge` | `simulator/battle.ts#legalActions` |
| `quick` | 迅捷技 | 站点描述（摄取层） | `simulator/battle.ts#skillIsQuick` / 换入 |
| `simple` | 无附加效果的攻击技（不移） | 站点描述（摄取层） | `mechanisms/runtime.ts` 伤害修饰 |
| `choice` | 选择技（明 / 暗分支） | 站点描述（摄取层） | `simulator/battle.ts#skillHasChoice` / 对战台 |

**为何 `simple` 不用机制推导**：实测「机制仅含 `dealDamage`」的口径（242 条）远大于文本口径（148 条）——大量技能附加效果尚未登记，机制口径会误判为「无附加」并放大 `simple.powerMul`（不移）结算。故 `simple` 保持站点描述口径，只把解析位置移到摄取层。

**为何 `charge` 用机制事实**：`beginCharge` 机制集合与「描述以蓄力开头」集合完全一致（各 5 条），机制是权威数据事实。

## 5. 分层与数据流

```text
站点描述 ──(摄取适配层)──┐
                        ├─▶ annotateSkillFlags(skills, mechanisms) ──▶ skill.{quick,simple,choice,charge}
mechanisms.json ────────┘
        装配期调用：data.ts#buildBundle（Worker/浏览器） · server.ts#getBundle（Node）
```

- `engine/catalog/skill-flags.ts`：`annotateSkillFlags(skills, mechanisms)` 纯函数。解析描述 → `quick` / `simple` / `choice`；读机制 → `charge`。幂等：每次先清除旧字段与历史 `tags`。
- **不在 `catalog/normalize.ts` 落盘**：注册图鉴是 normalize 的持久化产物，原始快照无法离线重放；标记在装配期由描述重建，等价且无需重新注册图鉴。

## 6. 接口 / 契约

技能对象新增（缺省即「否」）：

```ts
skill.quick?:  true   // 迅捷
skill.simple?: true   // 无附加效果的攻击技
skill.choice?: true   // 选择技
skill.charge?: true   // 蓄力技
```

- **删除** `skill.tags: string[]`。
- 对战台目录 `api/handlers.ts#skillBrief` 增 `choice` 字段，前端据此显示「明 / 暗」分支（不再正则判描述）。

## 7. 关键决策

- **D1 零结算变化**：`simple` 口径不变；`charge` 集合经核对与文本一致；纯结构重构。
- **D2 不留兼容层**：`tags` 数组与 5 个死标记直接删除，不做别名/回退。
- **D3 解析留在摄取适配层、装配期运行**：引擎核心与运行时彻底不碰文案。
- **D4 删除 `rules.json.turnPhases`**：阶段内核是代码（`battle.ts#step`），死声明删除。

## 8. 非目标

- 不新增 / 修改任何技能、特性、印记内容。
- 不做「回合阶段内核数据化」——那是固定规则内核，数据化收益低、风险高。
- 不迁移到 normalize 落盘（受原始快照可得性限制）。
