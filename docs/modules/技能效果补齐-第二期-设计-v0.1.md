## 1. 定位与边界

**现状**：`data/mechanisms.json` 覆盖 664 条机制；剩余的 `unsupported`（数据里显式占位）多为「需要新时机 / 新查询面 / 新 tag」的条目，其余是纯数据转写（在各自域文档推进）。

**目标**：为下述条目补**通用引擎能力**（不是为一个技能打补丁），使其可用数据表达；能算准的算准，算不准的显式 `unsupported` + `【待校准】`。

**不在本稿**：伤害主公式、面板、MCTS、前端展示；纯数据量补齐（继续走各域文档 / 批次转写）。

## 3. 通用能力设计

### 3.1 条件派生值（ratio / 行动时序）

- **派生值**：`Condition` 的比较两侧支持动态表达式。现 `valueFrom` 只取单路径；扩展为 `DynamicValue`（复用已有的 `path` + `scale` + `offset` + `terms` + `count`），使「HP < 50%」=`{ path: "self.active.hp", lt, valueFrom: { path: "self.active.maxHp", scale: 0.5 } }` 可表达。
- **行动时序**：执行技能时在事件里暴露 `event.wentFirst`（本行动是否在本回合此刻最先结算 / 是否快于对手），供「若先于敌方攻击」类条件。等价信息也可由 `event.reacted` 的派生（应对必先手）与速度快照给出，优先落 `wentFirst` 布尔。
- 影响面：`conditions.ts` 的 `valueFrom` 解析；`simulator` 在 `executeSkill` 事件补 `wentFirst`。

### 3.2 延迟效果（跨回合调度）

- 动机：入梦「敌方下回合回能 −5」；`蓄力` 亦隐含「延迟到下回合释放」。
- 设计：新增 `scheduleEffect`（与既有 `scheduleEntry` 同构）：把 `effects` 排入 `SideState.pendingEffects: { dueTurn: number; effects: EffectSpec[] }[]`，在 `turnStart` 结算 `dueTurn <= turn` 的条目（或指定 `timing: "turnStart" | "turnEnd"`）。
- 复用：`scheduleEntry`（下场 / 换人队列）已有先例，字段与执行器可共用。

### 3.3 层数阈值触发（onStack）

- 动机：`引电` 满 2 层触发；部分印记「满 N 层」同型。
- 设计：新增触发器 `statusReached` / `markReached`——`applyStatus` / `applyMark` **跨过阈值**时派发一次（事件带 `statusId` / `from` / `to` / `threshold`）。阈值与是否消耗层数由机制数据声明（`threshold` + 可选 `consume`）。
- 备选：仅用 `statusApplied` + 条件 `statuses.X gte N` + `oncePerTurn` 近似；但「跨过阈值」需去重，故仍建议独立触发器。

### 3.4 技能 tag（巧变 / 迸发 / 传动 / 蓄力 / 选择）

- **数据模型**：技能条目增加 `tags: string[]`（来源：图鉴 `description` 的 `desc_id` 解析），引擎按 tag 启用通用行为：
  - `蓄力 charge`：使用后技能进入 `pendingSkill`，下回合由行动队列自动释放；蓄力期间免疫离场效果。需要行动队列 / 模拟器支持「待释放技能」。
  - `迸发 burst`：`ActiveSprite` 记录 `firstActionSinceEntry`；入场后首次行动的事件带 `event.burst=true`，供数据条件（第一期已用 `onEntry` + 计数近似，可正式化）。
   - `传动 shift(N)`：`turnStart` 时把带 `传动X` 的技能在 `loadout` 内下移 X 位（按数据参数）——领域模型见 §3.6。
  - `选择 choice`：技能数据拆「明 / 暗」两套 effects，行动时选择执行其一（数据层 `variants`）。
  - `巧变 improvise`：使用后 `loadout` 中该技能替换为「指定范围内的随机技能且能耗 −1」，用完还原（复用现有 `randomizeSkill` + `skillOverrides`，补 tag 触发时机）。
- 原则：引擎只认 tag 的**通用行为**，具体技能 / 范围 / 参数全在数据。

### 3.5 星陨反制 & 换人登场状态

- **星陨反制（引力偏转）**：应对成功（`event.reacted`）且为防御技能时，对敌方执行一次「星陨引爆」——复用 `consumeMark`（`markId: starfall-mark`，`effectsOnConsume` 的伤害公式 N²+24N−24），无需新命令，仅需把触发时机挂到技能命中 / 应对链（第一期 `onHit` 已具备）。
- **换人登场状态（观测者效应）**：`escape` + 给「下个入场精灵」由 `scheduleEntry` 施加 `applyStatus(月陨星)`；依赖先把 `moonfall-star-state`（月陨星状态）语义补齐。

### 3.6 技能栏位置域（`传动`，B4b）

- **词条原文**（图鉴 `glossary[1033]`）：「回合开始时，带有『传动X』的技能会向下移动 X 个位置，该效果可叠加。」
- **领域模型**：`ActiveSprite.loadout: string[]` 由「固定技能池」升级为**有序技能栏**——位置 = 索引 + 1（1..N，N≤4），传动按回合重排该数组（就地持久化，故逐回合累积）。`loadout` 已随快照 / `cloneActive` 拷贝，回放无需改记录格式，仅前端技能栏要按数组顺序渲染。
- **通用能力**（引擎只认行为，参数全在数据）：
  1. **传动轮转 effect** `rotateLoadout{ skillId?; slots; target? }`：`turnStart` 对目标侧 active 的 `loadout`，把 `skillId`（默认机制 `ownerId`）**向下移 `slots` 位**（循环取模 `(旧位置+slots)%N`）。数据：每条传动技注册 `{ownerType:"skill", ownerId, trigger:"turnStart", when:[{path:"self.active.loadout",op:"contains",value:id}], effects:[{type:"rotateLoadout",slots:X}]}`。「可叠加」= 多条效果依次施加（位移相加）。
  2. **槽位条件**：行动事件补 `event.action.slot`（行动技能在施法者 loadout 的 1-based 位置）。「位于 N 号位」=`op:"eq"`；「1 号或 3 号位」=`op:"in"`。
  3. **相邻技能派生值**：行动事件补 `event.action.neighborPowerSum` / `neighborPowerDiff`（相邻两侧技能威力和 / 差绝对值，缺位按 0）。「威力为两侧和的三分之一」=`powerFrom:{path:"event.action.neighborPowerSum",scale:1/3}`；「额外增加两侧差的四分之一」=`powerFrom:{path:"event.action.neighborPowerDiff",scale:1/4,offset:30}`。
  4. **条件威力加成** `addPower{ value; valueFrom? }`：在 `beforeDamage` 收集，累加到本次 `dealDamage` 的有效威力（先于属性 / STAB 结算）。「位于 1 号位时威力 +60」= `when:[{path:"event.action.slot",op:"eq",value:1}]` + `addPower{value:60}`。
- **触发时机调整**：`turnStart` 由「单次全局派发」改为**按侧派发**（`actorSide`，与 `turnEnd` 一致），使 `self.active.loadout` 类条件可正确取自身；现有数据无 `turnStart` 机制，改动零回归。
- **命令携带事件**：`MechanismRegistry.collect` 给 `EffectCommand` 带上 `context.event`，使 `powerFrom` / `valueFrom` 能解析 `event.action.*`（此前命令无 event，路径恒为 0）。
- **决策**：
  - 轮转范围 = 当前 `loadout` 实际长度（`N` 可能因 learn/forget 变动），循环取模。
  - 相邻技能以**行动技能**为中心；行动技能不在 `loadout`（异常态）时相邻值记 0。
  - 传动重排与 `skillOverrides`（巧变）的先后：先传动、后巧变（待校准 §8.3）。
- **本批范围**：14 条 `传动` 技能的位置条件 / 威力加成 / 相邻威力 / 轮转；两个**被动两侧修正**（`sk-7070060` 两侧能耗 −1、`sk-7070250` 两侧威力 +10）需「相邻技能被动修正」能力（带 key 幂等），**移到 B4b-2**。
- **影响面**：`types.ts`（`rotateLoadout` / `addPower` effect）、`registry.ts`（命令带 event）、`runtime.ts`（两 effect 处理 + `addPower` 汇入伤害）、`battle.ts`（`turnStart` 按侧 + 行动事件补 slot / neighbor + `applyDamageCommands` 透传）。

## 4. 生命周期 / 触发时机

```text
turnStart
  └─ 传动位移 → pendingEffects(dueTurn) 结算 → 蓄力待释放技能入队
行动：beforeAction → executeSkill（事件带 wentFirst / burst）→ 伤害 → onHit（星陨反制）→ afterDamage
applyStatus / applyMark
  └─ 跨阈值 → statusReached / markReached
换人：beforeSwitch → scheduleEntry(登场状态) → onEntry → afterSwitch
```

## 8. 待校准

1. `wentFirst` 与「应对必先手」「先手度叠加」的口径（接第一期 §9）。
2. 蓄力期间「免疫所有离场效果」的范围（强制换人 / 脱离 / 自身换人）。
