# 对战台（实时对局推演） · 设计 v0.1

> 文档状态：设计 ✅ v0.2（§9 布局重构 / §10 回退机制，已确认） · 代码 🟡（v0.1 已上线，v0.2 重构中） · 验证 ✅ · 生产 ✅

## 1. 定位与边界

`对局辅助台-设计-v0.1` 的 `/` 主页是「一次性录入 → 推演一次」的复盘式面板。本稿新增 **对战台**：把 `/` 改为**左右对峙的实时对局推演**——屏幕左为我方、右为敌方，双方轮流手选动作，每次结算后**实时重算**胜率，用 **ECharts 双折线**展示双方胜率随回合变化，并把**推荐度直接标注在各技能 / 换人 / 聚能按钮上**。

不负责：任何战斗规则 / 概率计算（全在引擎）；仍不读取画面、不自动操作、不联网。

原「详细录入 / 存档复盘」面板移师 `/record`，能力不删。

## 2. 设计原则

- **人机同权**：左（我方）与右（敌方）都手选动作，不做敌方自动行动；工具只给两侧各自的推荐度。
- **状态即真相**：页面显示的「我方 / 敌方」字段全部由引擎 `BattleState` 驱动，前端不自行推演血量 / 能量。
- **数据驱动按钮**：按钮集合由 `catalog`（技能 / 系别 / 能量上限）与当前 `BattleState` 派生，不硬编码技能。
- **推荐度可解释**：按钮上的数字是 MCTS 的 `winRate`（该动作的期望胜率），不是启发式打分。

## 3. 领域模型

新增/复用的前端模型（`apps/web/src/modules/board/`）：

```ts
type Chosen = { action: EngineAction; label: string } | null;

interface TrendPoint { turn: number; myWin: number; enemyWin: number }

interface Board {
  catalog: Catalog;
  state: BattleState;                 // 由引擎运行态驱动
  rec: RecommendResult | null;        // 我方视角：按钮推荐度 + 位置胜率
  enemyRec: RecommendResult | null;   // 敌方视角：把 state 对调后推演
  history: TrendPoint[];              // 双折线数据
  pendingP: Chosen;                   // 本回合我方已选
  pendingE: Chosen;                   // 本回合敌方已选
  log: Event[]; terminal: Terminal;
}
```

- `winRate`（位置胜率）取该方 `rec.actions[0].winRate`（最优动作的期望胜率）。
- 敌方视角 = 把 `BattleState.player/enemy` 对调后调 `/recommend`；敌方按钮读 `enemyRec.actions`。
- 敌方不显示「首领化」（引擎中该动作仅 player 侧可用）。

### 动作集合（由状态派生）

| kind | 来源 | 条件 |
| --- | --- | --- |
| `skill` | 场上精灵 `loadout`（4 个） | `cost ≤ energy` |
| `switch` | 背包存活精灵 | `spriteId ≠ 当前` |
| `wish`（愿力冲击） | 全队背包技能 | `wishChargesLeft > 0 && wishCooldown == 0`（2 次 / CD 4） |
| `energy`（聚能） | 规则 `energy` | `energy < energy.max`；固定回 5、占用本回合 |
| `leader` | 场上次精灵 | 仅我方 · `leaderAllowed && !leaderUsed` |

> 引擎侧 `legal_actions` 不产生泛用「防御」动作（防御是技能类别），前端按钮与之保持一致。

## 4. 接口 / 契约

复用 `架构/引擎与前端通道-设计-v0.1` 的既有端点，无新增：

- `GET /catalog`：精灵 / 技能 / 系别（含 `nameZh`）/ 规则（含 `energy.max`）。
- `POST /simulate/turn`：提交双方动作 → 返回新局面 `state`、事件 `log`、`terminal`。
- `POST /recommend`：对当前局面跑 MCTS → `actions[].winRate`、`opponent`、`meta`。

引擎改动：
- `ActionKind` 增 `"energy"`；`rules.energy = { initial: 10, recover: 5, max: 10 }`；`rules.magic = { initialPerSide: 4, maxPerSide: 4, perFaint: 1 }`；`rules.wish` 2 次 / CD 4；`ActiveSprite.loadout` 与 `legal_actions` 按 loadout 取技能；`/catalog` 增 `allSkills` 与 `energy` / `magic` 规则。
- 阵亡**不自动换人**：`legal_actions` 在场上精灵阵亡时只返回换人动作；新增 `POST /simulate/forced-switch`（不推进回合）供玩家确认上场精灵。
- 元素键恒用英文 `short_name`（稳定），中文名走 `elements[].nameZh` / `sprites[].nameZh`（显示）。

## 5. 关键决策

1. **每次结算后重跑 MCTS**（非每点选一次）：胜率依赖双方当回合动作，回合结算后才是有效的新局面。
2. **两侧各跑一次 MCTS**（我方 + 敌方视角）以标注双方按钮推荐度；单次约百毫秒级，实时可接受。
3. **双折线口径**：`myWin` 取我方视角最优胜率，`enemyWin` 取敌方视角最优胜率（两侧独立推演，不做 1 − x 简化）。
4. **聚能是一等动作**：与技能并列在按钮区，参数在 `rules.energy`（固定回 5、上限 10），改规则不改代码。

## 6. 交互细节

- **技能自由替换**：场上精灵携带 `loadout`（4 个），可每回合更换；每个技能格右上角小「换」按钮开下拉切换，来源分组「本精灵技能 / 全部技能」（覆盖 `catalog.allSkills`），切换后实时重算推荐度。
- **技能田字格**：4 个技能以 2×2 网格呈现，**点击技能格即使用**（无独立「使用」按钮）；每格显示名称、类别、能耗、威力与推荐度。
- **其他动作**：聚能 / 换人 / 愿力冲击 / 首领化 以独立按钮列在技能格下方，点击即用并显示推荐度。
- **结算顺序**：技能按「先制度 → 速度」降序依次结算，**非同回合同时结算**；先手把对方打死时，后手不再出招（`_order_key` + `caster.alive()` 判定）。
- **魔力爱心**：每侧魔力以爱心呈现（上限 4，开局 4；每次精灵阵亡 -1，减到 0 判负），置于「我方 / 敌方场上」标题上方。
- **红蓝配色**：左（我方）红、右（敌方）蓝，用于胜率折线、推荐度数字与面板左边框。
- **阵亡换人**：精灵阵亡后**不自动换人**，在对应侧面板内（非全局弹窗）显示「选择上场精灵」，点选后调用 `/simulate/forced-switch` 完成，不消耗回合。
- **血条掉血动画**：结算后血条平滑过渡（`transition-all`），血条值旁浮出 `±N` 掉血 / 回血提示（`hp-delta` 关键帧）。
- **回合日志**：结算事件逐条列出（伤害 / 印记 / 阵亡 / 换人 / 聚能 / 愿力）。

## 7. 非目标

- 不做敌方自动行动 / AI 对战演示（双方均手选）。
- 不做录像回放与逐事件时间轴。
- 不做移动端原生形态（响应式 Web 即可）。

## 9. 布局重构（v0.2 · 已确认）

三列 **1 : 2 : 1**：

```text
┌──────────────┬────────────────────────────────┬──────────────┐
│ 我方 (1)      │  中列 (2)                       │ 敌方 (1)      │
│  场上「大头」  │  ┌ 对战状态 / 胜率走势 ─────────┐ │  场上「大头」 │
│  状态/印记栏   │  │ 双方面板 · 推荐 · 天气 · 摘要  │ │  状态/印记栏  │
│  技能 2×2      │  ├ 回合时间线（回退）──────────┤ │  技能 2×2     │
│  其他动作      │  ├ 对战记录（占余高 · 可滚动）──┤ │  其他动作     │
│  5 场下头像    │  └────────────────────────────┘ │  5 场下头像   │
└──────────────┴────────────────────────────────┴──────────────┘
```

- 顶部工具条**通栏**（模式 / 回合 / 天气 / 预设 / 重选队伍 / 详细录入）。
- **中列**上部＝对战状态 + 胜率走势；中部＝回合时间线；下部＝对战记录（填满剩余高度、内部滚动）。
- **左右列**（各 1）：场上「大头」（`sprite.head` 大图 + 名字 / 系别 / HP / 能量）→ 状态 / buff / 印记栏（含层数）→ 技能 **2×2** → 其他动作（聚能 / 愿力 / 首领化）→ **一排 5 个场下头像**（HP 条 + 能量 + 六维面板小标）。6v6 = 1 上场 + 5 场下。
- **响应式**：`≥860px` 三列；`<860px` 折单列，顺序＝我方 → 敌方 → 中列（面板 / 时间线 / 日志）；`<520px` 进一步紧凑。

### 9.1 交互

- **技能 2×2**：沿用「点技能即选用」+ 右上「换」改招式；双方都选完自动结算。
- **场下头像点击 = 换人**；场上精灵阵亡时点击场下头像 = 阵亡换人（`/simulate/forced-switch`，不耗回合）。
- **悬停详情卡（分平台）**：
  - 桌面 `(hover: hover) and (pointer: fine)`：`HoverCard` 移入浮出、移开收起。
  - 触屏 / 窄屏：无 hover，改**点击精灵 → 弹窗**展示同一张详情卡。
  - 内容：大头、`#号 名 / 系别 / 特性`、等级 / 星级 / 性格 /（血脉，可得时）、HP / 能量、六维面板、状态 / 印记 / buff、出战 4 技能；**场上大头与场下头像都可触发**。
  - 水合一致：hover 能力用 `matchMedia` 在 effect 内探测，初始渲染按触屏口径，避免 SSR 不一致。

## 10. 回退机制（回合时间线 · 已确认）

**语义**：点「第 3 回合」＝回到「**第 2 回合已结算、刚进入第 3 回合**」的局面（即该回合**开始前**的 `BattleState`）；其后所有记录丢弃，可重新选动作重打。因 `seed` 固定，重打同一动作结果确定，**换动作才产生新分支**。

**数据**（`board.tsx`）：用 checkpoint 栈替代单份 `state`。

```ts
interface Frame {
  turn: number;
  state: BattleState;        // 该回合「开始前」的快照
  log: BattleEvent[];        // 抵达本帧时展示的日志（上一回合产生）
  history: TrendPoint[];     // 抵达本帧时的胜率走势
  terminal: Terminal | null;
  label: string;             // 「回合 3」「阵亡换人」「首领化」…
}
// frames: Frame[]；cursor: number 指向当前帧；state/log/history/terminal 全由 frames[cursor] 派生。
```

- `simulate/turn`：结算前把当前帧入栈 → 结算后追加新帧（`turn = state.turn`）。
- `forced-switch` / `leader`：不推进回合但改局面 → 追加同回合新帧（`label` 注明）。
- **回退**：`frames = frames.slice(0, i + 1); cursor = i;` 清空 `pendingP / pendingE`，对 `frames[i].state` 重跑 MCTS。
- 「撤销上一回合」＝回退到 `cursor - 1`。

**UI**：中列「回合时间线」横向列出各帧（当前帧高亮），点击即回退；另给「撤销上一回合」按钮。

**非目标**：不做分支树（单线回退）；不做跨会话持久化（存档仍走 `/record`）。
