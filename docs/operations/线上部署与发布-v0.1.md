## 1. 定位与边界

- **定位**：把本工具部署到自有机（`cspy-site`，腾讯云），公网入口 `https://roco.shigu.zone`，供多人访问同一套引擎与图鉴。
- **边界**：
  - 仍**无数据库、无账号体系**；线上与本地唯一差别是「谁在访问」，不是「存了什么」。
  - 图鉴注册（`data/registry`，数百 MB）**不入镜像**，走宿主目录挂载；引擎参数 `data/*.json` 也以宿主为准（镜像内那份只作缺省）。
  - 镜像分发**不引入镜像仓库**：本地 `docker save` → `scp` → 远端 `docker load`，与本工作区既有的 ShiGuZone 发布方式一致。
  - 服务器是多项目共用机（同机还有 ShiGuZone / 锦创 / 微森等）：本项目的端口、目录、容器名、镜像 tag 都必须带 `shigu-rock` 前缀，不碰别人的资源。

## 2. 拓扑

```text
浏览器 ──https──> nginx(宿主 :443) ──roco.shigu.zone──> 127.0.0.1:18488 ──> 容器 shigu-rock:3000
                     │ certbot(nginx 认证器) 签发 / 自动续期
                     └ /etc/nginx/conf.d/roco-shigu-zone.conf
宿主目录 /opt/shigu-infra/shigu-roco/
  ├ compose.yaml        （= 仓内 compose.yaml，由 release.ps1 同步）
  ├ .env                （ROCO_HOST_PORT=18488；本地没有这个文件，默认 26900）
  └ data/               （= 仓内 data/，增量同步；容器挂 /app/data）
```

- **端口**：宿主 `127.0.0.1:18488`（仅环回，公网只经 nginx）。选它是因为 18487 = ShiGuZone、18080 = OnlyOffice、26910 = DSH，同机其它站点占用 18470/18476/18483/18485/18486 等。
- **compose 一份两用**：宿主端口参数化为 `127.0.0.1:${ROCO_HOST_PORT:-26900}:3000`——本地不写 `.env` 就是 26900（与 dev 一致），服务器 `.env` 写 18488，避免本地 / 线上两份 compose 漂移。
- **数据挂载**：`./data:/app/data` + `ROCO_DATA_DIR=/app/data`。容器内进程是 `node`（uid 1000），与宿主 `ubuntu`（uid 1000）同号，宿主上传的文件天然可写；**不能**把 data 目录 root 化，否则工作台写回 `mechanisms.json`、观战房间落盘都会失败。
- **证书**：`certbot` + **nginx 认证器（HTTP-01）**。服务器上 `shigu.zone` / `cspy.site` / `weisen-mat.cspy.site` 都是这条路径，由 `certbot.timer` 自动续期；通配证书（`*.cspy.site` / `*.tmxk.site`）走的是 `manual` + DNS-01，hook 脚本放在 `/tmp/opencode/`（重启即丢，续期链路不可依赖）——**新站点不要复制这条路**。

## 3. 设计原则

1. **一条命令发版**：`pwsh scripts/release.ps1 -Version x.y.z` 覆盖「质量门禁 → 同步数据 → 构建 → 分发 → 起容器 → 冒烟」。
2. **数据与镜像解耦**：数据变化（图鉴注册、`mechanisms.json` 工作台写回）只同步 `data/`，不重建镜像。
3. **增量同步、断点可重**：图鉴注册目录按 `registrationId` 命名且内容不可变，只需补新增；逐个文件 `scp`，失败重跑即续传。
4. **不静默失败**：远端脚本一律 `set -e`，本地每步 `Check-Step` 校验退出码；远端脚本用「单引号 here-string + 占位符替换」拼装，避开 PowerShell 与 bash 的 `$` 转义互相干扰（用双引号 here-string 会让 bash 的 `$(...)`、`${...}` 被本地吞掉）。
5. **回滚留一手**：清理旧镜像时保留「本次 + 上一次」，`.env` 与 `data/` 从不被发布过程改写（只有 compose.yaml 会被覆盖，覆盖前 `docker compose` 目录内不做备份是刻意的——它由仓内版本控制）。

## 4. 关键决策

| 决策 | 取舍 |
| --- | --- |
| 用 `docker save` + `scp` 分发，不上镜像仓库 | 单机单服务，量级 ~800MB，够用且无额外基础设施；代价是每次发版要传整包（镜像层缓存不参与） |
| 宿主端口 `18488` 而非复用 26900 | 26900 是本地 dev 口径；服务器上与其他项目共用，端口必须显式且不撞车 |
| nginx 站点配置入仓（`deploy/nginx/`） | 配置随代码走，重装/换机可控。**但签发证书后该文件归 certbot 管**（443 段由 certbot 注入），因此 `release.ps1` 只在「服务器上还没有该文件（首次）」或显式 `-SyncNginx` 时同步，避免每次发版把 HTTPS 段刷掉 |
| data/ 全量入服务器而非只传激活图鉴 | 语义完全不变、服务器保留完整注册历史；代价是首次 ~658MB。要省空间时可只传激活注册目录 + 精简 `index.json`（收益 520MB，见 §7） |

## 5. 发布流程

```powershell
# 全量：质量门禁 + 数据同步 + 构建 + 分发 + 起容器 + 冒烟
pwsh scripts/release.ps1 -Version 0.128.2

# 只改了代码：-SkipData 省掉数据比对与上传
pwsh scripts/release.ps1 -Version 0.128.2 -SkipData

# 部署步骤失败后重跑：镜像已在服务器 /tmp，免构建免上传
pwsh scripts/release.ps1 -Version 0.128.2 -SkipChecks -SkipData -SkipUpload
```

脚本步骤（远端脚本一律 LF，Windows 的 CRLF 会让 bash 吃到 `\r`）：

| 步 | 动作 |
| --- | --- |
| 前置 | `pnpm check`（lint / typecheck / 引擎 353 项测试）；`-SkipChecks` 跳过 |
| 0 | 远端磁盘余量（默认下限 10G）、`mkdir -p /opt/shigu-infra/shigu-roco/data` + `chown ubuntu` |
| 1 | 同步 `data/`：`find` 远端已有文件 `相对路径\|字节数` → 逐个比对 → 只传新增/变化；`-SkipData` 跳过 |
| 2 | 改写仓内 `compose.yaml` 的 `image: shigu-rock:<版本>`（本地文件，随提交入库） |
| 3 | `docker build`（`APP_VERSION` / `APP_BUILT_AT` 随镜像注入，页脚与 `GET /api/version` 展示） |
| 4 | `docker save` + gzip → `scp` 镜像 / compose / nginx 站点配置 |
| 5 | 远端 `docker load` → `docker compose up -d` → `nginx -t && systemctl reload nginx` → 清理旧镜像（保留本次与上一次）+ 清 `/tmp` 旧镜像包 |
| 6 | 冒烟：容器内 `127.0.0.1:18488/api/engine/health` 轮询等待（最多 180s，首次要读 ~130MB 图鉴）并**必须 200**；公网入口未就绪只提示不失败 |
| 7 | 清理本地临时镜像包（部署失败时不执行，包保留供排查） |

**发布前必做**：数据改动后重跑 `pnpm static:export` 并提交 `apps/web/public/data/bundle.json`——浏览器 Worker 优先读这个入仓静态包，不同步就会用旧机制（本次上线前就发现它落后了 4 个引擎版本 / 74 条机制）。

## 6. 首次部署（2026-10-16 完成）

1. 本地建镜像 `shigu-rock:0.128.1`，`docker save` + `scp` 到服务器（238MB）。
2. 服务器建 `/opt/shigu-infra/shigu-roco/`，增量同步 `data/`（657MB），`.env` 写 `ROCO_HOST_PORT=18488`，`docker compose up -d`。
3. nginx 站点配置同步到 `/etc/nginx/conf.d/roco-shigu-zone.conf`（80 段 + acme 挑战目录）。
4. DNSPod 加 **A 记录**：`roco` → `1.15.111.245`（与 `shigu.zone` 同机同 IP）。
5. 解析生效后签证书（HTTP-01，nginx 认证器）：

   ```bash
   sudo certbot --nginx -d roco.shigu.zone --redirect --keep-until-expiring
   ```

   certbot 把 443 段注入 `/etc/nginx/conf.d/roco-shigu-zone.conf` 并纳入 `certbot.timer` 自动续期（到期日 2027-01-14）。**此后该文件归 certbot 管**，`release.ps1` 默认不再覆盖它。
6. 验证：`https://roco.shigu.zone/` 200、`/api/engine/health` 200（counts 与本地一致）、HTTP 301 跳 HTTPS、`/data/bundle.json` 取到最新静态包（`engineVersion 0.80.0` / `mechanisms 1314`）；cdp 真浏览器冒烟首页与 `/record` 通过。

## 7. 回滚

1. 服务器 `/opt/shigu-infra/shigu-roco/` 里把 `compose.yaml` 的 `image:` 改回上一版 tag（脚本清理旧镜像时**保留本次与上一次**）。
2. `sudo docker compose up -d`，等 healthcheck 通过。
3. 若问题出在数据（`data/`）：数据是**增量同步、只增不改**，回滚镜像不会回滚数据；`mechanisms.json` 被工作台写坏时，用 git 里的版本重传该文件即可（`scp data/mechanisms.json ...`）。
4. 站点彻底故障时可先摘掉 nginx 站点止血：`sudo rm /etc/nginx/conf.d/roco-shigu-zone.conf && sudo systemctl reload nginx`（不影响同机其它站点）。

## 8. 非目标

- 不做多实例 / 横向扩容（观战房间是单进程内存 + 本地文件）。
- 不引入 CI / 镜像仓库 / 蓝绿发布：单人项目，一条命令 + 保留上一版镜像已覆盖回滚需求。
- 不在服务器上同步图鉴（`node scripts/sync-roco-world.mjs` 需要 dev 实例与外部站点访问）：数据源仍只在本地注册，注册完再同步上去。
