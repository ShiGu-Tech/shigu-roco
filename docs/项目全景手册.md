# 洛克王国世界 PVP 决策辅助工具 · 项目全景手册

> 文档状态：设计 v0.1 · 代码 进行中 · 验证 进行中 · 生产 进行中

## 1. 定位与边界

### 是什么

一个**离线的、单人的** PVP 对局决策辅助工具：

1. 玩家在网页上**手工录入**当前对局状态（双方场上精灵、血量、能量、印记、天气、魔力、养成等）。
2. 内置 TS 引擎按复刻的官方回合规则做**战斗模拟（MDP 环境）**。
3. 引擎用 **MCTS（蒙特卡洛树搜索）** 从当前状态向前推演，输出我方每个合法动作的**预估获胜概率并排序**；对手行为用贝叶斯模型，对手养成为隐藏信息、按后验采样。
4. 网页展示：动作胜率榜、对手动作概率推测、简要推荐理由；支持对局存档 / 复盘、对手库积累。

### 明确的非目标（Non-goals）

- **不读取游戏画面**：不做截屏识别、不做内存读取、不做抓包。
- **不自动操作游戏**：不模拟点击、不发包、不改客户端。
- **不需要联网**：除首次安装依赖外，运行时全程本地。
- **不做神经网络估值**：MVP 用纯 MCTS + 启发式估值；神经网络列为阶段 5 的可选加速项，非核心。
- **不做双人博弈 MCTS**：对手侧用贝叶斯动作频率采样，不展开对手搜索（算力不允许）。
- **不承诺规则 100% 精确**：Wiki 描述存在歧义，隐性机制需游戏实测校准；工具标注置信度与待校准项。

## 2. 核心约束与设计原则

1. **数据与代码解耦（第一原则）**：精灵种族、技能、印记、天气、属性克制、养成换算全部落在 `data/*.json`。外部游戏数据唯一参考源为 [roco.world 中文站](https://roco.world/zh/)，中文名称、说明、机制词条和图片保留源字段；版本平衡性更新只改 JSON，模拟器与 MCTS **业务代码零改动**。为此引入「效果 DSL」（见数据层设计稿），把技能效果描述为可配置的数据，而非硬编码 if-else。
2. **模拟器是固定规则脚本，MCTS 是搜索模型**：模拟器负责「按规则结算」，MCTS 负责「向前采样找最优动作」，二者职责分离、可独立测试。
3. **可校准优先于一次性写死**：伤害系数、印记结算公式、养成换算等不确定参数放进 `data/*.json`，使「游戏实测校准」= 改配置，而非改代码。
4. **可复现**：MCTS 使用可控随机种子（mulberry32）；同一状态 + 同一种子 + 同一配置 → 同一推荐结果。
5. **前端只做输入与呈现**：所有战斗规则、概率计算都在引擎侧；前端不复制任何游戏逻辑（引擎与前端同仓，但引擎为独立纯逻辑层）。
6. **同构优先**：引擎不依赖 `fs` / DOM，Node（API Route）与浏览器（Web Worker）复用同一份代码。

## 3. 技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 引擎 | **TypeScript（纯逻辑）** | 模拟器 + MCTS + 贝叶斯对手 + 养成后验 + 数据加载 |
| 引擎运行 | **Next.js Route Handler**（内置）+ **Web Worker** | 默认服务端执行；重推演在浏览器 Worker 内跑，免独立进程 |
| 前端 | **Next.js 16 + React 19 + TypeScript** | 对齐 `D:\ShiGuZone\main` 技术栈 |
| 样式 | **Tailwind CSS v4 + shadcn/ui（new-york）** | CSS-first 配置，`components.json` |
| 图表 | **ECharts 6** | 对手动作概率分布、动作胜率条形图 |
| 校验 | **TypeBox + AJV**（前端）；引擎内 TS 类型 | 契约校验 |
| 数据 | **仓库内 JSON + 浏览器 localStorage** | 无数据库；对局存档 / 对手库存 localStorage |
| 包管理 | **pnpm 11 workspace** | 单 app（`apps/web`），引擎为其内部模块 |
| 自检 | **vitest**（引擎回归）+ ESLint / tsc（前端） | 对齐参考项目「纯函数回归」思路 |

> 前端不引入 Postgres / Drizzle / 登录体系：本工具离线单人，参考项目的数据库与鉴权属于非目标的重量级部分，被有意剥离。

## 5. 领域模型（概念层）

| 实体 | 说明 | 静态 / 运行时 |
| --- | --- | --- |
| Sprite（精灵） | 编号、名称、阶位、系别、**基础资质（race）**、特性、携带技能 | 全量图鉴（现查注册） |
| Skill（技能） | 名称、系别、分类、动作类型、威力、能耗、命中、效果 DSL | 全量图鉴（现查注册） |
| Mark（印记） | 名称、叠加上限、结算时机与公式、下场清除、引爆 | 全量图鉴（现查注册） |
| Weather（天气/环境） | 伤害修正、持续回合、附加效果 | 全量图鉴（现查注册） |
| ElementTable（属性克制表） | 单 / 双系克制与抵抗倍率 | 全量图鉴（现查注册） |
| Rules（全局规则参数） | 初始魔力、愿力、首领化、结算阶段顺序、伤害系数 | 静态（`data/rules.json`） |
| Stats（养成） | 面板换算系数（种族/个体）、性格表、个体档位先验 | 静态（`stats.json`） |
| StatProfile（养成档案） | 等级（PVP 固定 60）、性格、个体值（天分 × 星级，0~60） | 运行时（挂在 ActiveSprite） |
| ActiveSprite（场上精灵实例） | 精灵 id、当前/最大血量、能量、buff/debuff、印记、**养成档案** | 运行时 |
| BattleState（对局状态） | 双方魔力、天气、愿力、首领化、双方场上、我方背包、敌方已见 | 运行时 |
| Action（动作） | 攻击 / 防御 / 状态 / 换人 / 愿力 / 首领化 | 运行时由状态派生 |
| OpponentModel（对手模型） | 对手 A/D/S 动作的概率分布（贝叶斯更新） | 运行时 + 会话内持久 |
| OpponentLibrary（对手库） | 某对手精灵的出招分布 + 养成档位计数 | localStorage 持久 |

## 7. MVP 迭代路线

| 阶段 | 内容 | 交付判据 |
| --- | --- | --- |
| 0 | 设计稿（本套文档） | 用户确认 |
| 1 | 项目骨架 + JSON schema 模板 + 采集器 | `data/` 可被引擎加载并通过校验 |
| 2 | 少量高频精灵数据 + 最小模拟器 | 测试覆盖伤害与结算顺序，单回合结果可人工复核 |
| 3 | 接入 MCTS + 贝叶斯对手模型 | 同状态同种子可复现；1.5s 内完成千次模拟 |
| 3.5 | 引擎 TS 化 + 养成资质 / 对手库 | 引擎并入前端、无独立进程；养成换算 / 后验接入 MCTS |
| 4 | 网页 UI：对战台 / 详细录入 / 存档 | 手动录入一局并得到排序推荐 |
| 5（可选） | 采集脚本 + 自动解析、扩充精灵库、NN 估值 | —— |

## 8. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| Wiki 结构变动 / 描述歧义 | 模拟器与真机不一致 | 参数化 + `【待校准】` 标注 + `simulate/turn` 供实测对拍校准 |
| 对手养成是隐藏信息 | 胜率偏差 | 离散档位贝叶斯后验 + rollout 内采样；UI 标注「推测」 |
| POMDP 隐藏信息（敌方背包 / 能量） | 概率偏差 | 明确建模为分布采样；对手库动态校正 |
| 版本迭代导致数据过期 | 推荐错误 | 数据版本号 + `/health` 暴露版本；更新只改 JSON；UI 提示更新时间 |
| 采集器随 Python 下线 | 数据更新不便 | 当前人工维护；按需以 TS 重建采集脚本 |

## 9. 关键决策记录（摘要）

- **D1 引擎并入前端、纯 TS**：单语言单进程，类型共用，免 26901 与 CORS；重推算放 Web Worker。
- **D2 无数据库**：离线单人 + 存档 / 对手库本地化，剥离 Postgres/Drizzle/鉴权。
- **D3 效果 DSL**：技能 / 印记 / 天气效果数据化，满足「改配置不改代码」硬约束。
- **D4 单侧 MCTS + 对手贝叶斯**：控制算力，避免双人博弈搜索。
- **D5 养成资质数据驱动 + 对手养成后验**：基础资质静态、养成运行时；对手养成按观测后验积分。
- **D6 战斗机制扩展层**：固定回合内核，技能 / 特性通过触发器、条件和效果命令改变状态或行动队列；未支持效果必须显式记录。

详细设计见 `architecture/` 与 `modules/` 下的各设计稿。
