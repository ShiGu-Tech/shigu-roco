# 对战舞台 UI 方向-v0.1

> 文档状态：设计 ✅ / 代码 🟡 原型 / 验证 ✅ / 生产 ⬜
>
> 范围：微信小程序「对战舞台」的场景与界面（不含技能特效）。本稿记录已确认的视觉方向，供后续移植使用。

## 1. 定位

- 小程序核心页：玩家在 PVP 对战中查看当前局面与推荐行动。
- 界面服务于「一眼读懂局面」，不是复刻游戏画面。
- **明确不做技能特效**：刀光、爆炸、粒子等由后续负责；本层只做场景氛围、镜头、血条与伤害数字。

## 2. 已确认方向

**原神式场景 + 崩铁式 HUD 的混合：**

- 场景：清晨偏金、空气感、草甸/溪流/远山、低对比、留白多。
- HUD：暗金切角面板、鎏金描边、衬线名称、精细血条。
- 交互：克制的镜头轻推与伤害数字，不做打击特效。

### 2.1 参考与边界

| 项 | 取舍 |
| --- | --- |
| 原神 | 场景光照、空气透视、衬线字体、轻量留白 |
| 崩铁 | 暗金 HUD、切角、行动顺序、金色描边 |
| 宝可梦 | 只保留近大远小的对峙构图与先手/应对顺序 |
| 明确排除 | 技能特效、3D 引擎（Three/Pixi）、写实渲染 |

## 3. 布局

- 全宽，不模拟手机宽度（不使用 `max-width: 480px` 之类容器）。
- 舞台逻辑坐标 **750 × 720**，位图 2×（1500 × 1440），CSS `width:100%` 等比缩放，等同小程序的 `rpx`。
- Canvas 内绘制场景 + HUD；页面其余部分（tabs / 推荐卡 / 日志 / 底部按钮）用 DOM，禁止固定最小宽度导致横向溢出。
- 横屏/宽屏不特殊适配，页面纵向滚动。

## 4. 场景规格

| 层 | 内容 |
| --- | --- |
| 天空 | 冷蓝 → 米白 → 暖金渐变；日轮柔光（screen） |
| 云 | 多层椭圆 + 高斯感阴影，低透明度 |
| 远山 | 3 层冷色山脊（空气透视），越远越淡越偏蓝 |
| 草甸 | 绿色渐变 + 暖光斑 + 田埂曲线 + 地平线雾 |
| 水系 | 右侧溪流（冷暖对比），带水面高光线 |
| 植被 | 边缘树丛、中景灌木、草叶与野花（固定种子，避免闪烁） |
| 前景 | 虚化草叶（景深）+ 暗角 |
| 氛围 | 飘落花瓣/浮尘、暖色调色、纸感颗粒 |

## 5. HUD 规格

### 5.1 面板

- 位置：敌方左上、己方右下（宝可梦式对峙，崩铁式面板）。
- 形状：切角矩形（右上/左下切角），双层描边（外层鎏金、内层细线）。
- 底色：深棕半透明渐变（`rgba(44,32,16,.90)` → `rgba(36,25,12,.92)`）。
- 描边：己方金 `#E9C877`，敌方银紫 `#9EA0E0`。

### 5.2 内容层级

1. 名称：衬线体 28px，`#FFF6E0`
2. 等级：`Lv.60`，金色
3. 阵营 / 先手：细金边胶囊
4. HP：`HP` 标签 + 轨道 + 数值
5. 底部：能量 `7 / 10` + 状态胶囊（如「物防 +2」）

### 5.3 血条

- 轨道：深色渐变 + 细描边 + 内阴影感
- 实值：三段渐变（绿 / 金 / 红），顶部高光
- 残影：掉血后白色残影延迟 0.18s 追上
- 刻度：25% 分隔线（低透明度）
- 低血：≤22% 呼吸闪烁（不做特效）

## 6. 交互

- **先手判定**：`priority`（应对成功 +100）→ 速度；与引擎 `orderKey = [priority, speed]` 一致。
- **依次出手**：先手打完，后手仍存活才行动；不是同时结算。
- **应对**：防御技匹配对方行动类型时判定成功，先手抬升，伤害按减伤比例结算；界面用六边形护罩标识。
- **镜头**：wide → 出手方近景 → 回 wide；缓动跟随。
- **反馈**：伤害数字（衬线、白描边）、血条掉血、行动顺序高亮。
- **禁止**：刀光、爆炸、粒子喷射、震屏（这些归技能特效层）。

## 7. 非目标

- 不做 3D、不做 Pixi/Three、不引入游戏引擎。
- 不做官方动画复刻。
- 不在本层实现技能特效。
- 不做横屏布局。

## 8. 已知限制

- 图鉴只有 128×128 头像，没有立绘/动作帧；当前呈现为「圆形灵体 + 法阵」。
- 放大到大屏会发虚；要真正接近原神/崩铁的质感，需要重新同步图鉴拿 ≥512px 立绘，或补美术资源。
- 在补素材前，保留「灵体/契灵」设定，避免假装全身角色。
