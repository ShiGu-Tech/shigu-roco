# 界面重设计 · 设计 v0.1

> 文档状态：设计 ✅ v0.1（方向与决策已定） · 代码 🟡 第一版 · 验证 ✅ · 生产 ✅（详见 §12 实施状态）
>
> 目标：把现有「轻微童话风」界面重做成**工具风 / 高信息密度（克制、专业）**。功能不变，只改信息架构与呈现。页面范围与配色细节待用户确认（§10）。

## 1. 定位与边界

**现状问题**（现有实现）：
- 视觉偏装饰：极光背景（`.app-shell::before`）、衬线标题（`.story-title`）、丝带、糖果色、`0.9rem` 大圆角、柔和阴影——信息密度低、层级靠「装饰」而非「结构」。
- 信息以卡片堆叠呈现，对局数据（面板 / 印记 / 冷却 / 胜率）没有统一的「数据表 / 状态条」表达，扫读成本高。
- 全站导航弱（仅首页几个文字链接），四页之间无统一外壳。

**目标**：以「对战分析工具」的形态重做——**结构优先、密度优先、克制**。让用户一屏内看到尽可能多且可比较的信息（双方面板、印记层数、冷却、动作收益），层级用边框 / 底色 / 字重表达，而非阴影和装饰。

**不在本稿**：引擎 / 数据 / 交互功能变更（功能保持现状）；品牌吉祥物 / 插画；移动端原生壳（`apps/mobile`）。

## 2. 设计原则

1. **结构 > 装饰**：用 1px 边框、分区分隔线、字号与字重建立层级；去掉极光、丝带、渐变底、大圆角、重阴影。
2. **密度优先**：默认紧凑（compact）；行高、内边距、字号以「一屏可比较」为准；数值一律 `tabular-nums` 等宽对齐。
3. **可比较**：同类信息（双方 HP / 攻击 / 防御 / 印记 / 冷却 / 胜率）**对齐同一栅格**，便于纵向扫读。
4. **数据驱动色**：语义色（成功 / 警告 / 危险 / 信息）低饱和；元素 / 类别 / 印记色来自数据，不硬编码。
5. **一致外壳**：全站统一应用壳（顶栏 + 内容区 + 状态栏），四页共用导航与页头规范。
6. **图标化**：元素 / 技能类别沿用现有 `ElementIcon` / `SkillCategoryIcon`；印记与状态新增 `StatusIcon`（§7）。
7. **响应式**：`min-[520px]:` / `min-[860px]:` 三档；≤520 单列、可横向滚动表格；按钮 / 数字不溢出。
8. **无障碍**：焦点可见、对比度达标、键盘可达；禁用浏览器原生 `alert/confirm/prompt`（沿用 `sonner` 反馈）。

## 3. 设计系统（Design Tokens）

> 全部落 `globals.css` 的 `:root` / `.dark`；JSX 只用语义 token，禁止硬编码色值 / 圆角 / 阴影。

### 3.1 色彩（中性为主 + 单一强调）

| 角色 | 用途 | 方向 |
| --- | --- | --- |
| `background` / `card` / `popover` | 底 / 面 / 浮层 | **浅蓝**底（`oklch ~0.97 / 240`）+ 白面，层级靠 `card` 与 `background` 微弱差 |
| `foreground` / `muted-foreground` | 主 / 次文本 | 深蓝灰正文 + 蓝灰次要 |
| `border` / `input` | 边框 / 输入 | 冷蓝 1px 描边 |
| `primary` | 强调 / 选中 / 主操作 | **蓝**（`oklch ~0.55 / 0.16 / 255`，如 `#2563eb` 一带），白字 |
| `success` / `warning` / `destructive` / `info` | 语义 | 低饱和、可读优先 |
| `star` | 星级 | 保留金色（数据语义） |
| 元素 / 类别 / 印记色 | 数据驱动 | 来自图鉴（`ElementIcon` / `StatusIcon`） |

- 去掉 `--ribbon` / `--aurora-*` / `--glow` / 阴影 tint 等装饰变量。
- **删除 `.dark` 与暗色相关变量**：仅浅色（决策 §10.4）。

### 3.2 字体

- UI：系统无衬线（现有 `--font-sans`）。
- **删除** `--font-display` 衬线标题（`.story-title` / `.eyebrow` 一并移除）。
- 数值：`font-variant-numeric: tabular-nums`（HP / 面板 / 概率 / 层数 / 冷却）。
- ID / 代码：`ui-monospace`。
- 字号阶：`11 / 12 / 13 / 14 / 16 / 20`（默认 13，正文 13–14，标题 16–20）。

### 3.3 间距 / 圆角 / 阴影 / 密度

- 间距：4px 网格（`0.25rem` 步进）；面板内边距 8–12px。
- 圆角：`--radius: 0.375rem`（6px）——按钮 / 输入 / 卡片统一小圆角。
- 阴影：**基本不用**；仅浮层（Dialog / Popover / DropdownMenu）用极轻阴影，其余用边框。
- 密度：**固定舒适**（决策 §10.3）；表格行 36–40px、面板内边距 12–16px、工具栏高 40px。结构仍按「可比较栅格」组织，不靠拥挤换密度。

- 顶栏常驻、导航高亮当前页；引擎状态（`/api/engine/health` 的 `dataVersion` / warnings）移到顶栏右侧小徽章。
- 页头统一：标题 + 一句话说明 + 右侧操作区。
- 内容区统一最大宽度与栅格；**对战台**桌面分三栏（左=双方状态、中=动作与日志、右=推演与趋势），平板折两栏，手机单列 + 关键表横向滚动。

## 5. 信息密度策略

1. **表格优先**：可比较的数据一律表格化（数据浏览、仓库、技能构成），支持紧凑行、列对齐、粘性表头。
2. **面板化**：每块信息用统一 `Panel`（细边框 + 12px 标题行 + 内容），取代现有大卡片 + 阴影。
3. **状态条**：HP / 能量 / 连击 / 冷却用**内联条 + 数字**（如 `HP 387/400`+进度条），而不是大数字卡。
4. **徽章 / Chip**：元素、类别、印记、状态、特性用图标 + 文字小徽章，出现在表格与面板行内。
5. **日志流**：回合事件用等宽紧凑行（`turn | side | 事件 | 数值`），可折叠 / 过滤。
6. **层级**：标题字号 / 字重 + 分隔线；不使用背景装饰表达层级。

## 7. 图标体系

- **已有**：`ElementIcon`（属性）、`SkillCategoryIcon`（技能类别），图标来源为图鉴同步的在线资源。
- **印记 / 状态（缺口）**：图鉴 14 印记 + 9 状态（buff，含中毒 / 灼烧 / 冻结 / 寄生等）**无 icon 字段**；站点机制词条仅提供 `icon_key`（共 54 个，如 `burn` / `poison` / `mark` / `counter-attack` / `starfall-mark`），`picture` 为 `null`，**无可直接下载的图片 URL**。
- **方案**：新增 `StatusIcon`，按 `icon_key` 映射到**自绘 SVG 图标集**（离线、可控、风格统一）。
  - 数据侧：同步脚本 `scripts/sync-roco-world.mjs` 补采 `glossary[].icon_key`（现只存 id/name/descPlain），注册 / 静态包携带，供 UI 映射；未映射的 key 回退为文字缩写徽章。
  - 与站点「唯一数据源」不冲突：样式自绘，语义与 key 来自站点。

## 8. 页面结构草案（范围待确认）

> 详细程度待用户给范围后再逐页展开；此处只给结构方向。

- **对战台 `/`**：顶栏状态；左栏双方精灵状态（HP / 能量 / 面板 / 印记 / 状态 / 冷却），中栏动作录入 + 回合日志流，右栏推演结果（动作收益表 + 胜率趋势）。桌面三栏。
- **精灵仓库 `/warehouse`**：左侧筛选 / 列表（紧凑表格），右侧详情（面板 / 技能 / 加点 / 血脉），操作用工具条。
- **基础数据 `/data`**：主从布局——左筛选 / 分类，右表格（精灵 / 技能 / 状态 / 印记 / 天气 / 属性），支持搜索 / 排序。
- **复盘 `/record`**：对局列表 + 详情（逐回合回放 / 胜率曲线）。

## 9. 响应式

| 档 | 断点 | 布局 |
| --- | --- | --- |
| 手机 | < `520px` | 单列；导航折叠；表格容器 `overflow-x-auto`；按钮不溢出 |
| 平板 | `520–860px` | 两栏 / 折叠侧栏 |
| 桌面 | ≥ `860px` | 多栏（对战台三栏），最大宽度约束 |

## 10. 已确认决策（用户）

1. **页面范围**：**全部页面**（对战台 `/`、数据 `/data`、复盘 `/record`、仓库 `/warehouse`）。
2. **配色**：**浅蓝**整站基调——浅蓝底 + 白面 + 蓝色强调（冷色，替代原糖果紫）。
3. **密度**：**舒适（comfortable）**——固定舒适密度，不做紧凑/舒适切换；仍保持结构化的高信息组织。
4. **主题**：**仅浅色**——删除 `.dark` 与暗色变量，不提供暗色。

## 11. 非目标

- 不改引擎、数据契约与交互功能。
- 不追求装饰性插画 / 动效演出。
- 不引入新 UI 框架（继续 Tailwind + shadcn/ui + ECharts）。
